# 高级编排

`go-on` 运行时包含一套高级编排模块，用于管理复杂的工作流执行、恢复和诊断。这些组件负责依赖感知调度、容错恢复、会话上下文管理和弹性故障处理。

---

## 1. DAG 执行引擎

DAG（有向无环图）执行引擎负责调度和执行具有显式依赖关系的任务。任务被组织为一个图，其中边表示数据或控制依赖关系。

### 拓扑执行

引擎在执行前计算 DAG 中所有节点的拓扑顺序。没有依赖关系的节点（根节点）首先被调度，只有当所有前驱节点成功完成后，节点才会被分发执行。

### 依赖管理

每个任务将其依赖关系声明为一组上游任务 ID。引擎验证：

- 所有引用的依赖项都存在于 DAG 中。
- 不存在循环依赖（参见下面的循环检测）。
- 依赖项所需的输出与下游任务的声明输入类型匹配。

### 并行组

处于同一拓扑级别的任务（即所有依赖项都已满足且彼此不依赖的任务）被分组为并行执行批次。引擎并发分发批次中的所有任务，受可配置的并发限制约束。

### 循环检测

在开始执行之前，引擎使用深度优先搜索（DFS）和递归栈进行完整的循环检测。如果检测到循环，整个 DAG 执行将被中止，并给出一个明确标识冲突边的错误。

## 2. 恢复编排器

恢复编排器（`src/fault_tolerance/`）处理节点级故障，并根据检测到的故障类型和严重度确定最佳恢复动作。它是一个面向集群健康状态的引擎：节点注册心跳，故障记录为 `FaultEvent`，`FaultToleranceEngine` 将其转化为可执行的恢复计划。

### 恢复动作

`RecoveryAction` 恰好有五个变体：

| 动作            | 描述 |
|-------------------|-------------|
| **RestartNode**       | 重启故障节点：心跳记录恢复为 `Online`，未命中计数清零。 |
| **FailoverToBackup**  | 将流量切换到新领导下的备份节点。 |
| **ScaleUp**           | 记录扩容动作，用于容量类故障（hang、资源耗尽、限流、延迟尖峰）。 |
| **Rebalance**         | 重新平衡节点，解决损坏类故障。 |
| **NotifyOperator**    | 通知操作员关注；用于无法自动解决的故障（I/O 错误、鉴权失败、部分写入），严重度 ≥ 9 时总是追加。 |

### 故障类型映射

`create_recovery_plan()` 根据节点的活跃 `FaultType` 推导动作集（按故障类别去重）：

| FaultType                                   | RecoveryAction          |
|---------------------------------------------|-------------------------|
| `Crash`、`Oom`、`ProcessCrash`              | `RestartNode`           |
| `Hang`、`ResourceExhaustion`                | `ScaleUp`               |
| `NetworkSplit`、`NetworkTimeout`、`NetworkPartition` | `FailoverToBackup` |
| `RateLimit`、`LatencySpike`                 | `ScaleUp`               |
| `DataCorruption`                            | `Rebalance`             |
| `FileIOError`、`AuthFailure`、`PartialWrite`| `NotifyOperator`        |

高严重度故障（`severity >= 9`）总是追加 `NotifyOperator`；没有具体动作映射的节点默认 `NotifyOperator`。

### 计划生命周期

编排器通过 `execute_recovery_plan()` 分发每个计划，执行每个动作的可观察进程内效果（状态重置、隔离组变更、故障解决、操作员通知），然后运行恢复后一致性检查。只有检查通过，计划才会 complete 或 fail——自动恢复要么真正解决故障，要么如实报告残留状态。

## 3. 会话上下文管理器

会话上下文管理器在多轮交互中维护和优化对话上下文，确保在有限的窗口预算内保留最相关的信息。

### 概念提取

每条用户消息都会被分析以提取关键概念——实体、意图和领域特定术语。提取的概念存储在与会话关联的轻量级内存索引中。

概念如果不被后续消息强化，则会随时间衰减。权重低于可配置阈值的概念会被从会话中修剪。

### 消息重要性评分

会话历史中的每条消息在多个维度上评分：

- **时效性**：较新的消息获得较高的分数。
- **相关性**：包含当前查询中出现过的概念的消息得分更高。
- **角色**：系统消息和明确的用户指令比随意对话得分更高。
- **可操作性**：触发了工具调用或产生了可观察副作用的消息得分更高。

### 连续性标记

连续性标记是注入到上下文窗口中的特殊注释，用于指示叙述的进展。它们通过总结已完成的工作和剩余的工作帮助模型在轮次之间保持连贯性。标记在关键里程碑处自动生成：

- `workflow.execute` / `task.execute` 工作流运行完成后。
- 恢复动作解决故障后。

### 窗口预算

上下文窗口是有限的。会话上下文管理器通过以下方式强制执行预算：

1. 始终保留最近的 `n` 条消息（可配置，默认：5）。
2. 用得分最高的较旧消息填充剩余预算。
3. 当预算超限时，剥离低重要性的消息。
4. 必要时通过总结来压缩长消息。
