## 2. 14 层不足与缺陷（当前有效）

### 2.1 架构层

1. 编排核心存在超大模块，职责边界不够清晰，维护与回归风险高。
2. 某些子系统存在“已实现但弱接线”现象，调用深度不一致。
3. WebSocket/会话状态同步存在解耦不足，实时推送链路可进一步稳固。

### 2.2 运行层

1. 聊天主路径仍存在较长串行段，影响多 agent 场景下的尾延迟。
2. 异步路径中仍有标准互斥锁热点，容易在高并发时抬高抖动。
3. 部分后台任务生命周期管理可进一步收口（启动/取消/回收一致性）。

### 2.3 智能层

1. 多模型融合策略在复杂分歧场景下仍有“偏规则化”倾向。
2. 元认知与自进化反馈链路虽已接入，但可解释与可控阈值需统一。
3. 高风险任务中的“投票+回退+再验证”联动策略可更精细。

### 2.4 治理层

1. 审计数据结构存在多来源并存风险，建议统一主审计源。
2. 某些治理事件的“告警-处置-追踪”闭环仍可加强。
3. 热重载后的治理策略再校验建议强制化。

### 2.5 协议层

1. 流式帧解析在边缘换行/分帧场景仍有鲁棒性改进空间。
2. 长连接崩溃恢复与重连退避策略仍可更积极。
3. 消息 ID 生成策略应统一到不可预测且全局去重方案。

### 2.6 韧性层

1. 故障注入与高并发链路结合时，局部锁争用仍可优化。
2. 排水/停机阶段的资源回收时序需更严格保障。
3. 租户级清理与失效传播需更快收敛。

### 2.7 可观测层

1. 部分指标更新尚未完全做到原子一致视图。
2. 子链路 trace context 传播仍有断点风险。
3. 关键治理与智能决策指标可再补齐“因果解释字段”。

### 2.8 内存层

1. 历史/缓存增长上限需持续强化，避免长跑漂移。
2. 部分检索路径在极端规模下仍有复杂度偏高问题。
3. 缓存未命中与序列化路径的开销需继续压缩。

### 2.9 GUI 层

1. GUI 侧仍有大体量聚合逻辑，影响迭代速度。
2. 非流式路径下的大响应可能影响交互顺滑度。
3. 可视化趋势与诊断信息深度可提升。

### 2.10 SDK 层

1. 多语言 SDK 在“真流式一致性”上仍有差异。
2. async 能力在部分 SDK 中不够完整。
3. 文档与实现需持续消除细小漂移。

### 2.11 VS Code Addon 层

1. 命令注册与视图交互存在模板代码偏多问题。
2. 会话持久化与后端 checkpoint 的一致性可加强。
3. 流式通道极端场景（超大包、重连）需继续硬化。

### 2.12 测试层

1. 部分 benchmark 存在“可读性好但真实性不足”的风险。
2. e2e 覆盖深度与故障注入场景可再扩展。
3. 协议与可观测链路缺少更细粒度回归用例。

### 2.13 部署层

1. 容器化独立运行路径需持续对齐“即开即用”标准。
2. 启动脚本在跨环境用户/权限假设上仍需收敛。
3. 观测组件的生产安全配置要默认更严格。

### 2.14 安全层

1. 密钥脱敏字段覆盖面需扩展到全部供应商键位。
2. 会话与消息标识应强化为更强随机性策略。
3. 多租户读写隔离规则需增加更显式防穿透校验。

## 3. 五体改进计划（50 步）

说明：5 体分别为架构体、运行体、智能体、治理体、体验体。每体按 P0/P1/P2 分层执行，全部完成后冲刺 10/10。

### 3.1 架构体（Architecture Body）

P0（基础重构）

1. 拆分超大主链路函数为“路由/执行/组装/审计”四段。
2. 建立统一执行上下文对象，去除隐式跨模块依赖。
3. 统一 WebSocket 与会话同步总线入口。
4. 对弱接线模块补齐启动期自检与运行期探针。

P1（稳定化）

5. 模块化边界契约化（输入输出结构固定）。
6. 高频调用路径执行图可视化并固化到治理状态。
7. 建立结构漂移检测（变更即报警）。
8. 清理残余兼容层冗余代码。

P2（工程化）

9. 自动生成架构依赖图与反向引用图。
10. 将核心编排链路纳入变更门禁。

### 3.2 运行体（Runtime Body）

P0（性能与并发）

11. 多 agent 执行改为并行调度 + 统一超时预算。
12. 标准互斥锁热点迁移到异步友好锁或无锁结构。
13. 修复缓存清理与淘汰一致性。
14. 统一后台任务生命周期（启动/取消/回收）。

P1（尾延迟与抖动）

15. 建立尾延迟专用治理阈值（P95/P99 分层）。
16. 对高频 JSON 序列化路径做批量与零拷贝优化。
17. 强化重试退避与熔断联动，避免雪崩。
18. 建立压测自动基线对比报告。

P2（长期运行）

19. 引入长跑内存漂移巡检任务。
20. 运行时性能画像自动化归档。

### 3.3 智能体（Intelligence Body）

P0（智能闭环）

21. 统一多模型融合策略：投票、融合、矛盾检测三段式。
22. 元认知反馈强制进入后续任务规划输入。
23. 自进化信号接入真实执行结果而非静态规则。
24. 高风险任务默认启用“多路复核 + 审核门”。

P1（质量提升）

25. 引入任务类型感知的策略模板（编码/诊断/迁移/审查）。
26. 强化反事实检查与失败样本回放。
27. 能力画像在线更新并提供可解释输出。
28. 低一致性结果触发自动降级路径。

P2（高阶能力）

29. 引入复杂任务分层记忆回溯策略。
30. 智能决策过程全链路可解释化。

### 3.4 治理体（Governance Body）

P0（统一治理）

31. 统一审计主源，收口审计写入与查询接口。
32. 认证关闭模式降为最小权限而非超级权限。
33. 治理策略热重载后强制重新验证与回滚保护。
34. 关键治理决策全部落可观测事件。

P1（安全与合规）

35. 多租户隔离规则前置到读写入口。
36. 风险评分与审批策略绑定版本化。
37. 审计数据哈希链与完整性校验定时化。
38. 治理异常触发自动熔断与恢复演练。

P2（制度化）

39. 治理规则变更必须附带回归证明。
40. 建立治理指标周报与门禁阈值演进机制。

### 3.5 体验体（Experience Body：GUI + SDK + Addon + 测试 + 部署）

P0（用户体感与交付能力）

41. GUI 聊天全链路流式化，避免大响应阻塞。
42. VS Code Addon 流式分帧与重连策略硬化。
43. SDK 流式语义统一（Rust/TS/Python）。
44. benchmark 改为真实测量并纳入 CI 门禁。

P1（工程体验）

45. Addon 命令注册去样板化（生成器/模板）。
46. SDK 文档与实现自动一致性校验。
47. 部署脚本跨环境权限模型标准化。
48. 观测面板补齐趋势、回放与异常定位。

P2（产品化）

49. 建立端到端体验评分模型并持续回归。
50. 将“快/稳/智”三指标写入发布准入。
