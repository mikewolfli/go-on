# FUTURE4 — 自进化全能助手升级路线图（自动匹配方案 + 子AI自训练接入）

> 目标：在 FUTURE3 全能助手能力之上，升级为"可自适应进化"的工程 AI 系统，
> 可根据需求自动从 Hugging Face、GitHub 等来源匹配方案，自动构建并训练子 AI，自动接入项目运行时，并通过强化学习持续扩展能力范围。
>
> 规则对齐 FUTURE3：
> - 保持 Local / Server 双轨并行
> - 使用目标编号 + 分阶段执行 + 风险矩阵 + DoD
> - 所有"自动化进化能力"必须受治理、预算、审计与回滚约束

---

## 背景与结论

FUTURE3 已覆盖全能助手核心能力（规划、执行、审查、记忆、评测、治理）。

FUTURE4 增量目标是引入"自进化闭环"：
- 自动发现与匹配外部方案（模型/代码/流程）
- 自动生成与训练场景化子 AI（Sub-AI）
- 自动集成到运行时并可灰度发布
- 自动强化学习并扩展能力边界

核心能力缺口：

| 领域 | 当前基础 | 目标状态 |
|---|---|---|
| 方案发现 | 人工选择为主 | 自动检索并评估 Hugging Face / GitHub 方案 |
| 方案匹配 | 规则驱动初步匹配 | 场景-能力-成本-风险四维匹配引擎 |
| 子AI 构建 | 固定角色代理 | 按任务画像自动生成可训练子 AI |
| 训练管线 | 手工调优 | 数据集自动构建 + 可控训练/微调流水线 |
| 自动接入 | 手工配置接入 | 插件化自动接入 + A/B + 回滚 |
| 强化学习 | 离线指标反馈为主 | 在线/离线混合强化学习与策略演化 |
| 能力扩展 | 版本迭代扩展 | 安全边界内的自增长能力图谱 |

## 执行路线（分阶段执行）

### P0 边界与治理冻结（先约束后自动化）
- [x] 冻结自动进化边界：哪些能力可自动，哪些必须人工审批
- [x] 定义外部来源可信度模型（官方源、社区源、未知源）
- [x] 定义红线策略：禁止高风险自动执行（如无审查写入生产）

### P1 方案发现与匹配引擎
- [x] 接入 Hugging Face 检索：模型卡、许可证、任务标签、推理成本
- [x] 接入 GitHub 检索：仓库活跃度、测试覆盖、许可证、供应链风险
- [x] 建立场景匹配器：任务类型 -> 候选方案排名（质量/成本/风险）

### P2 子AI 工厂与契约
- [x] 建立 Sub-AI 模板：planner、coder、reviewer、researcher、trainer
- [x] 自动生成子 AI 配置（工具权限、上下文窗口、预算）
- [x] 子AI 输出强制 schema（artifact、evidence、confidence、risk）

### P3 数据构建与训练编排
- [x] 构建数据流水线：采集成功轨迹、失败轨迹、审查结论
- [x] 增加数据质量门禁：去重、脱敏、标签一致性
- [x] 建立训练编排器：任务排队、断点恢复、版本化输出

### P4 自动接入与灰度发布
- [x] 子AI 训练完成后自动注册到运行时注册表
- [x] 支持 A/B 与 Canary（按租户/场景/流量切分）
- [x] 自动回滚触发：质量衰退、成本超阈、风险告警

### P5 强化学习与能力扩展
- [x] 定义奖励函数：任务完成度、审查通过率、成本与时延
- [x] 增加离线回放强化学习，在线学习仅在安全白名单场景启用
- [x] 能力图谱自动扩展：新增能力必须通过 eval gate + safety gate

### P6 评测、审计与合规
- [x] 建立多维评测：正确性、稳定性、可解释性、成本、风险
- [x] 建立来源与训练全链路审计（可追责、可回溯）
- [x] 输出合规报告：许可证、数据使用、模型来源、变更记录

### P7 双轨落地与发布
- [x] Local 轨：支持自动匹配与子 AI 执行（默认禁用训练）
- [x] Server 轨：支持完整训练、强化学习与自动接入闭环
- [x] CI/CD 门禁全绿后发布稳定版

## 能力矩阵（FUTURE4 目标能力）

| 能力维度 | 基线要求 | 验收信号 |
|---|---|---|
| 方案发现 | 自动检索外部方案并归档 | 候选方案含来源、许可证、风险评估 |
| 方案匹配 | 按场景自动排名选择 | Top-K 方案在基准任务优于基线 |
| 子AI 构建 | 自动生成并接入角色代理 | 新子 AI 可独立执行并输出合规 artifact |
| 自动训练 | 可恢复、可追踪、可回滚 | 训练产物有版本、日志、评测报告 |
| 自动接入 | 灰度发布与熔断回滚 | 质量下降时自动撤回 |
| 强化学习 | 可控策略改进 | 关键指标持续改善且无安全倒退 |
| 能力扩展 | 在安全边界内自增长 | 新能力上线前通过双门禁 |
| 治理合规 | 可审计可追责 | 全链路 provenance 可查询 |

## 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 外部方案污染（低质/恶意） | 引入安全与质量问题 | 来源可信度分层 + 沙箱评估 + 签名校验 |
| 自动训练过拟合 | 线上效果波动 | 交叉验证 + 回放评测 + 早停策略 |
| 在线强化学习失稳 | 行为偏移与倒退 | 默认离线 RL，在线 RL 仅白名单场景 |
| 成本失控 | 训练/推理预算爆炸 | 硬预算 + 配额 + 自动降级 |
| 子AI 泛滥 | 系统复杂度失控 | 能力图谱配额 + 生命周期管理 |
| 许可证合规风险 | 法务/发布阻断 | 自动许可证扫描与发布门禁 |
| 自动接入误伤主干 | 主流程不稳定 | 强制灰度 + 自动回滚 + 人工确认阈值 |

## 完成标准（DoD）

1. 所有阶段清单从 `[ ]` 变为 `[x]`。
2. 系统可按任务场景自动发现并匹配 Hugging Face / GitHub 方案。
3. 子AI 可自动生成、训练、评测、灰度接入并支持一键回滚。
4. 强化学习闭环可运行，且策略更新必须通过安全与评测双门禁。
5. 能力扩展全部纳入 capability graph，具备依赖与风险标注。
6. Local/Server 双轨行为一致性通过；训练默认仅 Server 轨开放。
7. 全链审计可追溯来源、训练数据、模型版本、上线变更。
8. CI/CD 新增门禁持续绿色后方可发布。
