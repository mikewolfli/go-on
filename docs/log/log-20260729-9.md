## 3. 本轮发现的违规项

### 🔴 Critical 3.1 — `src/agents/openai.rs`: 文件级 `#![allow(dead_code)]`

**原则违反**: #14（禁止文件级/模块级 allow dead_code）

**代码**:
```rust
//! OpenAI agent implementation
//! ...
// Note: OpenAiAgent is superseded by OpenAiCompatibleAgent with compression enabled.
// The struct and methods are kept for backward compatibility as public API.
#![allow(dead_code)]   // ← 文件级绕过！
```

**分析**:
- 整个 `OpenAiAgent` 模块已废弃，被 `OpenAiCompatibleAgent` 替代
- 注释说 "kept for backward compatibility"，但没有任何代码引用 `OpenAiAgent`
- 文件级 `#![allow(dead_code)]` 违反蓝图的明确禁令
- 该模块实际上在编译时不会被链接（未被任何生产路径引用），但因为是 pub mod 仍在编译

**修复方案**: 
1. 删除文件级 `#![allow(dead_code)]`
2. 改为 `#[cfg_attr(not(test), allow(dead_code))]` 在模块级，但原则 #14 也禁止。
3. **最正确的修复**: 将该模块标记为 `#[cfg_attr(any(), allow(dead_code))]` — 不行。**正确的修复是将整个模块 feature-gate 为 `#[cfg(feature = "legacy-openai")]` 配置项**，或直接删除该文件如果确认无外部依赖。
4. **本次选用的务实方案**: 移除 `#![allow(dead_code)]`，在 `OpenAiAgent` 结构体上加精确的 `#[allow(dead_code)]`（因为字段未使用），其余函数/方法全部删除。但字段-level `allow(dead_code)` 仍不理想。
5. **最彻底的方案**: 声明模块为 `#[cfg(feature = "sub-bus-legacy")]` 或者删除整个文件。考虑到该文件已经无人使用，直接删除是符合 principle.md 的最佳方案。

**决定**: 删除整个 `OpenAiAgent` 文件，200+ 行完全死代码。如果有人需要，可以从 git 历史恢复。`OpenAiCompatibleAgent` 已在 `src/agents/openai_compatible.rs` 中完全替代其功能。

### 🔴 Critical 3.2 — `src/memory/pg_pool.rs`: `Handle::current().block_on()` 热路径违规

**原则违反**: #23（block_in_place + block_on 禁止在热路径）、#24（Handle::current().block_on() 必须清零）

**代码**:
```rust
#[cfg(feature = "backend-postgres")]
pub(crate) fn pool_get(pool: &PgPool) -> Result<deadpool::managed::Object<PgClientManager>> {
    tokio::task::block_in_place(|| {
        tokio::runtime::Handle::current()   // ← Handle::current() 未使用 try_current() 模式
            .block_on(pool.get())           // ← block_on 在热路径
            .map_err(|e| anyhow::anyhow!("pool get failed: {e}"))
    })
}
```

**分析**:
- `pool_get` 是一个同步函数，用于将 async `deadpool::Pool::get()` 桥接到同步 `postgres::Client`
- 但它使用了双重违规模式：`block_in_place` + `Handle::current().block_on()`
- 根据原则 #24，应使用 `Handle::try_current()` 并优雅处理无 runtime 场景
- 根据原则 #23，这个模式不应出现在 production 热路径（缓存/向量读写的每个请求都会调用）

**更根本的修复**: 
- `pool_get` 的调用者应该在 spawn_blocking 内部调用 `pool_get`，而 pool_get 应该使用 `Handle::try_current()` 并回退到创建临时 runtime
- 但更彻底的修复是让所有调用处改为 async，直接 `.await pool.get()`

**由于此问题需要修改调用链上的多处代码（cache.rs, vector.rs 等），且涉及 PostgreSQL 生产部署的关键路径，本次扫描将其标记为待修复项。**
