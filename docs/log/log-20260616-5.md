## Round 1 发现汇总

### 🔴 P0 — 关键问题 (8 个)

#### 1. ObservabilityStack 死锁 + 死代码

**文件**: `src/observability/mod.rs`
**问题**: `ObservabilityStack` 结构体包含 3 个 `Arc<Mutex<...>>` 字段，全部标注 `#[allow(dead_code)]`。该结构体在 `bootstrap.rs` 中被创建后立即丢弃，锁从未被获取。
**修复**: 将字段替换为 `OnceLock<ObservabilityStackInner>` 全局单例；`init_independent()` → `init_independent_stack()` (幂等，返回 bool)。

#### 2. protocol_version 使用 async Mutex 包裹 u16

**文件**: `gui/src/backend/mod.rs`
**问题**: `protocol_version: Arc<tokio::sync::Mutex<u16>>` — 一个 u16 值不需要 async 互斥锁，应为 `AtomicU16`。
**修复**: 替换为 `Arc<AtomicU16>`，使用 `store(Ordering::Relaxed)` 写入。

#### 3. chat_endpoint 使用 async Mutex 包裹 String

**文件**: `gui/src/backend/mod.rs`
**问题**: `chat_endpoint: Arc<tokio::sync::Mutex<String>>` — 读多写少模式应使用 RwLock。
**修复**: 替换为 `Arc<tokio::sync::RwLock<String>>`。

#### 4. mime_to_extension() → parse_bytes() 管道断裂

**文件**: `src/multimodal/document_parser.rs`
**问题**: `mime_to_extension()` 映射 csv/json/xml/yaml/txt 扩展名，但 `parse_bytes()` 的 match 臂不处理这些扩展名，导致 `UnsupportedExtension` 错误。
**修复**: 新增 `parse_plain_text_bytes()` 处理方法，支持 csv/json/xml/yaml/txt 作为纯 UTF-8 文本。

#### 5. PROMPT_SKILL_AGENT 未接线

**文件**: `src/acp/impl/runtime/server_builder.rs`
**问题**: `PromptBasedSkill` 的 `execute()` 从不调用真正的 LLM，因为 `set_prompt_skill_agent()` 从未被调用。
**修复**: 在 `wire_server()` 中，当 `skills_enabled` 为 true 时，从代理注册表中查找主代理，包装为 `ChatBasedSkillAgent` 并调用 `set_prompt_skill_agent()`。

#### 6. 音频格式硬编码为 Wav

**文件**: `src/multimodal/mod.rs`
**问题**: `process_audio()` 始终传递 `AudioFormat::Wav`，导致非 WAV 音频（MP3/FLAC/OGG）失败。
**修复**: 新增 `detect_audio_format()` 函数，从魔数检测格式（RIFF + WAVE → Wav, fLaC → Flac, ID3/FFFB → Mp3, OggS → Ogg）。

#### 7. 视频临时文件扩展名硬编码为 .mp4

**文件**: `src/multimodal/mod.rs`
**问题**: `process_video()` 始终写入 `input.mp4`，导致非 MP4 格式（MKV/AVI/MOV）失败。
**修复**: 新增 `detect_video_ext()` 函数，从魔数检测视频扩展名（EBML → mkv, RIFF+AVI → avi, ftyp+qt → mov, ftyp → mp4）。

#### 8. Tokio features = ["full"] 过于宽泛

**文件**: `Cargo.toml`
**问题**: 工作区依赖使用 `features = ["full"]`，编译了大量不需要的特性。
**修复**: 替换为精确特性集：`rt-multi-thread, macros, sync, signal, process, fs, net, io-util, time, io-std`。

### 🟡 P1 — 次要优化 (3 个)

#### 9. excel/ppt 处理器缺少重新导出

**文件**: `src/multimodal/mod.rs`
**问题**: 外部消费者通过 `go_on::multimodal::*` 无法获取 `parse_excel_bytes` 或 `parse_pptx_bytes`。
**修复**: 添加条件编译的重新导出块。

#### 10. 缺少工作区级 [profile.release]

**文件**: `Cargo.toml`
**问题**: `[profile.release]` 仅存在于主 crate，GUI/sdk/test_i18n 未受益。
**修复**: 改为 `[workspace.profile.release]`，所有工作区成员继承。

#### 11. wire_cert_monitor 误导性注释

**文件**: `src/security/mod.rs`
**问题**: 注释说"保留为 no-op 以避免破坏调用者"，暗示无调用者，但实际上 2 个调用者存在。
**修复**: 更新注释为诚实说明。

### 🟢 P2 — 已确认无需更改 (5 个)

| 项目 | 文件 | 结论 |

| F-GAP 系列死代码 | 多个 | 所有 `#[allow(dead_code)]` 均带有功能跟踪 ID，是故意保留的未来脚手架 |

| `#[cfg(not(...))]` 门控 | 多个 | 所有均为合法条件编译 |
| `_` 前缀变量 | 多个 | 全部为符合规范的未使用变量抑制 |

## Round 2 发现汇总

### 🔴 P0 — 关键问题 (5 个)

#### 12. 完全删除死代码 grpc.rs

**文件**: `src/protocol/grpc.rs`
**问题**: 100% 死代码（232 行），每个项目都有 `#[allow(dead_code)]`。`GrpcRemoteExecutor` 不存在于当前代码库中。
**修复**: 删除整个文件 + 从 `protocol/mod.rs` 移除 `pub mod grpc;`。

#### 13. 从 schema/agent.rs 删除 11 个死类型

**文件**: `src/schema/agent.rs`
**问题**: `InitializeRequest`、`NewSessionRequest` 等 11 个请求类型和结构体被标记为死代码且从未使用。
**修复**: 删除 11 个类型定义及其 impl 块（~100 行）。`AuthMethodAgent.id` 改为 `String`；`ListSessionsResponse.sessions` 改为 `Vec<serde_json::Value>`。

#### 14. 缺少 `go-on skill` CLI 子命令

**文件**: `src/main/cli.rs`、`src/main/mod.rs`
**问题**: `scripts/skills-setup.sh` 引用 `go-on skill list` 和 `go-on skill import`，但这些命令不存在。
**修复**: 增加 `Skill` 子命令枚举，支持 `list`、`import`、`list-imported` 三个子命令。调用 `SkillMarketRegistry` 和 `SkillRegistry`。

#### 15. 两个占位测试（空函数体）

**文件**: `tests/e2e/test_server_startup_health.rs`、`tests/e2e/test_distributed_dag_e2e.rs`
**问题**: 违反 rule #9（不允许占位/空函数）——两个测试函数只有 `// Placeholder test — no assertions yet.`
**修复**: 
- `test_server_startup_health.rs`：运行时配置验证、ObservabilityStack 幂等性、GovernanceStatus 默认值测试
- `test_distributed_dag_e2e.rs`：CoreDag 空图排序、单节点、线性拓扑、环检测、指标计算测试

#### 16. first-run.sh 未调用 skills-setup.sh

**文件**: `scripts/first-run.sh`
**问题**: 首次运行脚本不自动设置技能环境。
**修复**: 在 macOS 信任引导后增加 skills-setup.sh 调用。
