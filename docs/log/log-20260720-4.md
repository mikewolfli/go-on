## 第五部分：本轮新增实施（S1 + 阶段2）

### S1: 懒加载 MemoryPersistence 启动优化

**问题**：`new_acp_server()` 在启动时同步创建了 **2 个 `MemoryPersistence::new()`** 实例，每个打开 SQLite 连接 + DDL 创建约 50-150ms，总计 **100-300ms** 不必要的启动延迟。

**方案**：使用 `OnceLock` 将创建推迟到首次实际访问时。

**修改文件**：
- `src/acp/server.rs`：新增 `lazy_memory_persistence`、`lazy_memory_retrieval_engine`、`lazy_memory_persistence_params` 三个 `OnceLock` 字段 + `get_or_init_memory_persistence()` / `get_or_init_memory_retrieval_engine()` 方法 + `LazyMemoryPersistenceParams` 结构体
- `src/acp/impl/runtime/server_builder.rs`：将 MemoryPersistence 的 2 次创建替换为存储路径 + 通过 `with_lazy_memory_persistence_params()` 传递
- `src/acp/background.rs`：后台任务中调用 `server.get_or_init_memory_persistence()` 懒初始化
- `src/acp/impl/runtime.rs`：memory bridge promote 中调用懒初始化
- `src/acp/impl/chat_phases.rs`：reflection persistence + retrieval engine 使用懒初始化
- 删除 `with_memory_persistence` 和 `with_memory_retrieval_engine` 两个死 builder 方法

**预估节省**：启动延迟 **100-300ms**（SQLite 连接创建移到首次请求时）
