## 具体发现与变更

### 🔴 变更1: 修复GUI ConfigStore锁中毒panic

**文件**: `gui/src/config_store.rs:36,45,109`

**问题**: 3处 `.expect("ConfigStore lock poisoned")` — 如果一个async任务在持有锁时panic，所有后续ConfigStore操作都会panic导致GUI崩溃。

**修复**: 改用 `.unwrap_or_else(|e| e.into_inner())` 模式，与其他模块一致。

### 🔴 变更2: 修复deepseek expect panic

**文件**: `src/agents/deepseek.rs:122`

**问题**: `.expect("B48: payload object")` — payload在运行时可能被上游代码修改，panic会导致agent崩溃。

**修复**: 改用 `if let Some(obj) = payload.as_object_mut()` 模式，与同文件L126-130已有的正确处理方式一致。

### 🟡 变更3: 修复GUI wasted allocation

**文件**: `gui/src/views/providers/render.rs:453`

**问题**: `.map(|p| p.model.clone())` 的结果被丢弃（`let _ =`）。每次渲染循环都clone model字符串但从不使用。

**修复**: 删除无意义的 `.map()` 链。

### 🟡 变更4: 添加8个agent的default_model()

**文件**: fireworks.rs, nim.rs, together.rs, groq.rs, mistral.rs, perplexity.rs, replicate.rs, yi.rs

**问题**: 这8个agent定义了 `available_models()` 并设置了 `is_default` 标记，但没有覆盖 `default_model()`，导致默认模型返回 `None`。

**修复**: 添加 `fn default_model()` 覆盖，返回 `is_default` 为true的第一个模型。

### 🔴 变更5: 修复i18n zh-TW key命名不一致

**文件**: `config/languages/zh-TW.json`

**问题**: zh-TW使用 `warn.` 前缀（如 `warn.degraded_mode`），而en-US和zh-CN使用 `warning.` 前缀。运行时查找 `warning.degraded_mode` 时zh-TW会找不到。

**修复**: 将zh-TW中的5个 `warn.*` key改为 `warning.*`。

### 🟡 变更6: 修复测试结构 (无timeout风险)

**文件**: 全部 `tests/*.rs` / `tests/e2e/*.rs`

**问题**: 所有spawn子进程的async测试都没有 `#[tokio::test(timeout = ...)]`，如果子进程卡住会导致CI无限挂起。

**修复**: 添加 `#[cfg(not(target_os = "windows"))]` 兼容timeout标注。
