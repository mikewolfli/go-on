# 全链路自动化工作流修复日志 - 2026-07-09

## 问题概述

用户通过 Agent World 邀请链接尝试接入 Agent 世界时，Go-On Agent 无法自动完成多步接入流程，表现为：
1. GUI 打开后跳转到 Provider 配置页（keyring 无法访问）
2. Agent 收到 URL 后只回复文本，不调用 `http_request` 执行
3. Agent 获取 SPA 页面后无法自动发现 API 端点
4. Agent 在获取任务包后不继续执行后续步骤（下载 Skill、生成密钥、提交绑定申请）
5. GUI 缺少 approve/deny 按钮

## 根本原因与修复

### 🔥 Fix 1: keyring 缺少 Linux Secret Service 后端

**位置**: `go-on/Cargo.toml`, `go-on/gui/Cargo.toml`

**根因**: keyring crate 的依赖只启用了 `apple-native`（macOS 专用特性），在 Linux 上没有任何可用的密钥环后端。`keyring` crate v3.6.3 的默认特性**不包含** Linux Secret Service 支持，必须显式启用 `sync-secret-service`。

```toml
# 修复前
keyring = { version = "3", features = ["apple-native"] }
# 修复后
keyring = { version = "3", features = ["apple-native", "sync-secret-service"] }
```

**影响**: `get_password()` 始终返回 "No matching entry found"，导致 `has_valid_providers()` 返回 `false`，GUI 跳转到 Provider 配置页。

**补充修复**: `go-on/gui/src/config.rs` 中 `compute_valid_providers()` 添加 fallback：当 `config.providers` 有 provider 条目时视为有效（应对 keyring 临时不可用的情况）。

---

### 🔥 Fix 2: `observe_phase` 缺少 URL 自动预抓取

**位置**: `go-on/src/acp/impl/chat_phases.rs`

**根因**: 聊天管道的 `observe_phase`（第一阶段）没有检测用户消息中的 URL，导致 LLM 需要自行决定是否调用 `http_request`。LLM 经常选择回复文本而不是执行工具。

**修复**: 在 `observe_phase` 中添加 URL 自动检测与预抓取逻辑：
- 扫描用户消息中的 HTTP/HTTPS URL
- 自动使用 `reqwest` 抓取 URL 内容（10 秒超时）
- 将抓取结果注入为 `system` 消息上下文
- 跳过本地/私有 IP 地址

---

### 🔥 Fix 3: SPA API 探针

**位置**: `go-on/src/acp/impl/chat_phases.rs`

**根因**: 对于 JavaScript SPA 页面，纯 HTTP GET 只能获取 HTML 外壳（`<div id="root">`），无法获取实际数据。URL 中的 `#fragment` 参数不会被发送到服务器。

**修复**: 在预抓取后检测 SPA 页面特征，自动执行：
1. 从 URL fragment 中提取参数（如 `task_access_token`）
2. 从 URL path 中提取路径参数（如 `invitation_id`）
3. 尝试 POST 到常见 API 模式（`/api/v1/agent-binding/invitations/{id}/agent-task`）
4. 将 API 探针结果追加到上下文消息

---

### 🔥 Fix 4: PUA 自动化规则不完善

**位置**: `go-on/src/governance/pua.rs`, `go-on/RULES/pua.md`

**根因**: 原有的 URL 规则只有一条简单指令，不足以指导 LLM 完成多步工作流。且规则与 `observe_phase` 预抓取存在冲突。

**修复**: 重新设计为 7 层 20+ 条通用规则体系：

| 层 | 规则 | 覆盖场景 |
|----|------|----------|
| Layer 1: Fetch | FETCH-001 | 任意 HTTP/HTTPS URL，含 fragment 和 query params；利用预抓取数据 |
| Layer 2: Analyze | ANALYZE-001, ANALYZE-002 | JSON/SPA/静态页面/二进制分类；401/403 自动探测认证方式 |
| Layer 3: Extract | EXTRACT-001~003 | 数据提取、端点发现、分页、Accept 头协商 |
| Layer 4: Chain | CHAIN-001~005 | 顺序执行、并行分发、人工在环、幂等性、限速 |
| Layer 5: Resource | RES-001~003 | 文件下载校验、密钥生成、签名 |
| Layer 6: Streaming | STREAM-001 | SSE/WebSocket 实时通信 |
| Layer 7: Error | ERR-001~003 | 指数退避重试、部分失败恢复、诚实限制报告 |

---

### 🔥🔥 Fix 5: `autonomy_loop` 丢弃 PUA 规则和工具定义（3 个连锁 Bug）

**位置**: 
- `go-on/src/acp/helpers/autonomy/autonomy_loop.rs`
- `go-on/src/acp/helpers/autonomy/autonomy_loop_adapter.rs`

**根因**: 这是最关键的 Bug。自主循环（autonomy loop）中有 3 个连锁缺陷：

**Bug 5a**: `run_autonomy_loop` 调用 `agent.chat()` 时传入了 `None, None`：
```rust
// 修复前：principles 和 options 都是 None
agent_clone.chat(agent_messages, None, None, sender)
```
`options` 参数包含 `tools`（http_request 等工具定义）和 `tool_choice`（"auto"），但因为没传进去，LLM 根本不知道有工具可用，只能用文字描述"我想用 http_request 拉一下 manifest"。

**Bug 5b**: `_principles` 前缀下划线导致 PUA 规则被静默丢弃：
```rust
// 修复前：下划线前缀表示"故意不用"
_principles: Option<Vec<String>>,
```

**Bug 5c**: 后续轮次丢失 PUA 上下文：
第一轮之后的消息被替换为简单的 "Continue with the task"，PUA 规则不再出现在后续轮次的上下文中。

**修复**:
1. `run_autonomy_loop` 新增 `principles` 和 `options` 参数
2. 传递给 `agent.chat()`:
   ```rust
   agent_clone.chat(agent_messages, principles_clone, options_clone, sender)
   ```
3. `_principles` → `principles`
4. 后续轮次消息保留 PUA 上下文

**影响**: 这是 LLM 无法调用任何工具的根本原因。修复后 LLM 在每个轮次都能收到完整的工具定义和 PUA 自动化规则，可以自动完成多步工作流。

---

### 🔥 Fix 6: `http_request` 工具在 `extract_url` 中使用 `#fragment` 限制

**位置**: `go-on/src/orchestration/tool/extended/http.rs`

**根因**: `extract_url` 提取 URL 后，工具在执行 HTTP 请求时自动丢弃 fragment。但 `observe_phase` 需要完整的原始 URL（含 fragment）来提取参数。

**修复**: 将 `extract_url` 从 `fn` 改为 `pub(crate) fn`，使其可在其他模块中使用。

---

### 🔥 Fix 7: URL 预抓取在 `observe_phase` 中需要 `&mut ChatParams`

**位置**: `go-on/src/acp/impl/chat_phases.rs`, `go-on/src/acp/impl/chat/pipeline.rs`, `go-on/src/acp/impl/chat.rs`, 以及 6 个调用站点

**根因**: URL 预抓取需要向 `params.messages` 插入系统消息，但函数签名使用 `&ChatParams`（不可变引用）。

**修复**: 将 `observe_phase`、`ChatPipeline::run`、`process_chat_request` 的参数从 `&ChatParams` 改为 `&mut ChatParams`，并更新所有 10+ 个调用站点。
