## 发现的问题与修复

### ✅ 变更1: 移除 `security/mod.rs` 中两处获取器函数（真正死代码）

**文件**: `src/security/mod.rs`

**问题**: 
- `get_content_safety_checker()` — 带 `#[allow(dead_code)]`，全局搜索确认**零个调用点**
- `get_prompt_injection_detector()` — 带 `#[allow(dead_code)]`，全局搜索确认**零个调用点**
- 违背原则#14（禁止 `#[allow(dead_code)]` 替代真正的接线或删除）

**修复**: 删除这两个函数 + 对应的 `#[allow(dead_code)]`。
- `wire_content_safety()` 和 `wire_prompt_injection()` 保留不变（它们在 `server_builder.rs` 和 `main/server.rs` 中被调用）
- `CONTENT_SAFETY_CHECKER` 和 `PROMPT_INJECTION_DETECTOR` OnceLock 保留（被 wire 函数使用）

**效果**:
- 消除2处违背原则#14的 `#[allow(dead_code)]`
- 减少二进制体积（去掉2个函数 + 注释）
- 原有功能完整性不受影响（wire函数继续执行安全检查初始化）

### ✅ 变更7: 修复 `barcode.rs` 中冗余 `#[cfg(feature)]` 导致的 28 个 rust-analyzer 假阳性错误

**文件**: `src/orchestration/tool/extended/barcode.rs`

**问题**: 
- `barcode.rs` 内所有函数、结构体、常量都重复标注了 `#[cfg(feature = "barcode-tools")]`，而模块级 gate（在 `mod.rs` 中 `#[cfg(feature = "barcode-tools")] pub mod barcode;`）已经足够
- 双重 gate 导致 rust-analyzer 在分析文件时由于无法解析 gated-out 的导入类型而产生 28 个假阳性语法错误
- 此外，`place_format_info()` 函数的 `mask_id` 参数从未使用（之前被冗余 cfg 隐藏）

**修复**:
1. 删除文件内所有冗余 `#[cfg(feature = "barcode-tools")]` — 保留 `use` 导入、`struct`、`impl`、所有 `fn` 和 `const` 上的标注
2. 修复 `place_format_info()` 中未使用变量警告：`mask_id` → `_mask_id`

**验证**:
```bash
cargo check --no-default-features --features "local,barcode-tools"  # ✅ 零错误、零警告
cargo test --lib --no-default-features --features "local,barcode-tools" barcode  # ✅ 6/6 通过
cargo check  # ✅ 默认 Profile 零错误
```
