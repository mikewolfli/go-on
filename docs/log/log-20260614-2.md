# GUI 无法连接后台 — Debug & Fix Log — 2026-06-14 (Round 1)

> **问题**: GUI 启动后无法连接后台，后台进程存活但不监听 8090 端口
> **排查方式**: 全链路分析 + 进程栈采样 + 源码调试

---

## 问题现象

GUI 启动后反复重试 RPC 连接：
```
[RPC] Attempt 1/1000 transport error for url (http://127.0.0.1:8090/rpc)
```

后台进程 `go-on` 存活但未监听任何 TCP 端口 (`lsof -i :8090` 无输出)。进程 CPU 使用率接近 0%，卡在 `S` (sleep) 状态。

## 排查过程

### Step 1: 进程栈采样（sample）

```
$ sample <PID>
→ 主线程阻塞在 __psynch_mutexwait
→ _pthread_mutex_firstfit_lock_slow
→ <std::sync::Mutex>::lock
```

所有 tokio 工作线程空闲（等待 condvar），主线程被 mutex 死锁阻塞。

### Step 2: LLDB 符号化（debug build）

```
frame #7: self_model.rs:209 — SelfModelCore::persist → lock_guard(&self.inner)
frame #8: self_model.rs:244 — SelfModelCore::set_identity → self.persist()
frame #6: server_builder.rs:168 — new_acp_server 闭包
```

**关键发现**: `set_identity()` 先锁了 `self.inner`，然后调用 `self.persist()` 再次锁同一个 `self.inner`。`std::sync::Mutex` **不可重入**，导致同一线程死锁。

### Step 3: macOS Keychain 阻塞（第二死锁点）

修复 Step 1 后进程继续卡住，再次采样发现：

```
frame #14: security_framework::os::macos::passwords::find_generic_password
frame #15: keyring::Entry::get_password
frame #16: agent.rs:275 — load_secret_value
```

`SecKeychainFindGenericPassword` 在后台无 GUI 会话时永久阻塞。原代码没有超时机制。

### Step 4: RPC Pipe 读取永不返回（第三问题）

测试 RPC endpoint 发现 `POST /rpc` 请求永不返回。分析代码：

```
pipe_writer → server.output → handle_request → write to pipe
pipe_reader → read_to_end → 等待 pipe 关闭
restore stdout → 关闭 pipe writer ← 在 read_to_end 之后!
```

`read_to_end` 在 writer 关闭前不会返回，但 writer 关闭在 read 之后，形成死循环。

## 修复详情

### Fix 1: SelfModelCore 重入锁死锁 [CRITICAL]

**文件**: `src/intelligence/self_model.rs`

**问题**: `set_identity()` 锁住 `self.inner` 后调用 `persist()`，而 `persist()` 再次锁 `self.inner`。

**修复**: 将 `persist()` 拆分为锁内写入版 `persist_inner()` 和带锁版 `persist()`。

```diff
  fn persist(&self) {
      let inner = lock_guard(&self.inner);
-     inner.persistence_path ...  // 原内联逻辑
+     Self::persist_inner(&inner);
+ }
+
+ fn persist_inner(inner: &Inner) {
      if let Some(path) = &inner.persistence_path { ... }
  }

  pub fn set_identity(&self, identity: SelfIdentity) {
      let mut inner = lock_guard(&self.inner);
      inner.identity = Some(identity);
-     self.persist();                // ← 重入锁死锁
+     Self::persist_inner(&inner);   // ← 避免二次加锁
  }
```

### Fix 2: macOS Keychain 超时降级 [HIGH]

**文件**: `src/agents/agent.rs`

**问题**: `keyring::Entry::get_password()` 调用 `SecKeychainFindGenericPassword`，后台模式下永久阻塞。

**修复**: 在 keychain 访问外层添加 `std::thread::spawn` + `recv_timeout(5s)`，超时后自动降级到环境变量。

```diff
  Ok(entry) => {
-     match entry.get_password() {
+     let (tx, rx) = std::sync::mpsc::channel();
+     std::thread::spawn(move || {
+         let _ = tx.send(entry.get_password());
+     });
+     match rx.recv_timeout(Duration::from_secs(5)) {
          Ok(Ok(value)) if !value.is_empty() => return Ok(value),
-         ...
+         Err(_timeout) => {
+             warn!("keyring lookup timed out after 5s, falling back");
+             keyring_error = "keychain lookup timed out";
+         }
      }
  }
```

### Fix 3: RPC Pipe 读取顺序错误 [HIGH]

**文件**: `src/acp/impl/runtime/http.rs`

**问题**: `read_to_end` 在 pipe writer 关闭前不会返回，但 writer 关闭在 pipe 读取之后。

**修复**: 交换顺序——先等 RPC 任务完成并恢复 stdout（关闭 writer），再读取 pipe。

```diff
- let mut response_bytes = Vec::new();
- let read_result = pipe_reader.read_to_end(&mut response_bytes).await;
  let rpc_result = rpc_task.await;
  // 恢复 stdout → 关闭 pipe writer
  { let mut guard = server.output.lock().await;
    let _ = mem::replace(&mut *guard, Box::new(tokio::io::stdout())); }
+ let mut response_bytes = Vec::new();
+ let read_result = pipe_reader.read_to_end(&mut response_bytes).await;
```

### Fix 4: HotReload enabled 字段未使用 [LOW]

**文件**: `src/core/config/hot_reload.rs`, `src/main/mod.rs`

**问题**: `HotReloadConfig.enabled` 定义了但 `start()` 方法从未检查。`main/mod.rs` 中设置 `enabled: false` 不会阻止 notify watcher 创建。

**修复**: `start()` 方法中添加 `enabled` 检查，为 `false` 时立即返回空任务。

### Fix 5: 文件对话框每帧弹出 [CRITICAL]

**文件**: `gui/src/views/chat/chat_impl/ui/old_ui_content.rs`

**问题**: `attachments::handle_attach_button(self, ui)` 和 `attachments::handle_external_editor(self, ui)` 在聊天页面的水平工具栏中每帧无条件调用，未包裹在 `clicked()` 守卫中。

- `handle_external_editor()` 每次调用写入临时文件并尝试启动外部编辑器

```diff
  if CHAT_STAGE6_ENABLE_EXTRA_BUTTONS {
-     attachments::handle_attach_button(self, ui);
-     attachments::handle_external_editor(self, ui);
+     if ui.button("📎").on_hover_text(...).clicked() {

+     }

+     }
```
