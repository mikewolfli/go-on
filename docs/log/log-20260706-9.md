## 已发现并修正的问题

### 1. ToolRegistry 代码重复优化
**问题**: `run_with_fallback` (同步) 和 `run_with_fallback_async` (异步) 有超过80行几乎完全相同的降级链逻辑，违反了DRY原则。

**修改**: 抽取公共降级核心 `execute_fallback_chain`，两个变体都调用同一个核心逻辑。同步版本保持 `primary.run(input)`，异步版本使用 `primary.run_async(input.clone()).await`，在fallback循环中共享相同的profile查找和metrics记录代码。

**影响**: 减少重复代码 ~80 行，维护时只需要修改一处降级逻辑。

### 2. Governance Gate 别名处理优化
**问题**: `execute_simple_tool` 先调用 `governance_gate(name, args)` 检查工具名，再执行别名映射。但governance gate中的工具名单可能不包含别名(如"bash", "run")，导致合法请求被拒绝。

**修改**: 将别名映射移到governance gate之前，确保gate检查的是规范化后的工具名。

**影响**: 通过 `bash`、`run`、`grep` 等别名调用的工具不再被governance gate误拦。

### 3. Chat 系统消息与实际工具同步
**问题**: chat.rs 的初始 system message 中列出的工具列表与实际 `ToolRegistry::new()` 注册的工具不完全同步，缺少 `create_directory`, `copy_path`, `diagnostics`, `environment_info` 等核心工具。

**修改**: 同步 system message 中的工具列表，使用 `tool_registry().all_names()` 动态生成列表。

**影响**: AI agent 现在能感知到所有已注册工具，包括最近新增的。

### 4. Session 自动保存优化
**问题**: 自动保存使用 `tokio::spawn` 每次克隆整个messages数组，在长会话中造成大量内存分配。

**修改**: 使用 `Arc<Mutex<>>` 保护session数据，只在需要持久化时加锁克隆。

**影响**: 减少长会话中的内存分配和消息克隆开销。

### 5. Token 估算优化
**问题**: `estimate_tokens` 每次调用都要遍历全文，在长会话中频繁调用。

**修改**: 引入 `CachedTokenEstimator` 包装，缓存已计算过的消息token数，只对新消息进行计算。

**影响**: 减少 token 估算的重复计算，提升长会话性能。

### 6. 工具执行 Metrics 冗余记录
**问题**: `record_tool_execution` 在 `run_with_fallback` / `run_with_fallback_async` 中的成功/失败路径各被调用一次，且在 `execute_simple_tool` 中没有调用。

**修改**: 统一在 `execute_simple_tool` 的出口处调用一次，减少 metrics 记录冗余。

**影响**: metrics 数据更准确，无重复计数。

### 7. 清理空的 feature gate 代码
**问题**: `sub-bus-voter-future` feature 在 Cargo.toml 中定义但在源码中未被任何 `#[cfg(feature = ...)]` 使用。

**修改**: 保留 feature 定义（可能用于 future），添加注释说明当前未使用状态。

**影响**: 代码意图更清晰。

### 8. 移除无意义的测试
**问题**: 发现部分测试使用了宽松的 `assert!(result.len() >= 6)` 而不是精确值。

**修改**: 对能够确定工具数量的测试使用更精确的断言。

**影响**: 测试更加精确可靠。
