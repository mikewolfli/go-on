## 最终轮优化 (Round 3 — 流式增量Markdown渲染)

### 背景

原方案：流式输出原始文本 → 完成后对整个response重新markdown渲染 → ANSI擦除行 → 重新打印格式化文本。**存在可见闪烁**（尤其含大代码块时）。

### 实现方案

新增 `StreamMarkdownRenderer`（在 `markdown_renderer.rs` 中）：

```mermaid
flowchart LR
    A[LLM token] --> B[line_buf 缓冲]
    B --> C{\n 到达?}
    C -->|否| D[继续缓冲 + 打印原始文本]
    C -->|是| E[process_line]
    E --> F{类型判断}
    F -->|代码块| G[缓冲到 ```]
    F -->|表格| H[缓冲到非|行]
    F -->|普通行| I[立即render_inline + flush]
    G --> J[代码块关闭→render_code_block→flush]
    H --> K[表格结束→render_table→flush]
    I --> L[out_buf → cursor up擦除原始行 → 打印ANSI格式化行]
```

### 关键变更

| 文件 | 变更 |
|------|------|
| `cli/markdown_renderer.rs` | 新增 `StreamMarkdownRenderer` 结构体 + 295行实现（`feed`/`flush`/`take_raw_response`/`process_line`/`render_regular_line`） |
| `cli/chat.rs` | 主循环和跟循环各使用独立的 `StreamMarkdownRenderer`，`renderer.feed(token)` + `renderer.flush()` 逐行增量输出 |
| `cli/markdown_renderer.rs` | `render_markdown` 标记为 `#[allow(dead_code)]`（公共API保留） |

### 消除的后处理开销

- ❌ `response.clone()` → 不再需要（renderer 维护 raw_response）
- ❌ `spawn_blocking(move || render_markdown(...))` → 不再需要
- ❌ ANSI行擦除循环（`\x1B[F\x1B[K` × line_count）→ 仅在行完成时局部擦除
- ❌ `followup_response.clone()` → 不再需要
