### 4. GUI token 重估死调用修复 ✅

### 5. L3 假模板缓存整体删除 ✅（违反 principle #9/#14 的假实现）

`L3TemplateCache`（token_cache L554-796，约 240 行）是**彻头彻尾的假实现**：
- `add_template` 存 `output_template: entry.output.clone()`（完整旧输出原文，不含 `{input}` 占位符）
- `match_template` 执行 `template.output_template.replace("{input}", input)` 是 **no-op**
- 命中时**原样返回旧回复全文** → 结构签名相同（≥10 字符）但内容不同的长请求会得到完全不相关的旧回答（正确性 bug）
- 注释谎称 "SQLite-backed"（实为 JSON 文件）、"FIFO 逐出"（实为 HashMap 任意序）

**删除**：`L3TemplateCache`/`TemplatePattern`/`extract_signature`/`match_template`/`add_template`/`save_to_disk`/`load_from_disk` 全删；`TokenMultiLevelCache` 移除 `l3` 字段与 `new()` 的 `l3_store_path` 参数；`CacheLevel::L3` 删除；stats 移除 `l3_hits/l3_misses`（Long miss 归入 L2 统计）；health payload 移除 l3 段；`cache_strategy.rs` 的 "L3" 分支删除 + 2 个 L3 测试改为 unknown-level Miss 断言。三端 grep 零消费，删除安全。

**效果**：消除假命中返回旧文的正确性 bug；L2 语义缓存已覆盖 Medium+Long 输入，功能无损。
