## 1. 实施内容(5 项全部完成)

### P0 — EvolutionLoop 人工审批补接线(消除 §8/§13 占位违规)

**问题**:`evolution_loop/mod.rs` 的 `RequireHuman`/`RequireApproval` 分支此前写死 `"not implemented yet — rejecting"`(blue71 标记的 go-on 唯一自进化缺口)。

**方案**:新建进程级审批子系统,事件驱动(blue71 要求,非轮询):
- `src/orchestration/self_evolution/approval.rs` — `ApprovalBroker` 进程单例:submit → watch channel → respond(approve/deny)+ 有界 resolved 审计队列(128 条)
- `evolution_loop/mod.rs` — `await_approval` 接入 broker:`RequireApproval`/`RequireHuman` 提交请求并 await watch 决策;新增 `with_approval_timeout`(默认 10 分钟,超时转拒绝,防挂起)
- `evolution_loop/apply.rs` 错误语义保持(`Rejected` 非终止循环)
- ACP 面:`evolution.approval.list` / `evolution.approval.respond`
- **state-sync 联动**:submit/respond 发布 `StateSyncEvent::ApprovalUpdated`(GUI/vscode 通过 `/v1/state/events` SSE 实时收到审批通知)——契约 `contracts/state-sync-events.json` 新增 `approval_updated`,脚本重新生成三端类型

**验证**:approval.rs 3 测试 + evolution_loop 集成测试(RequireHuman 真实提交→broker 响应→批准传播),self_evolution 55 项全过。

### P1 — MCP 客户端(服务端完备/客户端为零的补齐)

**问题**:go-on 一直是 MCP 服务器(stdio/http),无客户端;agent 无法调用外部 MCP 工具服务器。

**方案**:`src/mcp/client.rs` — 双传输客户端:
- `McpStdioClient`:spawn 外部 MCP 进程,JSON-RPC over stdin/stdout,`initialize` → `tools/list` → `tools/call`,带 `init_timeout`/`request_timeout` 超时,`kill_on_drop`
- `McpHttpClient`:streamable HTTP 传输(JSON + SSE Accept),复用 reqwest
- `McpClientRegistry`:进程级连接注册表(client_id → handle)
- ACP 面:5 个 `mcp.client.*` 方法(connect/list/tools/call/disconnect),`src/acp/impl/request/mcp_client_pack.rs`
- `examples/echo_mcp.rs`:最小 MCP 服务器示例,供 stdio 客户端**真实端到端测试**(§12)

**验证**:client.rs 3 测试(含真实 stdio 端到端:连接 echo server → list_tools → call_tool)。HTTP 不可达错误路径测试。

### P1 — 记忆导出/导入快照(完全空白补齐)

**问题**:三层持久化(hot/warm/cold)已闭环,但无跨实例迁移/备份能力。

**方案**:`memory_persistence.rs`:
- `export_snapshot()` — 全 tier(hot+warm+cold)收集 → gzip NDJSON
- `import_snapshot()` — 解析并按 tier 路由(hot→hot cache;warm/cold→warm store upsert)
- ACP 面:`memory.export`(base64 编码传输)/ `memory.import`(base64 解码)

**验证**:roundtrip 测试(store+promote → export → 导入新实例 → 可检索),memory_persistence 13 项全过。

### P2 — 进化图谱观测端点(有数据无消费面)

**问题**:`EvolutionGraph` 已有 profile/degrading/promotion 方法,但零消费方。

**方案**:`evolution.graph` ACP 方法返回 profile + degrading 能力 + promotion 候选 + 全图记录(激活 `find_degrading_capabilities`/`find_candidates_for_promotion` 零调用方法)。

**验证**:编译零警告,方法接线完整。

### P2 — 多实例自动节点发现(基础设施在,缺自动注册)

**问题**:DMB 需手工 `GOON_MEMORY_PEERS` 注册 peer;Hub daemon 已有 discovery 文件机制但未联动。

**方案**:`distributed_memory_bus.rs`:
- `discover_peers_from_hub()` — 读 `HubDiscovery::default_path()` 文件,自动注册 hub endpoint 为 peer
- `configure_cluster()` — env peers 优先 + hub discovery 补充,统一启动传输
- `server_builder.rs` 启动路径改调 `configure_cluster()`

**验证**:multi-users-server 编译零警告。

## 5. 设计决策记录

1. **审批事件经 state-sync SSE 推送**而非单独轮询端点:复用 `/v1/state/events` 既有通道,三端(后端枚举/契约/GUI/vscode)自动对齐,符合 blue71 事件驱动要求
2. **MCP 客户端用 Box<McpStdioClient>** 消除 clippy 大枚举变体警告;registry 用 tokio Mutex(与既有模式一致)
3. **记忆快照 base64 传输**:JSON-RPC 天然不支持二进制,base64 保证跨传输安全;gzip NDJSON 格式与 cold tier 一致,可复用冷存储读取器
4. **approval 超时默认 10 分钟**:可配置(`with_approval_timeout`),防止无人响应时循环挂起(§14 不挂起)
5. **F-GAP-49 文档保留历史表格 + 头部状态声明**:不删历史记录,但明确当前代码无预留项(§18 文档与代码一致)
