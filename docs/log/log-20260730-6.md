## 1. `chat_phases.rs` — 缓存查询并行化

### 问题
Token cache（L843-889）和 semantic cache（L892-913）**串行执行**。token cache 查完才查 semantic cache，两者都是只读操作，无相互依赖。

### 方案
用 `tokio::join!` 将两个缓存查询并行化，结果合并后 token cache 优先：

```rust
// 之前: 顺序
let token_result = token_cache.lookup(...).await;
if miss { let semantic_result = semantic_cache.get(...); }

// 之后: 并行
let (token_result, semantic_result) = tokio::join!(
    async { token_cache.lookup(...) },
    async { semantic_cache.get(...) }
);
// 合并: token cache 优先
```

### 关键设计
- 定义局部 `TokenOutcome` / `SemanticOutcome` 结构体捕获结果
- 流式响应在 `join!` 之后统一发送（避免 `?` early-return 问题）
- `agent_attempts` 条目顺序保持与原来一致
- `cache_bypassed_for_execution` 等指标记录位置不变

## 2. `memory_persistence.rs` — LRU O(n) → O(1)

### 问题
`HotCache` 使用 `Vec<String> lru_order`：
- `get()`: `.iter().position(|x| x == id)` — **O(n)** 扫描
- `insert()`: `.iter().position(|x| x == &id)` — **O(n)** 扫描
- `remove()`: `Vec::remove(pos)` — **O(n)** 移位

### 方案
用 `indexmap::IndexSet<String>` 替换 `Vec<String>`（`indexmap` 已是项目依赖）：

| 操作 | 之前(O(n)) | 之后(O(1)) |
|------|-----------|-----------|
| 查找位置 | `.iter().position()` | `shift_remove()`（哈希查找）|
| 删除 | `.remove(pos)` 后移 | `shift_remove(id)` 哈希删除 |
| 尾部插入 | `.push(id.to_string())` | `.insert(id.to_string())` |
| 取首元素 | `.first()` | `.first()`（IndexSet 保留插入顺序） |

### 收益
每次 `get()` / `insert()` / `remove()` 从 O(n) 降为 O(1)，max_entries=2048 时预期加速 ~1000×。

## 3. `semantic_cache.rs` — Bigram 预计算

### 问题
每次 `get()` 对候选条目计算 Jaccard 相似度时，重新为双向字符串分配：
```
let a_bigrams: Vec<&[u8]> = a.as_bytes().windows(2).collect();
let b_bigrams: Vec<&[u8]> = b.as_bytes().windows(2).collect();
let set_a: HashSet<&[u8]> = ...;
let set_b: HashSet<&[u8]> = ...;
```
对 `n` 个候选条目，做 `2n` 次 bigram 构建。

### 方案
在 `put()` 时预计算并缓存 Bigram 集合，`get()` 时仅计算查询字符串的 bigram：

| 操作 | 之前 | 之后 |
|------|------|------|
| `put()`: 存储 | 只存 `request_text` | 额外存 `bigram_set: Option<HashSet<Vec<u8>>>` |
| `get()`: 精确命中 | hash 比较 | hash 比较(不变) |
| `get()`: 语义匹配 | 双向 bigram + Jaccard | 仅查询字符串 bigram + 预计算集合 Jaccard |

### 收益
对 `n` 个候选条目的语义匹配：`2n` 次 bigram 构建 → `n+1` 次（只有查询字符串在每次 `get()` 构建一次）。
