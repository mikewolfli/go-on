## 已执行的优化

### ✅ O1: `init_intel_hub()` + `init_intel_voters()` 合并为 `init_intelligence_hub()` (G3)

**问题**: 两个函数必须依次调用 (`init_intel_hub()` 先, `init_intel_voters()` 后)，增加了调用复杂度。且 `init_intel_hub_with_addrs()` 的 `DEFAULT_*_ADDRESS` 常量在合并后完全无用。

**修改**:
- `src/intelligence/hub.rs`: 创建 `init_intelligence_hub(enable_delphi_debate, capability_bus)` 单入口函数
- `src/intelligence/hub.rs`: 删除旧的 `init_intel_hub()`、`init_intel_hub_with_addrs()`、`init_intel_voters()` 函数
- `src/intelligence/hub.rs`: 删除无用的 `DEFAULT_LOCAL_AGENT_ADDRESS`、`DEFAULT_CAPABILITY_BUS_ADDRESS` 常量
- `src/acp/impl/runtime/server_builder.rs`: 更新为单调用
- `src/intelligence/voter_impls.rs`: 更新文档注释
- `src/governance/rationalization.rs`: 更新文档注释

**节省**: 减少40行重复代码，消除2个dead_code警告

### ✅ O2: `protocol::acp_methods` → `acp::method_names` (Y5)

**问题**: ACP方法名常量定义在 `protocol::acp_methods` 中，但这是ACP专属常量，放在protocol层造成模块划分混乱。

**修改**:
- `src/acp/method_names.rs`: 新建文件 (内容从 `protocol::acp_methods` 迁移)
- `src/acp/mod.rs`: 添加 `pub mod method_names;`
- `src/protocol/mod.rs`: 删除 `pub mod acp_methods;`
- `src/protocol/acp_methods.rs`: 删除
- `src/acp/impl/request/governance_handlers/governance_pack.rs`: 更新引用

**节省**: 模块归属更清晰，protocol模块减少1个冗余子模块

### ✅ O3: ContinuousLearningCenter 早期创建消除 (Y1)

**问题**: `run()` 中创建了完整的 `ContinuousLearningCenter` 结构体（包含CenterState分配、Mutex初始化），但只使用其中的 `agent_handle()`。中心体在 `run()` 结束后被丢弃，而真正的 review loop 在 `CapabilityBus.continuous_learning` 中运行。这造成了浪费和混淆。

**修改**:
- `src/main/mod.rs`: 用直接创建 `AgentInjector` (`Arc<Mutex<Option<Arc<dyn Agent>>>>`) 替换 `ContinuousLearningCenter::new()`
- `src/main/mod.rs`: 删除 `ContinuousLearningCenter` 和 `ContinuousLearningConfig` 的导入

**节省**: 避免不必要的 `CenterState` 分配 (~2KB 内存 + 初始化时间)
