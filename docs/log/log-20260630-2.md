## 主要架构改进

### 1. ChatPipeline 状态机接入

之前：`process_chat_request` 包含 4 个阶段的内联编排，每个阶段 ~15 行 OTel span 样板代码。
之后：调用 `ChatPipeline::run()` 统一管理 span 创建/结束、阶段执行、缓存提前退出、阶段定时。

### 2. UnifiedSessionManager 集成

新增 `session_manager` 模块，集成 `SessionContextManager`（语义评分）和 `SessionCompressor`（Token 压缩）：
- `Contextual`：小规模会话使用语义评分
- `Compressive`：大规模会话使用 Token 预算压缩
- `Adaptive`：自适应策略（默认）

### 3. 工具特征增强

在 `Tool` trait 中添加 `description()` 和 `input_schema()` 方法，使 LLM 能通过原生函数调用获取工具参数模式，消除 40+ 工具的空模式问题。

### 4. SSE 错误处理修复

将原始的裸 `event: error` 发送改为 `event: done` + `{"done": true, "error": ..., "response": ""}`，确保 GUI 能将错误显示为"完成但出错"而非"流式错误"。

### ✅ 已修复: execute_loop 同步/异步重复

提取共享的 `IterationAction` 枚举 + `handle_iteration()` 函数，消除 ~70 行重复的 observe/match 逻辑。
两个函数现在仅在 Act 阶段执行调用不同（~10 行差异）。

### ✅ 已修复: ToolRecommender 接入执行路径

- `think()` 函数新增 `recommender: Option<&ToolRecommender>` 参数
- 三阶段策略：推荐器 → 关键词匹配 → 重试次数轮询
- `execute_loop()` 和 `execute_loop_async()` 传递推荐器并在工具执行后调用 `record_usage()`
- 所有现有调用点更新为传递 `None`（向后兼容）

### ✅ 已完成分析: OnceLock 迁移计划

完成 58 个 `OnceLock` 实例的全量分析：
- **17 个** 合法单例（保留）- HTTP 客户端、缓冲区池、静态配置
- **37 个** 可变全局状态（待迁移到 `AcpServer`）
- **2 个** 死代码重复（待删除）
- **2 个** 测试专用（排除）

建议四阶段迁移计划：
1. **Phase 1（1-2天）**：迁移原子标志、只写一次引用、无状态注册表（~10 项）
2. **Phase 2（3-5天）**：迁移到已存在的 `AcpServer` 子结构（~15 项）
3. **Phase 3（5-7天）**：迁移深层嵌入的有状态映射（~8 项）
4. **Phase 4（1天）**：清理死代码重复 + 合并 GUI HTTP 客户端

关键观察：
- 大多数 Category-2 项已被访问 `server: &AcpServer` 的函数使用
- `AcpServer` 是自然的迁移目标
- 37 个可变静态变量意味着测试无法真正并行运行
