## 10. 🟡 模块架构交替状态 — `planner_executor`

| 文件 | 问题 |
|------|------|
| `src/orchestration/planner_executor/mod.rs` | 模块标记 `#[deprecated]`，但仍导出 `PlanStep`、`ExecutionPlan`、`PlannerExecutorConfig` |
| `src/orchestration/planner_executor/execution.rs` | `Executor` 标记 `#[deprecated]`，但仍在内部测试中使用 |
| `src/orchestration/brain_loop/plan_construction.rs` | 依赖 `planner_executor::ExecutionPlan` 和 `PlanStep` |

**分析**:
- `planner_executor/mod.rs` 的 `#[deprecated]` re-export 了 `Planner`、`TaskComplexity`、`DagMetrics` 到 `brain_loop::plan_construction`
- 但 `ExecutionPlan` 和 `PlanStep` 类型本身未被标记 deprecated
- `brain_loop::plan_construction::Planner::plan()` 返回 `ExecutionPlan`，而 `ExecutionPlan` 定义在 `planner_executor` 中
- 这创建了循环依赖: brain_loop 依赖 planner_executor 的类型，但 planner_executor 重导出 brain_loop 的类型

**原则违反**: #21（禁止迁移幻觉 — 新旧共存且互相引用）

**处理建议**:
1. 将 `PlanStep` 和 `ExecutionPlan` 类型移至独立的共享模块（如 `orchestration/types.rs`）
2. 或者将这两个类型直接移到 `brain_loop::plan_construction` 中
3. 将 `planner_executor/mod.rs` 的过期 re-export 改为直接使用新位置
4. 待所有引用更新后，删除 `planner_executor/execution.rs` 中的 deprecated `Executor`

## 11. 🟡 重复类型定义 — Message 类型

**处理建议**: 两个模块功能互补，且已按关注点分离（压缩 vs 语义保留）。不合并，但应确保无重叠的 default 值（`DEFAULT_MAX_MESSAGES: 1000` vs `ContextWindowBudget.max_messages: 1000` — 正好相同，无冲突）。✅ 不需要修改。
