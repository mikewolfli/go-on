## Zed Comparison Findings

### 1. SSE Streaming Token Extraction (`src/agents/mod.rs`)

**go-on approach:** Token protocol via `StreamingSender` (`mpsc::Sender<String>`) with sentinel-prefixed strings:
- `__thinking__<text>` — reasoning content
- `__tool_call__:<name>:<json>` — tool calls

**Zed approach:** Typed `LanguageModelCompletionEvent` enum with structured variants.

#### Critical Issue: Multi-chunk Tool Call Accumulation

**go-on bug:** `extract_all_tokens()` requires `name` AND `arguments` in the same SSE chunk. OpenAI-compatible APIs stream tool calls across multiple events:

1. `{"delta":{"tool_calls":[{"index":0,"id":"call_1","function":{"name":"search"}}]}}`
2. `{"delta":{"tool_calls":[{"index":0,"function":{"arguments":"{\"q\":"}}]}}`  
3. `{"delta":{"tool_calls":[{"index":0,"function":{"arguments":"\"test\"}"}}]}}`

go-on **drops all of these** because neither chunk has both fields.

**Zed fix:** Maintains a `HashMap<usize, RawToolCall>` that accumulates `id`, `name`, `arguments` across chunks by `index`.

#### Missing: `fix_streamed_json` for Tool Call Arguments

Partial JSON like `{"q":` is not valid JSON. Zed uses `fix_streamed_json()` + `partial_json_fixer` to repair trailing escapes and produce parseable prefixes.

#### Missing: `finish_reason` Handling

Zed inspects `choice.finish_reason` (`"stop"`, `"length"`, `"tool_calls"`) and emits appropriate events. go-on completely ignores `finish_reason`.

#### Missing: Usage Token Extraction

Zed emits `UsageUpdate(TokenUsage)` events. go-on ignores the `usage` field in SSE responses.

#### Fixes Applied

1. **`extract_all_tokens` → added tool call accumulator** (HashMap-based, index-keyed)
2. **Added `strip_trailing_incomplete_escape` for partial JSON repair**
3. **Added `finish_reason` extraction and forwarding**
4. **Added `usage` field extraction**

### 2. Copilot Token Resolution (`src/agents/copilot.rs` vs `src/acp/impl/request/runtime_pack.rs`)

**Issue:** Token resolution logic is duplicated. `copilot.rs` uses `resolve_secret()` (with secret pooling), while `runtime_pack.rs`'s `resolve_copilot_github_token()` manually checks env vars and keyring, bypassing the secret pool.

**Zed difference:** Zed reads tokens from `auth.db` (SQLite, Copilot SDK's native storage), env vars, and JSON files. go-on only checks env vars + keyring.

**Fix:** Added `GH_COPILOT_TOKEN` to env var search order (matching Zed's priority).

---

### 3. System Prompt Assembly (`src/agents/mod.rs` vs Zed)

**go-on:** Static `principles_to_text()` with hardcoded preamble.
**Zed:** Dynamic system prompt with project context (files, diagnostics, git state).

**Improvement deferred:** Requires larger architectural change to add per-request context assembly. Logged for future round.

### 4. Tool Definition Formatting

**go-on:** Tools passed as opaque `Value` through options HashMap.
**Zed:** Typed `ToolDefinition` structs.

**Improvement deferred:** Adding `ToolDefinition` struct and `fn supports_tool_injection()` to Agent trait would improve type safety. Logged for future round.

## Round 2 Fixes Applied

### Fix 4: Tool Call Accumulator — Global static → Thread-local (HIGH)

**File:** `src/agents/mod.rs`

Changed `TOOL_CALL_ACC` from a global `static Mutex` to `thread_local! RefCell`. The global static would cause data races when multiple chat streams run concurrently on different threads — tool call chunks from stream A could be mixed with stream B. Each tokio worker thread now gets its own accumulator instance.

### Fix 5: Copilot Token Resolution — Keyring-only path (MEDIUM)

**File:** `src/acp/impl/request/runtime_pack.rs`

`resolve_copilot_github_token()` now only checks keyring accounts (`github_copilot_token`, `copilot_api_key`), skipping environment variables. The `copilot.rs` agent already handles env vars via `resolve_secret()` with full secret pooling. This eliminates the divergent resolution path.

### Fix 6: `build_thinking_token` Dead Parameter Cleanup (LOW)

**File:** `src/orchestration/autonomy_runtime.rs`, `src/agents/mod.rs`

Removed the unused `content: Option<&str>` parameter from `build_thinking_token()` — it was always called with `None`. Updated all 3 call sites and the test.
