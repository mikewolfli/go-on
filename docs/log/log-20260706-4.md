#### 文档化的非问题

以下项经审查确认为设计中不可避免的折衷:

| 项 | 说明 |
|----|------|
| `response.clone()` 在 `run_agent_with_tools` | Agent::chat() 接收 `Vec<Message>` by value，同时需要response作为返回值。一个clone是API设计约束。对于1-2K典型响应，开销可忽略 |
| `messages.clone()` 在 agent/followup 两次clone | Agent trait设计为 `Vec<Message>` by value，两次clone是必需的。`Rc<[Message]>` 或 `Arc<[Message]>` 可优化但需改变trait签名 |
| session序列化每轮写入 | serde_json对50条消息的序列化延迟 < 100μs，`tokio::fs::write` 异步执行 |
| `ToolRegistry::new()` 600行注册 | 抽取配置文件的收益有限，注册链清晰且只在启动时执行一次 |
| `run_with_fallback` sync/async并存 | sync版本仍有同步调用者，移除会破坏API |
