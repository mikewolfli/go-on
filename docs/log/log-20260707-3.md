## 第 2 轮修复 (本轮新增)

### 架构级改进

#### 🔥 1. Governance gate 动态工具注册 (消除手动同步)

**问题**: `governance::status::tool_category()` 和 `known_tool_names()` 包含硬编码工具名列表，必须手动与 `ToolRegistry::new()` 保持同步。新增工具若遗漏更新，会被 governance gate 拒绝为"未知工具"。

**解决方案**: 
- 在 `governance::status.rs` 添加 `GOVERNANCE_TOOL_NAMES: OnceLock<Mutex<BTreeSet<&'static str>>>` 全局动态注册表
- 公开 `pub fn register_tool(name: &'static str)` 函数
- 在 `ToolRegistry::register_with_profile()` 中自动调用 `governance::status::register_tool(name)` — 每注册一个工具，自动同步到 governance gate
- `do_quick_check()` 新增 fallback 路径：静态 `tool_category()` 未匹配时，查动态注册表；已注册则允许（保守放行），未注册则拒绝（fail-closed）
- `known_tool_names()` 自动合并动态注册的工具名

**收益**: 零维护成本。新增工具只需注册到 ToolRegistry，governance 自动认可。

#### 🔥 2. 渐进式工具结果流式输出 (对标 ZED Chat)

**问题**: 原实现使用 `join_all` 等待所有工具完成才一次性显示结果。即使 `read_file` 在 2ms 内完成，用户也要等所有慢工具（如 `cargo_test` 耗时 30s）完成才能看到结果。

**解决方案**: 
- 用 `FuturesUnordered` 替换 `join_all`
- 每个工具完成立即显示结果，不必等所有工具完成
- 匹配 ZED Chat 的渐进式结果流式输出模式

**收益**: 用户交互体验大幅提升 — 快工具的结果即时可见，而非等待所有工具完成。

#### 🔥 3. 工具并发执行限流 (防止资源耗尽)

**问题**: 当 Agent 发出 50+ 并行工具调用时，无并发限制。50 个 `shell_exec` 或 `http_request` 同时执行会耗尽系统资源。

**解决方案**: 
- 添加 `MAX_CONCURRENT_TOOLS = 10` 常量
- 使用 `tokio::sync::Semaphore` 限制并发工具执行数
- I/O 密集型工具（read_file, search_files）受益于有限并行，CPU 密集型工具被自动限流

**收益**: 防止资源耗尽，保证系统稳定性。

#### 4. 自动压缩提示优化

**问题**: 当对话达到 30 条消息阈值时，提示 `/compact`。但到 60+ 条消息时，提示信息不够醒目。

**解决方案**: 区分两级阈值：
- 30 条：温和提示 (💡)
- 60 条：强烈警告 (⚠️) + 更明确的提示文字

**收益**: 用户在对话过长时获得更清晰的引导。
