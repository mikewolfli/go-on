### 关键性能改进说明

#### 改动1: 消除chat热路径的 `block_on`

**之前**:
```
execute_simple_tool (async)
  └─ spawn_blocking                          # ① 阻塞线程
       └─ run_with_fallback (sync)
            ├─ ReadFileTool.run (sync)        # ✅ 正确在blocking线程执行
            ├─ WriteFileTool.run (sync)       # ✅ 正确在blocking线程执行
            └─ SkillExecuteTool.run (sync)    # ❌ block_on专用runtime
                 └─ skill_runtime().block_on( # ❌ 创建新runtime
                      run_async(input))
```

**之后**:
```
execute_simple_tool (async)
  └─ run_with_fallback_async (async)
       ├─ ReadFileTool.run_async              # → spawn_blocking (自动)
       ├─ WriteFileTool.run_async             # → spawn_blocking (自动)
       └─ SkillExecuteTool.run_async          # → 真正异步, 无block_on
```

**效果**: 消除三重嵌套, 同步工具通过`Tool::run_async`默认实现自动spawn_blocking, 异步工具直接异步执行.

#### 改动2: `native.rs` Schema自动生成

**之前**: 40+工具的OpenAI-compatible JSON Schema全部手写(600+行), 新增工具需同步修改native.rs

**之后**: 从 `tool.input_schema()` + `tool.description()` 自动生成, 0行手写schema

**效果**: 代码量减少97%, 新增工具自动获得正确schema

#### 改动3: CLI Chat技能初始化

**之前**: CLI chat (`go-on -a`) 不初始化SkillRegistry, `/skills` 命令返回"no skills"

**之后**: CLI chat启动时自动扫描 `~/.agents/skills/` 并注册技能, 全功能可用
