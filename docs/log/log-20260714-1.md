## 1. `DispatchOutput` 统一输出架构

### 新增文件

| 文件 | 说明 |
|------|------|
| `src/acp/impl/request/dispatch.rs` | `DispatchOutput` 枚举 + `dispatch_to_client` 统一分发函数 |

### DispatchOutput 枚举定义

```rust
pub enum DispatchOutput {
    Json(Value),                                    // 标准 JSON-RPC 成功
    Error { code: i32, message: String, data: Option<Value> }, // JSON-RPC 错误(含精确码)
    Stream { receiver: mpsc::Receiver<StreamFrame> }, // 流式输出(chat)
    Text(String),                                   // text/plain 响应
    Checkpoint(CheckpointResult),                   // 多分支 checkpoint
    Silent,                                         // 无响应(notification)
}
```

### dispatch_to_client 统一分发函数

| Variant | 行为 |
|---------|------|
| `Json(v)` | `write_response()` → JSON-RPC 成功 |
| `Error { code, msg, data }` | `write_response()` → JSON-RPC 错误(含精确码) |
| `Stream { rx }` | 从 channel 接收 `StreamFrame`，按 event 类型转发为 notification / result / error |
| `Text(s)` | `__text_plain__` sentinel 包装 |
| `Checkpoint(Created\|Deleted)` | 自动解包为标准 JSON-RPC 格式 |
| `Silent` | 无操作 |

## 3. Chat handler → `DispatchOutput::Stream` 迁移

### 改造前

```
protocol_pack::handle_chat(server, params, request_id, trace) → Result<()>
  └─ session::handle_chat
       └─ StreamObserver::jsonrpc(id) — 通过 send_notification 发事件
       └─ send_result(server, id, final) — 最终 JSON-RPC 响应
```

### 改造后

```
protocol_pack::handle_chat(server, params, trace) → Result<DispatchOutput>
  └─ 创建 (tx, rx) = mpsc::channel::<StreamFrame>(256)
  └─ StreamObserver::sse(tx) — 通过 channel 发事件
  └─ session::handle_chat(server, None, params, ...) — id=None 跳过 send_result
  └─ 返回 DispatchOutput::Stream { receiver: rx }
       ↓
dispatch_to_client 处理 Stream:
  ├─ "chunk" → send_notification("chat.stream.chunk")
  ├─ "done" → send_notification("chat.stream.done")
  ├─ "telemetry" → send_notification("chat.stream.telemetry")
  ├─ "result" → send_result(id, final)
  └─ "error" → send_error(id, -32603, msg)
```

### 修改文件

| 文件 | 修改 |
|------|------|
| `session.rs` | 添加 `stream_observer: Option<StreamObserver>` 参数；有 SSE sender 时通过 channel 发 final result |
| `protocol_pack.rs` | `handle_chat` 返回 `Result<DispatchOutput>`，内部创建 channel + observer |
| `request.rs` | chat dispatch arm 改用 `dispatch_to_client` |
| `dispatch.rs` | 新增 `Stream` variant + drain 循环 |

## 4. 错误路径统一

### `respond()` 改进 (`io.rs`)

改造前：`Err` 路径硬编码 `-32602`，无 platform profile 注入

改造后：`Err` 路径通过 `io::send_error` → 获得 `inject_platform_profiles_if_absent`

### `dispatch_to_client::Err` 改进 (`dispatch.rs`)

改造前：`Err` 路径内联 `write_response`，无 profile 注入

改造后：`Err` 路径通过 `io::send_error` → 获得 profile 注入

### 错误码精确化

| 场景 | 改造前(硬编码) | 改造后(精确码) |
|------|---------------|---------------|
| `_` 通配(未知方法) | `-32602` | `AcpErrorCode::MethodNotFound` (`-32601`) |
| `prompts.get` 缺 id | `-32602` | `AcpErrorCode::InvalidParams` (`-32602`) |
| chat rate-limited | 特殊处理 | `-32029`（保留） |
| 其他 handler 错误 | `-32602` | `AcpErrorCode::InvalidParams` (`-32602`) |

## 5. 其他优化

### HTTP text/plain 检测链

`src/acp/impl/runtime/http.rs`：
- 新增 `write_http_text_response()` — 以 `Content-Type: text/plain` 响应
- RPC buffer 解析后检测 `result.__text_plain__` sentinel
- 命中时以 text/plain 返回，否则回退 JSON

### Silent variant 推广

- `$/cancel_request` → `DispatchOutput::silent()`（JSON-RPC notification，无需响应）
- 删除 `cancel_request_payload` 死代码

### 死代码清理

| 删除项 | 位置 | 原因 |
|--------|------|------|
| `send_result` 函数 | `chat_pack.rs` | 所有 handler 改用 DispatchOutput |
| `inject_pua_report_into_result` | `pua_pack.rs` | 仅被已删除的 send_result 调用 |
| `cancel_request_payload` | `protocol_pack.rs` | $/cancel_request 改用 Silent |
| `error_with_data` 构造器 | `dispatch.rs` | 未使用 |
| `already_exists`, `conflict`, `not_found`, `listed`, `checkpoint` 构造器 | `dispatch.rs` | 未使用 |
| `CheckpointResult::AlreadyExists/Conflict/NotFound/Listed` | `dispatch.rs` | 未使用 |
