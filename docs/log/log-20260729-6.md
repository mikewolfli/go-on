## 1. Hub SQLite 保险库持久化

### 设计

```
hub.store(key, value)
  → HashMap::insert(key, value)          # 快速缓存（主读路径）
  → INSERT OR REPLACE INTO hub_vault     # SQLite 持久化 (feature-gated)

hub.retrieve(key)
  → HashMap::get(key)                    # 快速路径
  → if miss: SQLite SELECT               # 慢路径 + 回填 HashMap

hub.list
  → HashMap keys ∪ SQLite keys           # 去重合并
```

### 变更

| 文件 | 行 | 变更 |
|------|-----|------|
| `hub/server.rs:26-27` | 新增 | `use rusqlite;` (feature-gated) |
| `hub/server.rs:38` | 新增 | `vault_path: Option<PathBuf>` 字段 |
| `hub/server.rs:58` | 修改 | 初始化 `vault_path: None` |
| `hub/server.rs:86-108` | 新增 | 启动时创建 SQLite 表 (feature-gated) |
| `hub/server.rs:162-170` | 新增 | `with_vault_path()` builder 方法 |
| `hub/server.rs:285-302` | 修改 | `hub.store` write-through 到 SQLite |
| `hub/server.rs:311-344` | 修改 | `hub.retrieve` SQLite 回退 + 回填 |
| `hub/server.rs:350-365` | 修改 | `hub.list` 合并 HashMap + SQLite 键 |

### 特性

- **零新依赖**: 复用已有的 `rusqlite` (feature-gated)
- **向后兼容**: `vault_path: None` 默认，现有调用者无需改动
- **HashMap 优先**: 读写都走 HashMap，SQLite 仅用于持久化
- **写穿透**: 每次 store 同时写入 HashMap 和 SQLite

## 2. Python SDK tools/list + tools/call

### 新增类型

| 类型 | 字段 |
|------|------|
| `ToolInfo` | name, description, input_schema |
| `ToolCallRequest` | tool_name, arguments, session_id |
| `ToolCallResult` | success, output, error, duration_ms |

### 新增方法

| 方法 | RPC | 返回 |
|------|-----|------|
| `tools_list()` | `tools/list` | `list[ToolInfo]` |
| `tools_call(req)` | `tools/call` | `ToolCallResult` |

### 示例输出 (basic_usage.py)

```python
async with GoOnClient() as client:
    tools = await client.tools_list()
    print(f"Available tools: {len(tools)}")
    
    result = await client.tools_call(
        ToolCallRequest(tool_name="read_file", arguments={"path": "test.txt"})
    )
    print(f"Success: {result.success}")
```

## 4. mTLS 测试 (15 个测试)

### 新增依赖

```toml
rcgen = { version = "0.13", features = ["pem"] }  # dev-dependencies
```

### 测试结构

| 组 | 测试数 | 覆盖 |
|----|--------|------|
| `build_server_config` | 7 | 有效证书、空链、无效PEM、缺失CA、缺失Key、密钥不匹配 |
| `build_ca_store_with_cn_check` | 3 | CN 允许、CN 拒绝、空列表跳过 |
| Builder 方法 | 4 | with_client_cert true/false、with_allowed_cns |
| `accept` | 1 | TCP 连接 + 非 TLS 对端 → HandshakeFailed |

### 关键技术决策

- 使用 `rcgen` 在测试时内联生成自签名证书，无需外部文件
- TLS 握手测试使用随机端口 `TcpListener`，避免端口冲突
- Builder 方法测试使用 `#[cfg(feature = "multi-users-server")]` 匹配生产代码
