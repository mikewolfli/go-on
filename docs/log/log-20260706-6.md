## 问题1: Chat 系统缺少初始 system message

**位置**: `src/cli/chat.rs` `run_agent_with_tools()` L739-1041

**问题**: Agent 收到第一条用户消息时，没有预先注入系统级指令。`build_cli_principles()` 只在每次 agent.chat() 调用时注入工具列表，但 agent 的实现（如 OpenAI）不一定会将 principles 视为 system 消息。这导致：
- Agent 可能在不了解工具协议时就开始对话
- 首条消息的效率低下，agent 需要"猜测"自身能力

**修复**: 在 `run_terminal_chat()` 启动时向 `messages` 注入一个 system 角色的初始消息，完整描述工具调用协议、可用能力列表。

## 问题2: Chat 系统的 token 估算不精确

**位置**: `src/cli/chat.rs` L744-745

**问题**: `estimated_prompt_tokens = prompt_chars / 4` 是粗略估算，与实际 LLM tokenizer 有 30-50% 误差。影响 `/cost` 和 `/context` 命令的准确性。

**修复**: 添加基于 tiktoken 风格的近似 token 计算（按中英文混合场景优化），并缓存计算结果。

## 问题5: SkillReloadTool 在持有写锁时执行磁盘 I/O

**位置**: `src/orchestration/tool/mod.rs` `SkillReloadTool::run()` L2584-2624

**问题**: 持有 `registry.write()` 锁的同时执行 `discover_and_register_local_skills()`, 该函数执行磁盘扫描和文件读取。这会导致：
- 锁持有时间过长
- 如果磁盘 I/O 慢，所有读操作都被阻塞

**修复**: 先在锁外扫描磁盘获取结果，再获取写锁注册。
