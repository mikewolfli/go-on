## 1. 三端 SDK OpenAI-compat 契约补齐(新增方法 + 测试)

**发现**:后端 `src/acp/impl/runtime/openai_compat.rs` 暴露 4 个 OpenAI 兼容 HTTP 端点(`/v1/chat/completions`、`/v1/responses`、`/v1/responses/{id}`、`/v1/models`),但**三端 SDK 均未暴露**——这是契约面缺口。本轮三端统一补齐 4 个方法,请求体按 OpenAI wire format 原样转发:

| SDK | 方法 | 端点 |
|-----|------|------|
| Python | `chat_completions` / `responses_create` / `responses_get` / `models_list` | POST /v1/chat/completions、POST /v1/responses、GET /v1/responses/{id}、GET /v1/models |
| TypeScript | `chatCompletions` / `responsesCreate` / `responsesGet` / `modelsList` + 私有 `httpJson` helper | 同上 |
| Rust | `chat_completions` / `responses_create` / `responses_get` / `models_list` + 私有 `http_json` helper | 同上 |

**测试扩展**(全部实测通过):

- **Python SDK 32/32**(24→32,+8):4 个 openai 契约(session 原有 11 项之上)+ `session/resume`、`session/config/set`、`session/close` 补齐。openai 测试用 MockTransport 断言**路径 + 原样 body**;GET 请求无 body,共享 mock handler 加 `request.content` 空判断
- **TS SDK 31/31**(24→31,+7):`chatCompletions`/`responsesCreate`/`responsesGet`/`modelsList` + `session/resume`/`session/config/set`/`session/close`,mock fetch 断言 URL + method + body
- **Rust SDK 14/14**(10→14,+4):Rust SDK 无 HTTP mock 设施,新建**进程内 TCP 捕获服务器**(`tokio::net::TcpListener` 读请求行+body,回发 canned OpenAI 响应),验证**真实 wire 契约**:method、path、verbatim body 转发。这是 §12 要求的"真实行为验证",非 in-memory 构造
