## 发现并修复的问题

### 🔧 Fix 1: Chat ANSI重渲染行数计算错误 (严重 🔴)
**文件**: `src/cli/chat.rs:929-941`  
**问题**: `run_agent_with_tools()` 中markdown重渲染使用 `response.lines().count()` 计算需要清除的行数，但ANSI渲染后的输出行数可能不同（markdown渲染可能增加/减少行数）。`\x1B[F\x1B[K`（光标上移+清行）序列因此可能清除过多或过少行，导致视觉残留或行错位。  
**修复**: 使用 `rendered.lines().count()` 替代 `response.lines().count()`，确保清除的行数匹配实际ANSI输出行数。  
**影响**: 消除每次AI响应后的视觉闪烁和行错位问题，达到ZED CHAT级别流畅渲染。

### 🔧 Fix 2: Follow-up ANSI重渲染缺失+行数错误 (严重 🔴)
**文件**: `src/cli/chat.rs:1092-1115`  
**问题**: Follow-up响应完全没有ANSI重渲染（与主响应不同），导致follow-up中的markdown代码块、表格等完全没有格式化。并且response变量在ANS I渲染前就已赋值，导致渲染后的内容不生效。  
**修复**: 
1. 在 `response = followup_response` 赋值前执行ANS I渲染
2. 将渲染后的内容赋值给 `rendered_final` 然后给 `response`
3. 使用 `rendered.lines().count()` 而非原始行数  
**影响**: Follow-up响应现在获得与主响应一致的markdown格式化，视觉体验完整闭环。

### 🔧 Fix 3: /review 命令 diff 二次迭代 (中 🟡)
**文件**: `src/cli/chat.rs:680-696`  
**问题**: `display_diff(&detailed, Some(60))` 遍历60行并输出，然后 `detailed.lines().count()` **两次** 遍历大型diff的全部行（lines 690和694）。对大型diff（数千行）造成不必要的2×O(n)开销。  
**修复**: 预先计算 `let total_lines = detailed.lines().count()` 存储到变量，后续两处引用该变量。  
**影响**: 消除大型diff场景下的重复遍历（从3次reduce到1次），review命令响应速度提升。

### 🔧 Fix 4: 会话文件路径归入.goon/目录 (中 🟡)
**文件**: `src/cli/chat.rs:45,284`  
**问题**: `SESSION_FILE` 硬编码为 `".goon-chat-session.json"` 在当前工作目录，与项目其他元数据文件（在`.goon/`中）不一致，且可能造成根目录文件杂乱。  
**修复**: 
1. `SESSION_FILE` 改为 `".goon/chat-session.json"`
2. 会话初始化时自动创建 `.goon/` 目录  
**影响**: 会话文件统一归入`.goon/`，与项目其他元数据文件一致。

### 🔧 Fix 5: ToolRegistry::new() 巨型函数拆分 (中 🟡)
**文件**: `src/orchestration/tool/mod.rs:184-1398`  
**问题**: ToolRegistry::new() 函数超过1200行，注册了50+工具。单一巨型函数导致编译器优化困难、增量编译时间长、维护极为困难。  
**修复**: 将工具注册拆分为按功能领域分组的8个辅助方法：
- `register_core_tools()` — 6个核心工具
- `register_extended_filesystem_tools()` — 20+个扩展工具  
- `register_feature_gated_document_tools()` — 13个特性门控文档工具
- `register_feature_gated_cad_tools()` — 17个特性门控CAD工具
- `register_network_and_time_tools()` — 3个网络工具
- `register_data_tools()` — 8个数据序列化+4个图像工具
- `register_skill_tools()` — 4个技能工具
- `register_backward_compat_aliases()` — 7个别名注册
主 `new()` 方法仅调用这些方法。
**影响**: 每个子函数<100行，编译器更易优化、减少增量编译时间、提高代码可维护性。行为完全不变。

### 🔧 Fix 6: unused `_tool_args_str` 清理 (低 🟢)
**文件**: `src/cli/chat.rs`  
**问题**: `for (tool_name, _tool_args_str, result, elapsed) in results` 中 `_tool_args_str` 虽以 `_` 前缀抑制警告，但完全不需要匹配该字段。  
**修复**: 改为 `for (tool_name, _, result, elapsed) in results`。  
**影响**: 代码更简洁。
