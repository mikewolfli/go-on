## 新发现的问题

### 🔴 Issue 1: `known_tool_names()` 缺失20+工具名

**文件**: `go-on/src/governance/status.rs`

`known_tool_names()` 是手动维护的工具名称列表，与 `tool_category()` 不同步。从 `tool_category()` 但缺失于 `known_tool_names()` 的工具：

| 类别 | 缺失的工具 |
|------|-----------|
| 读工具 | `docker_logs`, `code_metrics`, `encode_decode`, `file_watch`, `hash_file`, `lint_run`, `random_token`, `search_packages`, `security_scan`, `template_render`, `uuid_gen` |
| 写工具 | **`edit_file`**, `apply_code_action`, `dependency_add`, `format_code` |
| Shell/执行 | `build_run`, `docker_build`, `docker_compose`, `docker_exec`, `docker_push`, `spawn_agent` |

最严重的是 **`edit_file`** 缺失——这是LLM编码工作流中的主要写入工具。

**状态**: ✅ 已修复（已添加缺失的工具名）

### 🔴 Issue 2: `compute_risk_score()` 使用 `contains()` 导致误报

**文件**: `go-on/src/orchestration/mode.rs:540-583`

`compute_risk_score()` 使用 `lower.contains(kw)` 检查危险关键词，这会产生误报：

| 输入 | 匹配关键词 | 是否误报 |
|------|-----------|---------|
| "`undelete` file" | `delete` | ✅ 是（"undelete"包含"delete"） |
| "`dropdown` menu" | `drop` | ✅ 是（"dropdown"包含"drop"） |
| "a`rm` the system" | `rm` | ✅ 是（"arm"包含"rm"） |

对比发现：
- **GUI版** `types.rs:compute_risk_score()` 已正确使用 `word_boundary_match()`
- **`is_high_risk_operation()`** 也正确使用 `word_boundary_match()`
- **仅 `mode.rs:compute_risk_score()`** 存在此问题

该函数是 SafeGuard 模式风险评估的核心——误报会导致用户不必要的中断。

**状态**: ✅ 已修复（改用 `word_boundary_match()` 消除误报）

### 🟡 Issue 4: `with_db_path` 在 `backend-sqlite` 关闭时静默忽略持久化

**文件**: `go-on/src/governance/approval_engine.rs:317`

```rust
pub fn with_db_path(mut self, db_path: String) -> Self {
    self.db_path = Some(db_path.clone());
    #[cfg(feature = "backend-sqlite")]
    { Self::init_sqlite(&db_path); }
    self
}
```

当 `backend-sqlite` 未启用时，`db_path` 被设为 `Some(...)` 但 SQLite 初始化被跳过。任何检查 `self.db_path.is_some()` 来确定持久化是否激活的代码都会得到误报。

**状态**: ✅ 已修复（在 `cfg(not(feature = "backend-sqlite"))` 分支添加警告日志，仅在 sqlite 启用时设置 `db_path`）
