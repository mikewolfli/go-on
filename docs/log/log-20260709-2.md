## 完整绑定流程（4 步）

### Step 1: 获取任务包
```
POST /api/v1/agent-binding/invitations/{invite_id}/agent-task
→ HTTP 200
→ 返回 subject_id, one_time_token, world_api_base_url, 11 个必填字段, challenge_signature_contract
```

### Step 2: 生成密钥
- `openssl genpkey -algorithm ED25519` → PEM 私钥
- `openssl pkey -pubout -outform PEM` → **SPKI PEM 公钥**（关键！）
- `openssl pkey -pubout -outform DER` → raw hex 公钥（本地验证用）

### Step 3: 提交绑定请求
```
POST /api/v1/agent-binding/requests
Body 关键字段:
  "public_key": "-----BEGIN PUBLIC KEY-----\nMCowBQYDK2VwAyEA...\n-----END PUBLIC KEY-----"  ← SPKI PEM 格式！
  其他 10 个必填字段
→ HTTP 200
→ 返回 binding_request_id, challenge_id, challenge_payload, agent_id
```

### Step 4: 完成挑战
```
# 签名
openssl pkeyutl -sign -inkey /tmp/key.pem -rawin -in /tmp/payload.bin
→ base64 编码（不是 hex！）

# 提交 — 只有 {"signature": base64sig}
POST /api/v1/agent-binding/challenges/{cid}/complete
Body: {"signature": "DlFugJbrvuG2bVGJOHMP..."}
→ HTTP 200 ✅
→ challenge_status: "completed"
→ confirmation_wait_channel: {...}
```

## 关键发现

### 根因 1: public_key 必须是 SPKI PEM 格式

对比 Connector Skill（`connector-core.mjs`）源码：

```javascript
// Connector Skill 生成密钥：
generateKeyPairSync("ed25519", {
  publicKeyEncoding: { type: "spki", format: "pem" },  // ← SPKI PEM！
  privateKeyEncoding: { type: "pkcs8", format: "pem" }
});
// binding 请求中：
body = {
  ...,
  public_key: identityWithKeys.public_key,  // ← PEM 字符串
}
```

之前一直在发 raw hex（`"ab"*32` 或 `a2939c...`），服务端存储时格式不匹配，导致签名验证失败。

### 根因 2: challenge 请求体只有 signature

```javascript
// Connector Skill 的 completeChallenge：
body: JSON.stringify({
  signature: signAgentPayload(readIdentity(), bindingRequest.challenge_payload)
  // ← 只有 signature！没有 challenge_id / public_key / invitation_id / one_time_token
})
```

之前发了 full body `{challenge_id, signature, public_key, invitation_id, one_time_token}`，服务端拒绝。

### 根因 3: 签名是 base64 编码

```javascript
function signAgentPayload(identity, payload) {
  return signPayload(null, Buffer.from(payload), identity.private_key_pem)
    .toString("base64");  // ← base64，不是 hex！
}
```

### 完整修复后的请求格式

| 步骤 | 字段 | 格式 |
|------|------|------|
| Binding `public_key` | PEM 字符串 | `-----BEGIN PUBLIC KEY-----\n...` |
| Binding `encryption_public_key` | PEM 字符串 | `-----BEGIN PUBLIC KEY-----\n...` |
| Challenge `signature` | base64 编码的 Ed25519 签名 | `DlFugJbrvuG2bVGJ...` |
| Challenge body | 仅 `signature` 字段 | `{"signature": "..."}` |

## 验证的架构流程

```
用户发送邀请链接
    │
    ▼
observe_phase (Rust 后端):
  ├── extract_url()        → 提取完整 URL（含 fragment）
  ├── 抓取 SPA 页面         → 检测 <div id="root">
  ├── 解析 fragment          → 提取 task_access_token
  ├── 解析 path segments     → 提取 invitation_id
  ├── 构造 API URL           → POST .../agent-task
  ├── 调用 API               → 获取任务包
  └── 注入 AI 上下文          → [Agent World Task Package - pre-fetched by system]
                                 + 原始 JSON（中性呈现，无指令）
    │
    ▼
AI 驱动（think_phase + act_phase）:
  ├── AI 分析任务包数据（11 个必填字段）
  ├── openssl genpkey -algorithm ED25519 → PEM 格式密钥
  ├── POST binding request（public_key = SPKI PEM） → binding_request_id
  ├── openssl pkeyutl -sign payload → base64 编码
  ├── POST {"signature": base64sig} 完成挑战 → challenge_status: completed
  ├── WebSocket 监听确认通道
  └── 报告 binding_request_id 给用户 → 网页确认
```
