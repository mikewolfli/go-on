### 已完成的裁决（扫描结论，先固化）

- **双语义缓存（M2）→ 不合并**：两缓存 key 粒度是语义分界（token 缓存=完整对话的对话级重放；语义缓存=末条 user 消息的问题级复用），有效服务阈值已统一在 0.95（cache_strategy.rs 服务门）；TTL/驱逐/运维面（clear/purge/hit_ratio）各异。合并须改变热路径产品行为，非机械收敛。`共享一次 embedding` 不可行（嵌入文本不同且维度不同）。**附带发现**：token L2 全对话 key 在长对话下有陈旧答案隐患（minhash 1024-token 上限 → 长历史向量 cos≈1.0），需探针复现后独立修复（见下）。
- **shell.rs 换 runner → 留后续**：exec_common 无带超时 runner，需新增 API + 100 行敏感代码搬家（GNU timeout/kill 线程/降级顺序），行为等价要求高，无功能缺口。
- **docker/game 沙箱 → 不做**：bwrap 未 bind `/var/run/docker.sock`（沙箱内连不上 daemon），且 docker CLI 是宿主机 daemon 的薄客户端，包 bwrap 无 containment（正确隔离在治理层）；game 依赖 X11（被 `--tmpfs /tmp` 遮蔽）+ detached 长活进程（与 runner 一次性等待模型不兼容）。
- **normalize_path 合并 → 不做**：两函数 ~90% 重复但策略相反（status.rs 保留 `..` 逃逸做安全检查，code_repo_analyzer 丢弃越根 `..`），带参合并复杂度与现状打平且破坏安全契约。
