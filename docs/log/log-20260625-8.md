## 具体发现与变更

### 🔥 变更1: 删除死代码 `compose_skills()` + `ComposedSkill`

**文件**:
- `src/orchestration/skill/registry.rs` — 删除 `compose_skills()` 方法 (72行)
- `src/orchestration/skill/execution.rs` — 删除 `ComposedSkill` struct + `impl Skill` (68行)

**理由**: 全项目 `grep` 确认零外部调用。`compose_skills()` 和 `ComposedSkill` 仅在自己的定义文件中被引用，无任何 UI、CLI、RPC 端点或测试代码调用它们。这是一个"流水线式 A→B"技能组合功能，已构建但从未接线激活。

**验证**: `grep -r "compose_skills\|ComposedSkill" src/` 确认仅剩删除后的零结果。

### 🔥 变更2: 标记 Feature Flag 弃用

**文件**: `Cargo.toml`

**变更**: 为 `local-acp-sqlite` 和 `server-mcp-postgres` 添加 DEPRECATED 注释标记。

**理由**: 这两个是旧版别名的遗留 feature flags，零 `#[cfg]` 引用，仅为了向后兼容保留。已添加弃用说明，将在未来 breaking release 中移除。

### ✅ 确认: 锁效率审计通过

| 检查项 | 结果 |
|--------|------|
| `.await` 时持有 `std::sync::Mutex` | ✅ 0处 — 所有Mutex均在scoped block中，drop后才.await |
| I/O操作时持有锁 | ✅ 0处热路径 — 非关键路径(create_skill)接受此模式 |
| 嵌套锁(死锁风险) | ✅ 0处 — BrainLoop所有write_guard顺序获取 |
| Poison处理 | ✅ 全部使用 `unwrap_or_else` + `poisoned.into_inner()` |
| try_acquire非阻塞 | ✅ 生产路径只使用try_acquire, blocking版本#[cfg(test)] |

**说明**: 两项 🟡 发现(`create_skill_from_prompt` 和 `remove_prompt_skill` 在锁内做文件I/O)仅影响不频繁的操作(技能创建/删除)，不影响 per-request 执行路径。
