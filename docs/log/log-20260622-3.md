## II. 🔴 P0 — Security Critical Fixes

### Fix 1: ApplyPatchTool path traversal vulnerability
**File**: `src/orchestration/tool/mod.rs:866`

**Before**: `current_dir` used raw from payload — no sanitization
```rust
let current_dir = input.payload["directory"].as_str().unwrap_or(".");
// ... command.current_dir(current_dir)
```

**After**: Added `sanitize_path()` call
```rust
let sanitized_dir = sanitize_path(input, current_dir)?;
// ... command.current_dir(&sanitized_dir)
```

### Fix 2: InspectGitDiffTool path traversal vulnerability
**File**: `src/orchestration/tool/mod.rs:1031`

**Before**: Same issue — raw `current_dir` from payload
```rust
let current_dir = input.payload["directory"].as_str().unwrap_or(".");
// ... command.arg("diff").current_dir(current_dir)
```

**After**: Added `sanitize_path()` call
```rust
let sanitized_dir = sanitize_path(input, current_dir)?;
// ... command.arg("diff").current_dir(&sanitized_dir)
```

### Fix 3: RunTestsTool directory sanitization
**File**: `src/orchestration/tool/mod.rs`

**Before**: Raw directory from payload used directly

**After**: Uses `sanitize_path()` for directory parameter

## VI. 🧪 SKILLS System Fixes

### Fix 1: bootstrap.rs — SkillRegistry is no longer discarded
**File**: `src/core/bootstrap.rs`

**Before**: Created temporary `SkillRegistry`, ran discovery, **discarded** the result:
```rust
SkillRegistry::default().discover_and_register_local_skills(None)?;
```

**After**: Returns `SkillRegistry` from `perform_bootstrap()`:
```rust
let mut skill_registry = SkillRegistry::default();
skill_registry.discover_and_register_local_skills(None)?;
Ok(skill_registry)
```

### Fix 2: ServerBuilder — Local skills now discovered on server start
**File**: `src/acp/server.rs`

**Before**: Registered `EchoSkill` and `SkillCreatorSkill` but never called `discover_and_register_local_skills()`.

**After**: After built-in skill registration, calls `discover_and_register_local_skills(None)` to load user skills from `~/.agents/skills/`.

### Fix 3: skills-setup.sh — Step numbering, dependency checks, TOML config
**File**: `scripts/skills-setup.sh`

1. **Step numbering**: Fixed `Step 1/4` → `Step 1/5` and all subsequent steps
2. **Node.js check**: Added optional `node` command check
3. **npm check**: Added optional `npm` command check
4. **Python check**: Added optional `python3`/`python` command check
5. **Config format**: Replaced YAML example with TOML format matching Rust config:
   ```toml
   [feature]
   skills_enabled = true
   skills_import_enabled = true
   [runtime]
   skills_allowed_sources = ["github.com/my-org/*"]
   skills_require_sha256 = false
   skills_allow_floating_ref = true
   ```
6. **Bidirectional sync**: Skills from `skills-import/` are now synced to `~/.agents/skills/` so Rust discovery finds them.

## VIII. Fix: Excel Writer Error Conversion

**File**: `src/multimodal/excel_writer.rs:175`

**Before**: Attempted `rust_xlsxwriter::XlsxError::from(Box::new(e))` which doesn't compile with newer `rust_xlsxwriter` crate (no `From<Box<dyn Error>>` impl).

**After**: Uses `ExcelWriterError::CellIndexOutOfBounds(format!(...))` which is a valid variant that properly wraps the error message.

**Fix**: `src/multimodal/ppt_reader.rs` — Added explicit type annotations for `zip::write::FileOptions` (3 locations) to fix compilation with zip 2.x.
