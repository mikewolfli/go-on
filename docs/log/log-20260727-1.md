## 一、🔴 block_on 热路径违规（违反原则#23/#24）

### 1.1 SkillExecuteTool::run() — `builtin_tools.rs:1147-1151`

```rust
fn run(&self, input: &ToolInput) -> Result<ToolOutput> {
    let input = input.clone();
    let rt = skill_runtime();
    rt.block_on(skill_execute_arc().run_async(input))
}
```

**问题**: 在同步 `run()` 中创建runtime + block_on。注释已承认这是反模式，但需要同步trait实现。  
**建议**: 所有调用者应直接使用 `run_async()` 而非 `run()`。

### 1.2 LSP 工具 — `lsp.rs:375-419`（3处）

```rust
fn run_lsp_definition/references/code_action(…) {
    let rt = tokio::runtime::Runtime::new()?;
    rt.block_on(async { … })
}
```

**问题**: 3个同步函数各自创建runtime并block_on。  
**建议**: 如果这些工具从同步环境调用，可合并为一个共享runtime。

### 1.3 WebSearchTool::run() — `web_search.rs:68-75`

```rust
match tokio::runtime::Handle::try_current() {
    Ok(handle) => handle.block_on(async { … })?,
    Err(_) => { let rt = …; rt.block_on(…) }
}
```

**问题**: `handle.block_on()` 在async运行时线程上调用会阻塞线程。  
**建议**: 需改为统一使用专用的blocking runtime。

### 1.4 SpawnAgentTool::run() — `spawn_agent.rs:148-152`

```rust
let rt = tokio::runtime::Runtime::new()
    .map_err(|e| anyhow::anyhow!("failed to create temp runtime: {}", e))?;
```

**问题**: 每次调用都创建新runtime + block_on。  
**建议**: 使用共享的blocking runtime。

## 补充: 扫描方法论

1. 直接代码阅读（所有模块mod.rs + 关键源文件）
