### 4.3 Transport Trait 实施（Phase 1 + Phase 2）

**新增文件**: `src/acp/transport.rs`（181 行）

```rust
#[async_trait::async_trait]
pub(crate) trait Transport: Send + Sync {
    async fn write_json_line(&self, value: &Value) -> Result<()>;
    async fn write_sse_event(&self, _event: &str, _payload: &Value) -> Result<()> { Ok(()) }
    async fn flush(&self) -> Result<()> { Ok(()) }
}

// 三个实现
pub(crate) struct StdioTransport;        // → tokio::stdout
pub(crate) struct RpcBufferTransport;   // → Arc<Mutex<Vec<u8>>>
pub(crate) struct SseTransport;          // → TcpStream
```

**全局 Transport 分路**：
```rust
static CURRENT_TRANSPORT: OnceLock<Arc<dyn Transport>>;
// → write_json_line: ① CURRENT_TRANSPORT ② RPC_BUFFER ③ stdout
```

**接入点**：
- `run_acp_server` — 设置 `StdioTransport`
- `dispatch.rs` — HTTP RPC handler 保留 `RPC_BUFFER.scope()`
- `http.rs` — SSE handler 保留 `write_sse_event` 直接调用

**架构改进**：
| 维度 | 之前 | 之后 |
|------|------|------|
| 传输分路 | 隐式 `RPC_BUFFER` task-local | 显式 `Transport` trait + 全局分路 |
| SSE 写入 | 独立 `sse.rs` 函数 | `Transport::write_sse_event` trait 方法 |
| 扩展性 | 新增 WebSocket 需修改3个文件 | 新增 `WebSocketTransport: impl Transport` |
| 可见性 | 调用点看不到数据流 | 全局 `CURRENT_TRANSPORT` 可观测 |

**Phase 3 计划**：移除 `RPC_BUFFER`，完全通过 `Transport` trait 路由。

## 第五部分：GUI-Backend 审批流分析

```
用户发送 Edit 模式任务
  ↓
Backend autonomy_loop → emit_tool_approval_event() → SSE → GUI 显示 Approve/Deny
  ↓ (不等待，直接执行)
Backend 执行工具 → 返回结果
  ↓
GUI 用户点击 "Approve" → RPC "tool.approve" → user_approved_tools ← 下次生效
```

**结论：设计如此（非 bug）** — SSE `tool_approval` 是通知而非请求，`tool.approve` RPC 影响后续同工具调用。与 ZED 的"前端控制审批显示"设计一致。
