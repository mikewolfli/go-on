### 4.2 `loop_executor think()` 异步化分析

**当前**: 
```rust
let think_result = block_in_place(|| {
    think(task, &tool_candidates, &retry_counts, config, recommender.as_deref())
});
```

**分析**: `think()` 是 CPU 密集的同步操作（token 匹配、评分计算），不包含 LLM 调用。因此 `block_in_place` 是 **正确的 CPU 卸载模式**，不应改为 async。

**结论**: 无需更改。`think()` 保持 `block_in_place` 是最高效的方式。

### 4.3 编译速度优化

`test_i18n` workspace member 移除：
- 之前: 7 个 workspace members
- 之后: 6 个 workspace members
- 收益: 每次编译减少一次 workspace 初始化开销 (约 1-2s)

## 5. Tools/Skills 全链路完整性

### 5.1 Tool 注册执行流程

```
AI 识别任务 → Agent 选择工具
  → [go-on server] ToolRegistry::get(name) → HashMap O(1)
  → Governance 检查 (PUA/RBAC/Guardian + 缓存)
  → Bulkhead 并发限流 (Semaphore)
  → ToolHook pre_execute (并行 join_all)
  → Tool::run / Tool::run_async 执行
  → ToolHook post_execute
  → 结果返回 Agent
```

**状态**: ✅ 全链路畅通，无阻塞节点

### 5.2 Skill 注册执行流程

```
AI 识别任务 → 选择 skill_execute/skill_list 工具
  → [go-on server] SkillRegistry::get(name) 或 discover_skills()
  → skill_discovery::SkillDiscovery (缓存包装, 300s TTL, 200 entries)
  → Skill::execute(input) 执行
  → 结果返回
```

**状态**: ✅ 全链路畅通，skill_discovery 已内联到 skill 模块
