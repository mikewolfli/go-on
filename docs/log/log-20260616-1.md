# Log 2026-06-16-1: `std::sync::Mutex` 重入死锁修复 & 全量扫描

## 背景

`cargo test --lib` 全量测试超过 10 分钟超时。经排查，根因为多处 `std::sync::Mutex` 重入死锁（Rust 的 `std::sync::Mutex` 不可重入，同一线程重复加锁立即死锁）。

---

## 修复 1：`src/intelligence/self_model.rs` — 6 处死锁

### 根因

`SelfModelCore` 的 6 个方法持锁后调用 `self.persist()`，而 `persist()` 内部再次锁同一 `self.inner`：

| 方法 | 行号 | 持锁调用 |
|---|---|---|
| `register_capability` | L287 | `self.persist()` → 死锁 |
| `update_capability` | L310 | `self.persist()` → 死锁 |
| `add_limitation` | L354 | `self.persist()` → 死锁 |
| `acknowledge_limitation` | L374 | `self.persist()` → 死锁 |
| `record_performance` | L423 | `self.persist()` → 死锁 |
| `record_execution_result` | L522 | `self.persist()` → 死锁 |

`set_identity`（L252）已正确使用 `Self::persist_inner(&inner)`，是唯一幸免的。

### 修复

- 全部 6 处改为 `Self::persist_inner(&inner)`（持锁态写入，不再重复加锁）
- 删除不再使用的 `persist()` 方法（原方法先锁再调 persist_inner，已无调用者）
- 更新文档注释：`persist_inner` 改为主入口，标注调用者必须持锁

### 附带修复

`test_persistence_save_and_load` 测试因死锁从未执行到断言处，实际存在 bug —— `std::fs::create_dir_all` 从未调用，写入目录不存在导致 `load_from_file` 报 `No such file or directory`。添加了目录创建。

### 验证

```
cargo test --lib intelligence::self_model
24 passed, 0 failed, 0.01s  (之前 >60s 死锁)
```

## 修复 2：`src/memory/vector.rs` — `upsert` 方法死锁

### 根因

`VectorStore::upsert` 在已持 `self.conn` 锁的 scope 内（L575），eviction 查询时再次 `self.conn.lock()`（L613），导致死锁。

### 修复

eviction 查询改为复用外层 `conn` 引用（`conn.prepare(...)`），不再重新加锁。

### 验证

此死锁导致 2 个 `process_chat_request_*` tokio 测试 >60s 挂起：
```
cargo test --lib "process_chat_request_wires_vector_context"
1 passed, 0 failed, 0.03s  (之前 >60s)
```

### 发现的正确模式（参考）

代码库中多处已正确处理了不可重入锁问题：

1. **`security_governor.rs:467-472`** — 显式 `drop(inner)` 注释说明再调重新加锁函数
2. **`memory/memory_persistence.rs:1360-1366`** — block-scoped 锁，释放后调子方法
3. **`capability_bus/core.rs:554-558`** — 注释标注"绝不在子系统边界持锁"
4. **`self_model.rs`** — `persist_inner` 静态函数模式（修复后已推广到全部 6 处）
