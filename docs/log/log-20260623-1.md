## 四、🧪 测试真行为验证 — `test_federated_learning_e2e.rs` 全量重写

### 问题严重性

**原文件**: 所有断言都是同义反复（tautological）：

- `assert!((1.0 - 0.1 - 0.2 - 0.7).abs() < f64::EPSILON)` — 测试基本算术而非 DP
- `assert_eq!(node_a.id, "node-alpha")` — 测试硬编码构造器值
- `assert!(discovered_set.contains("node-alpha"))` — 测试 `HashSet::insert` 工作

**违反规则**: principle.md 第 17 条 — "新增功能的测试必须是真实行为验证，不是 assert!(true) 或空测试体"

### 修改方案

完全重写为 12 个行为验证测试:

| # | 测试名 | 验证内容 | 行为类型 |

## 五、⚡ 冗余锁/序列化移除

### Fix 1: 移除 6 个冗余 `#[serial]`

**文件**: `tests/openai_compat_matrix_integration.rs`

- 移除 6 个 `#[serial]` 标注（openai_http_request_matrix_regression, responses_api_r1 等）
- 移除 `use serial_test::serial;` 导入

**原因**: `HttpHarness::spawn()` 内部已使用 `CrossProcessLock("openai-compat", 60)` 进行进程级序列化。`#[serial]` 是多余的线程级序列化，阻止 Cargo 并行运行这些测试。

**保留** 的 `#[serial]`: 18 个在 `src/` 中，全部为合法使用（env var 全局状态、OTel 全局状态、共享缓存、子进程固定端口）。

### Fix 2: `process_is_alive` 跨平台支持

**文件**: `tests/common/mod.rs`

**修改前**: 仅 Linux (`/proc/{pid}`)，macOS CI 上静默失败

**修改后**: 双平台实现：

```rust
#[cfg(target_os = "linux")]
fn process_is_alive(pid: u32) -> bool {
    std::path::Path::new(&format!("/proc/{}", pid)).exists()
}

#[cfg(not(target_os = "linux"))]
fn process_is_alive(pid: u32) -> bool {
    std::process::Command::new("kill")
        .arg("-0")
        .arg(pid.to_string())
        .status()
        .map(|s| s.success())
        .unwrap_or(false)
}
```
