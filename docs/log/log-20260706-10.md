## 发现并修复的问题

### 🔧 Fix 1: Chat跟随轮询缺少principles (严重 🟡)
**文件**: `src/cli/chat.rs:1039`  
**问题**: 工具执行后的agent follow-up调用传递了 `None` 作为principles，导致follow-up轮次中的agent不知道可用工具列表、`__tool_call__`协议或已注册的skills。  
**修复**: 改为传递 `build_cli_principles()` 的结果，与初始调用一致。  
**影响**: Agent follow-up响应现在能正确使用工具和skills。

### 🔧 Fix 2: `/diff <path>` 路径参数永远无法匹配 (严重 🟡)
**文件**: `src/cli/chat.rs:511-521`  
**问题**: match arm `"diff"` 精确匹配 `cmd`，但 `cmd` 在用户输入 `/diff src/main.rs` 时为 `"diff src/main.rs"`，不匹配 `"diff"`。路径过滤逻辑(514-521行)的 `else` 分支是死代码。  
**修复**: 将匹配改为 `cmd if cmd == "diff" || cmd.starts_with("diff ")`。  
**影响**: `/diff <path>` 现在正确工作，不再是未知命令。

### 🔧 Fix 3: `input` 变量未使用 (低 🟢)
**文件**: `src/cli/chat.rs:263`  
**问题**: `input` 变量声明并 `.clear()`，但从未赋值。实际输入来自 `stdin_rx` 的 `line` 局部变量。  
**修复**: 删除 `input` 声明和 `input.clear()` 调用。  
**影响**: 减少无意义的内存操作。

### 🔧 Fix 4: `options` 变量始终为 None (低 🟢)
**文件**: `src/cli/chat.rs:836`  
**问题**: `options: Option<HashMap<String, Value>>` 变量始终为 `None`，仅使用一次。  
**修复**: 在调用处直接使用 `None`，删除变量。同时删除未使用的 `HashMap` import。  
**影响**: 代码更简洁。

### 🔧 Fix 5: 退出保存与自动保存竞态 (中 🟡)
**文件**: `src/cli/chat.rs:802-814`  
**问题**: 退出时的session保存不检查 `SAVE_IN_FLIGHT`，若上一轮的自动保存(`tokio::spawn`)仍在写盘，两个写入并发导致数据丢失。  
**修复**: 退出保存前最多等待500ms让in-flight保存完成（50次×10ms轮询）。  
**影响**: 消除会话数据并发写入丢失的风险。

### 🔧 Fix 6: ToolRegistry fallback链代码重复严重 (严重 🔴)
**文件**: `src/orchestration/tool/mod.rs`  
**问题**: `run_fallback_chain_sync`(50行) 和 `run_fallback_chain_async`(50行) 仅有执行方式不同，其余完全相同。`run_with_fallback`(40行) 和 `run_with_fallback_async`(40行) 也重复了metrics记录和fallback耗尽逻辑。  
**修复**: 
- 抽取 `run_fallback_step` / `run_fallback_step_async` 作为单步执行抽象
- 抽取 `record_fallback_success` 作为成功记录抽象
- 抽取 `run_core_fallback` 作为主工具执行+fallback核心逻辑（sync版本共享）
- async版本保留但复用这些抽象，重复代码减少约60%
**影响**: 维护时只需要修改一处fallback逻辑。减少约80行重复代码。

### 🔧 Fix 7: pipeline.rs缺少 `skill_create` 映射 (中 🟡)
**文件**: `src/orchestration/tool/pipeline.rs:188`  
**问题**: `pipeline_tool_to_action` 中 `skill_create` 未映射到任何action，落到 `_ => "read"` 默认值且触发警告。  
**修复**: 将 `"skill_create"` 添加到 `"write"` 操作组（与 `"skill-creator"` 同组）。  
**影响**: pipeline沙箱正确识别skill_create为写操作。

### 🔧 Fix 8: `handle_chat_mode` 中 ProtocolNegotiator 完全无用 (中 🟡)
**文件**: `src/main/server.rs:287-294`  
**问题**: `ProtocolNegotiator` 分配 + `negotiate()` 调用后结果仅用于debug日志，不影响 `run_terminal_chat` 的行为。  
**修复**: 移除 `ProtocolNegotiator` 分配和 `negotiate()` 调用，直接用简单日志。同时移除不再需要的 `ProtocolNegotiator` 和 `NegProtocolMode` import。  
**影响**: 每次chat启动减少2个对象分配。

### 🔧 Fix 9: start_server中ProtocolNegotiator结果无用 (中 🟡)
**文件**: `src/main/server.rs:243-254`  
**问题**: `dispatch_mode` 已由 `resolve_access_selection()` 完全解析，`ProtocolNegotiator` 的 `negotiate()` 结果仅用于日志，不影响 `dispatch_server`。  
**修复**: 移除 `ProtocolNegotiator` 使用，直接日志记录 `dispatch_mode`。  
**影响**: 每次server启动减少不必要的negotiation。保持功能不变。

### 🔧 Fix 10: `_active_config` 无用分配 (中 🟡)
**文件**: `src/main/mod.rs:262-271`  
**问题**: `_active_config` 是已禁用的热加载watchdog(注释说macOS因kqueue死锁禁用)的遗留代码。分配了 `Arc<RwLock<AppConfig>>` 但从未引用。  
**修复**: 删除 `_active_config` 和相关死锁注释块。  
**影响**: 每次启动减少一次完整AppConfig克隆 + Arc/RwLock分配。热加载如果将来需要需重新实现。

### 🔧 Fix 11: CLI测试冗余断言 (低 🟢)
**文件**: `tests/cli_tests.rs:43-46`  
**问题**: 第二个assert `!stdout.is_empty() || status.success()` 中 `status.success()` 在39-42行已assert为true，导致条件总是true。  
**修复**: 简化 `assert!(!stdout.is_empty())`。  
**影响**: 测试断言精确。

### 🔧 Fix 12: Security测试文档与实际不匹配 (低 🟢)
**文件**: `tests/e2e/test_security_e2e.rs:52`  
**问题**: doc注释声称测试"all five security control planes"，实际只测试了3个（prompt injection、audit integrity、secret rotation）。mTLS和request signing测试缺失。  
**修复**: 更新doc注释如实说明。  
**影响**: 文档准确。

### 🔧 Fix 13: Self-evolution测试死注释 (低 🟢)
**文件**: `tests/e2e/test_self_evolution_e2e.rs:254-257`  
**问题**: 注释承诺了一个sandbox迭代预算的断言，但从未实现。  
**修复**: 删除死注释。  
**影响**: 代码清晰。
