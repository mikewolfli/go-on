## 第1轮修复详细清单

### 修复 P0-1: hyper_resilience.rs 编译错误
**文件**: `resilience/hyper_resilience.rs:1240`
**问题**: 调用 `chaos.should_inject_fault(FaultType::NetworkTimeout)` 但方法名为 `check_fault(&str)`，参数类型也不匹配。
**修复**: 
```rust
// 修改前:
if chaos.should_inject_fault(crate::resilience::chaos::FaultType::NetworkTimeout) {
// 修改后:
if chaos.check_fault("execution").is_some() {
```

### 修复 P0-2: compute_deviation epsilon 逻辑缺陷
**文件**: `governance/drift/drift_protection.rs:578-585`
**问题**: epsilon=1e-6 导致 baseline=0 时产生 100,000,000+ 偏差值。
**修复**: 将 epsilon 改为 0.01，使零 baseline 的偏差值保持在合理范围。

### 修复 P1-6: 移除 _phase_val 死变量
**文件**: `gui/.../runtime.rs:329-333`
**问题**: `_phase_val` 分配后从未使用，但 `.clone()` 仍执行。
**修复**: 直接删除该变量，保留 `use_workflow_rpc` 初始化。

### 修复 P1-7: 优化 plan_output 解析
**文件**: `gui/.../runtime.rs:796-808`
**问题**: `plan_output` 被完整解析后丢弃，只用于 debug_assertions 日志。
**修复**: 简化为 `.is_some()` 检查，日志保持 debug_only。

### 修复 P1-8: _status_log cfg 条件编译
**文件**: `gui/.../runtime.rs:913-921`
**问题**: `_status_log` 格式字符串在 release 和 debug 模式都分配。
**修复**: 将整个变量和 eprintln! 移入 `#[cfg(debug_assertions)]` 块。

### 修复 P2-2: ForkRegistry Mutex → RwLock
**文件**: `orchestration/fork_registry.rs`
**问题**: 读远多于写的 API 使用独占 Mutex。
**修复**: 改为 RwLock，读方法使用 `.read()`，写方法使用 `.write()`。

### 修复 P2-4: build_cli_principles Mutex → RwLock
**文件**: `cli/chat.rs:1563-1617`
**问题**: 热路径缓存使用独占 Mutex。
**修复**: 改为 RwLock，读检查用 `.read()`，写更新用 `.write()`。

### 修复 P3-6: 移除 agent 冗余 supports_model_override()
**文件**: 29 个 agent 实现文件
**问题**: 每个 agent 都覆写 `supports_model_override()` 返回 `true`，与 trait 默认实现相同。
**修复**: 从所有 agent 实现中删除该方法（见 `agents/agent.rs` L574 默认实现）。

### 修复 P3-7: build_cli_principles 返回类型
**文件**: `cli/chat.rs:1563`
**问题**: 返回 `Option<Vec<String>>` 但从不返回 None，调用处用 `unwrap_or_default()`。
**修复**: 改为直接返回 `Vec<String>`，调用处也相应调整。

### 修复 P6-1/2/3: CLI Chat Thinking 顺序
**文件**: `cli/chat.rs`
**问题**: Thinking tokens 在 reply 之前输出，导致展示顺序为 thinking 在上、reply 在下。
**修复**: 
- 在 streaming 过程中缓冲 thinking tokens
- 在 reply 流完后(before tool execution)统一打印 thinking
- 输出格式: `"💭 Thinking:"` 标题 + thinking 内容（灰色）

### 修复 P4-1/2: GUI Chat 重复克隆和哈希计算
**文件**: `gui/.../old_ui_content.rs`
**问题**: 每次渲染时 content 字符串克隆 2 次，哈希计算 2 次。
**修复**: 复用脏检查阶段的哈希值，减少不必要的字符串克隆。

### 修复 P5-1: 过期注释
**文件**: `protocol/acp_methods.rs:4-5`
**问题**: 引用已重构的 `protocol_pack.rs` 和 `request.rs`。
**修复**: 更新为 `acp/impl/`。

### 修复 P6-4: CLI /commit 升级为 AI 驱动（带用户确认）
**文件**: `cli/chat.rs`

**原实现问题**:
1. `git add -A` 无确认直接全部暂存
2. commit message 是 `feat: file1, file2` 这种无语义的纯文件名拼接
3. 无用户确认，直接提交

**修复**:
1. 添加 `chat_simple()` 辅助函数：向 agent 发送简单 prompt 并收集完整回复
2. `/commit` 现用 AI 分析 diff 生成 conventional commit message
3. 展示 AI 建议的 message 给用户确认
4. 用户可：按 Enter 接受、输入自定义 message、输入 n 取消
5. 仅在确认后执行 `git add -A && git commit -m`
6. AI 失败时自动降级为简单 fallback

### 修复 P6-5: CLI /plan 升级为 AI 驱动
**文件**: `cli/chat.rs`

**原实现问题**: 只显示最后一条用户消息的前 200 字符，然后告诉用户"去问 AI"

**修复**:
1. 从对话上下文中提取最后 10 条非系统消息
2. 发送给 AI 生成结构化分步骤执行计划
3. 显示 AI 生成的计划（含文件路径建议）

### 修复 P6-6: CLI /review 升级为 AI 驱动
**文件**: `cli/chat.rs`

**原实现问题**: 只显示 git diff 截断到 60 行，无代码审查

**修复**:
1. 先显示变更文件统计摘要
2. 将完整 git diff 发给 AI 进行代码审查
3. AI 分析 bug、安全问题、代码质量、改进建议
4. AI 失败时自动降级为原始 diff 展示
