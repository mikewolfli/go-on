## 二、go-on 与 Zed Agent Server 规格对比

### 2.1 Zed Agent Server 预期规格（逆向工程自Zed源码）

Zed的Agent Server通过 **ACP (Agent Communication Protocol)** 通信，关键规格：

```
通信方式: 子进程 stdin/stdout，line-delimited JSON-RPC 2.0
会话管理: session/new → session/prompt → (session/cancel) → session/close
工具定义: AgentTool trait, JSON Schema (schemars), ToolKind (Read/Write/Destructive)
流式更新: update_fields notifications during tool execution
认证: AuthMethod (terminal, URL等)
模型选择: AgentModelSelector (list_models, select_model, selected_model)
配置选项: SessionConfigOption (mode, model parameters)
会话列表: session/list, session/resume, session/load
```

### 2.2 go-on 当前符合度

| 规格 | 当前状态 | 符合度 |
|------|---------|-------|
| **JSON-RPC 2.0 stdio** | 通过 `McpStdioServer` 支持，但ACP stdio缺少干净的事件循环 | ⚠️ 部分 |
| **session/new** | 已实现，路由到 `protocol_pack::session_new_payload` | ✅ |
| **session/load** | 已实现 | ✅ |

## 三、深度扫描发现的问题

### P1: 巨型match语句性能瓶颈
**位置**: `src/acp/impl/request.rs` L611-726
**问题**: 500+行的 match 语句硬编码所有方法路由，每次请求O(n)字符串比较
**副作用**: 违反原则第9点（代码质量），影响性能
**修复**: 改用已存在的 `MethodRouter` 注册模式

### P2: ACP Stdio模式缺少独立事件循环
**位置**: `src/protocol/mcp_server.rs` (McpStdioServer)
**问题**: MCP有专用的stdio事件循环，但ACP模式通过 `dispatch_server` 进入，无法最小化启动
**修复**: 创建 `protocol/acp_stdio.rs` 作为轻量级stdio事件循环

### P3: 工具定义不暴露到ACP协议层
**位置**: `src/acp/impl/request/protocol.rs`
**问题**: ACP方法列表中无 `tools/list` 或 `tools/call` 端点定义
**影响**: Zed Agent Server需要工具发现能力，否则Zed无法知道go-on有哪些工具
**修复**: 在ACP方法列表中添加 `tools/list` 和 `tools/call`，实现工具定义响应

### P4: 会话缺少项目工作目录跟踪
**位置**: `src/acp/impl/request/protocol_pack.rs`
**问题**: `AcpSessionState` 有 `cwd` 但未在 `session/new` 中填充
**影响**: Zed Agent Server使用 `work_dirs` 参数指定工作目录
**修复**: session/new 从params提取 `work_dirs` 并存储

### P5: 方法路由未使用MethodRouter
**位置**: `src/acp/impl/request/method_router.rs`
**问题**: MethodRouter已定义 (B51-28) 但未被 `handle_request` 使用
**影响**: 额外代码复杂度，无实际用途
**修复**: 将主要handler注册到MethodRouter并替换match语句

### P6: block_in_place + block_on 检查
**查找**: 所有 `block_in_place` 和 `Handle::current().block_on`
**问题**: 热路径中使用阻塞操作

### P7: 测试覆盖
**问题**: 部分测试在 `backend-postgres` feature下被静默跳过
**检查**: `src/acp/impl/chat_tests.rs` 中所有测试有 `#[cfg(not(feature = "backend-postgres"))]`

### P8: Session能力协商缺失
**位置**: `src/acp/impl/request/protocol_pack.rs`
**问题**: initialize 返回的capabilities不包含ACP协议版本、工具支持、流式能力等
**影响**: Zed无法通过能力协商优化通信

## 五、详细改进记录

### 5.1 创建 ACP Stdio Runner

**文件**: `src/protocol/acp_stdio.rs`
**目的**: 提供Zed可以直接spawn的轻量级ACP stdio事件循环
**设计**:
- 从stdin读取line-delimited JSON
- 解析JSON-RPC 2.0请求
- 通过现有 `handle_request` 路由
- 写入line-delimited JSON-RPC响应到stdout
- stderr输出日志

### 5.2 增强protocol_pack工具定义

**文件**: `src/acp/impl/request/protocol_pack.rs`
**新增**: `tools_list_payload()` 和 `tools_call_payload()` 函数
**设计**:
- 从 `ToolRegistry` 枚举工具
- 转换为ACP标准工具描述格式
- 支持按 `tool_name` 精确查询

### 5.3 接线MethodRouter

**文件**: `src/acp/impl/request/method_router.rs`
**改进**:
- 为session、tools、skill等方法注册handler
- `handle_request` 优先尝试MethodRouter，回退到原有match
- 逐步迁移所有方法到注册表
