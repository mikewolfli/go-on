## 发现的问题与修复

### ✅ 变更1: Windows `shell_exec` 兼容性修复

**文件**: `src/orchestration/tool/extended/shell.rs`

**问题**: Windows 上使用 `sh -c` 执行命令（不存在），且`timeout`命令检测假设GNU环境。`kill`命令也不适用于Windows。导致测试失败：
```
shell_exec should run: 目录名称无效。 (os error 267)
```

**修复**: 
- 使用 `cfg!(target_os = "windows")` 检测平台：Windows用 `cmd.exe /C`，Unix用 `sh -c`
- 超时终止进程：Windows用 `taskkill /F /T /PID`，Unix用 `kill -9`
- GNU `timeout` 检测仅限Unix，Windows使用Rust级线程超时

**效果**: `shell_exec_runs_echo` 测试在Windows上通过（1922/1922全部通过）

### ✅ 变更2: 修复 `PromptBasedSkill` 模板替换空格bug

**文件**: `src/orchestration/skill/execution.rs:98`

**问题**: `format!("{{{{{} }}}}", key)` 中的空格导致 `{{key }}`（带尾随空格）代替 `{{key}}`。任何依赖 `{{key}}`（无空格）语法的模板引擎将无法匹配。

**修复**: 改为 `format!("{{{{{}}}}}", key)` 产生正确的 `{{key}}`（无空格）。

### ✅ 变更3: 移除未使用的 `LoopStage` 枚举

**文件**: `src/orchestration/tool/mod.rs:2397-2403`

**问题**: `pub enum LoopStage { Think, Act, Observe }` 在整个代码库中从未被引用。仅定义处引用自身。

**修复**: 删除整个枚举。`LoopIteration.stage` 字段已使用字符串字面量 `"think"`/`"act"`/`"observe"`。

### ✅ 变更4: 修复mTLS方法上的 `#[allow(dead_code)]` 误导性注释

**文件**: `src/security/mtls.rs:252-266`

**问题**: `with_client_cert` 和 `with_allowed_cns` 上的 `#[allow(dead_code)]` 注释称它们"未接线"，但实际上在 `run_acp_http_server` 的 `#[cfg(feature = "multi-users-server")]` 块中被调用。

**修复**: 更新注释准确描述"在 `multi-users-server` feature 下被调用"。

### ✅ 变更5: 为全局安全检查器添加公有getter，消除写后不读的死代码

**文件**: `src/security/mod.rs`

**问题**: `CONTENT_SAFETY_CHECKER` 和 `PROMPT_INJECTION_DETECTOR` 全局变量是 `OnceLock` 实例，仅在 `wire_content_safety`/`wire_prompt_injection` 中被写入（`.set()`），但从未被读取（`.get()`）——纯粹的"写后丢弃"设计。

**修复**: 添加公有getter函数：
- `get_content_safety_checker()` → `Option<&'static SafetyChecker>`
- `get_prompt_injection_detector()` → `Option<&'static InjectionDetector>`

这完成了该设计的初衷：提供全局访问点，供代码库中任何需要安全检查的组件使用。

### 注意（非修复）

一些代理发现的问题经确认后决定不修改：

1. **`execute_loop`/`execute_loop_async` 重复** — 约400行几乎相同的代码。有意保持为独立函数因为：(a) **`run()` 同步** vs **`run_async()` 异步** 签名有根本的不同；(b) 抽象会引入间接层，可能影响性能；(c) 经过11轮审核后，此重复已知且被接受。

2. **`memory_response_cache.rs` `&mut self`** — 使用 `Arc<RwLock>` 但方法签名仍为 `&mut self`。可通过去除 `&mut` 和让内部可变性接管来改进，但这需要更多测试来验证没有破坏任何东西。

3. **`code_repo_analyzer.rs` 部分实现** — LOC计数和依赖图是空壳。这些被标记为"预留未来使用"（树-sitter集成），但核心基础设施（仓库克隆、文件遍历、关键词问答）工作正常。

4. **`content_safety.rs` 中的 `check_with_feedback` 类型** — 完全实现的守卫，但当前没有代码调用它们。保留为未来使用（F-GAP）。
