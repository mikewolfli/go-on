## 1. Zed 源码深度研究成果

### 1.1 `agent_servers` 设置解析

**文件**: `zed/crates/settings_content/src/settings_content.rs:147` → `settings_content/src/agent.rs:653-797`

Zed 的 `agent_servers` 使用 **ACP 协议（stdio）**，与 go-on 的 `acp_stdio` 模式完全兼容。

```rust
// CustomAgentServerSettings 结构（settings_content/src/agent.rs）
pub enum CustomAgentServerSettings {
    Custom {
        command: PathBuf,       // agent 可执行文件路径
        args: Vec<String>,      // CLI 参数
        env: HashMap<String, String>,
        default_mode: Option<String>,
        default_config_options: HashMap<String, AgentConfigOptionValue>,
        ...
    },
    Registry { ... },           // 从 Zed 扩展注册表安装
}
```

**注意**: `agent_servers` 设置使用的是 ACP 协议，**不是 MCP**。

### 1.2 协议版本

**文件**: `zed/crates/agent_servers/src/acp.rs:655`

```rust
const MINIMUM_SUPPORTED_VERSION: ProtocolVersion = ProtocolVersion::V1;
```

Zed 使用 `agent-client-protocol` crate v1.1.0，协议版本 `V1`。初始化时发送 `initialize` 请求，agent 回复 `protocol_version`。

### 1.3 传输方式

**文件**: `zed/crates/agent_servers/src/acp.rs:830-870`

Zed 使用**换行分隔的 JSON-RPC over stdio**，不是 SSE：

```rust
let stdout = child.stdout.take()...;
let stdin = child.stdin.take()...;
// 使用 Lines transport 逐行读写
let incoming_lines = futures::io::BufReader::new(stdout).lines();
let transport = Lines::new(tapped_outgoing, tapped_incoming);
```

每个 JSON-RPC 消息必须是**单行**（`\n` 分隔），不支持 SSE 的 `data:` / `event:` 帧格式。

### 1.4 Session 通知（流式输出）

Zed 通过 `session/update` notification 接收流式数据：

| 更新类型 | 说明 |
|---------|------|
| `agent_message_chunk` | AI 回复文本块 |
| `agent_thought_chunk` | thinking/reasoning 块 |
| `tool_call` | 工具调用 |
| `tool_call_update` | 工具调用更新（含 terminal 输出） |
| `usage_update` | token 用量统计 |
| `session_info_update` | 会话标题更新 |
| `available_commands_update` | slash commands 更新 |

### 1.5 Sub-Agent 支持

**文件**: `zed/crates/acp_thread/src/acp_thread.rs:125`

Zed 通过 ToolCall 的 `meta.subagent_session_info` 字段支持子代理：

```rust
pub struct SubagentSessionInfo {
    pub session_id: acp::SessionId,
    pub message_start_index: usize,
    pub message_end_index: Option<usize>,
}
```

子代理会话通过**同一个 stdio 连接**使用自己的 `session_id` 通信。

### 1.6 Terminal 输出

**文件**: `zed/crates/agent_servers/src/acp.rs:4791-4850`

Zed 通过 ToolCall 的 `meta.terminal_output` / `meta.terminal_exit` 字段处理终端输出，不是通过独立的 notification。

## 3. 测试修复

### 3.1 `prepare_environment_with_prerequisites` 修复

**原因**: 测试使用 `"rust"` 和 `"cargo"` 作为 prerequisites，但 CI 环境中不一定安装。`check_prerequisite_available` 用 `command -v` 检测返回 `false`。

**修复**: 改用 `"sh"`（在所有 Unix 系统上通用）。

### 3.2 `test_evolution_history_persistence` 修复

**根因**: `EvolutionHistory` 的 `Drop::drop()` 将整个 HashMap 写为单个 JSON 对象（`serde_json::to_string(&data)`），但 `load_from_disk()` 期望 NDJSON 格式（每行一个 JSON）。

```
Drop::drop 写入:   {"uuid1": {...}, "uuid2": {...}}
load_from_disk 读取: {"id":"uuid1",...}  ← 解析失败！
                    {"id":"uuid2",...}
```

**修复**: `Drop::drop()` 改为以 NDJSON 格式写入：

```rust
// 修复前
let _ = std::fs::write(&path, &serde_json::to_string(&data)?);

// 修复后
for entry in &data {
    writeln!(&mut out, "{}", serde_json::to_string(entry)?)?
}
```

## 5. go-on ACP stdio 针对 Zed 的优化建议

基于 Zed 源码深度分析，go-on 目前的 ACP stdio 实现已基本兼容。以下为可选的增强方向：

| 优先级 | 改进项 | 说明 |
|--------|--------|------|
| ⭐⭐⭐ | 确保 Z 协议版本协商 | `agent-client-protocol` v1.1.0 要求 `ProtocolVersion::V1` |
| ⭐⭐⭐ | 单行 JSON-RPC | 每条消息必须是单行 `\n` 分隔，不能是多行 |
| ⭐⭐ | stderr 日志 | Zed 捕获 stderr 并在连接失败时显示 |
| ⭐⭐ | Sub-agent session 支持 | 通过 ToolCall meta 传递 `subagent_session_info` |
| ⭐ | Terminal 输出 via meta | 放在 ToolCall 的 `meta.terminal_output` 而非独立 notification |
