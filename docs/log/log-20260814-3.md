# Log 2026-08-14 #3 — go-on 神级 AGI 进化总方案（综合三方优势的可落地路线图）

> **输入**：`log-20260814-2.md` 三方对比（hermes/codex/dsh）全部优化建议 + 本仓库实测基线。
> **目标**：go-on 综合各方优势——hermes 的编排智能、codex 的执行器接口、dsh 的插件化形态——同时**保留自己的治理/协议/韧性底座**，分阶段落地，最终成为"可信、自主、能干、会成长、可互联"的 AGI 运行时。
> **原则**：每一里程碑可独立交付、可验证（lib 测试全绿 + clippy 零警告是永久门槛）；先精炼清地基，再架构定型，最后能力与生态。

---

## 0. 愿景与总原则

### 0.1 神级 AGI 运行时 = 五个正交能力面

```
┌──────────────────────────────────────────────────────────────┐
│  信任 Trust    治理底座：RBAC / 审计链 / 注入检测 / 韧性       │ ← 保留（go-on 独有）
├──────────────────────────────────────────────────────────────┤
│  自主 Autonomy  编排智能：技能闭环 / 跨会话记忆 / 无人值守      │ ← M3（学 hermes）
├──────────────────────────────────────────────────────────────┤
│  能干 Capable   执行器接口：exec --json / 沙箱 / 审批分层       │ ← M2（学 codex）
├──────────────────────────────────────────────────────────────┤
│  成长 Growth    生态形态：能力缝 / 插件化注册 / 自进化          │ ← M1+M4（学 dsh）
├──────────────────────────────────────────────────────────────┤
│  互联 Connected ACP / MCP / SSE / 多平台 / SDK                 │ ← M2+M3（保留+扩展）
└──────────────────────────────────────────────────────────────┘
```

AGI 的落地释义（不空洞）：**可信**（每步可审计可回滚）× **自主**（任务无需人工分步）× **能干**（真工具真沙箱真结果）× **成长**（越用越强，技能/记忆自进化）× **互联**（进得了任何入口、出得了任何平台）。

### 0.2 总原则（每阶段强制）

1. **编译期保证优先**：能 trait 抽象/类型保证的，不做运行时动态（区别于 dsh 的 TS 动态，Rust 优势不丢）。
2. **治理永不绕过**：任何新能力（exec、cron、插件）都必须经过 HarnessBus/RBAC/审计，插件层之上。
3. **单一事实源**：每类信息（事件、工具 schema、会话历史）只有一个权威定义，杜绝四方分叉。
4. **验收即绿色**：`cargo test --lib` 全绿 + `cargo clippy --all-targets -D warnings` 零警告 + 新增回归测试，缺一不可。
5. **增量可回滚**：每里程碑独立 commit；配置向后兼容（新增默认关闭的开关优先）。

## 4. 里程碑详案（可落地到文件）

### M0 — 地基精炼（先清地基，再盖楼）

**M0.1 统一流式事件契约**（收益：消灭一类缺陷源）
- **现状**：`StreamFrame`（`acp/impl/chat/streaming.rs`）是载体，但消费方四套各自解析：`acp/impl/request/protocol_pack/session.rs`（ACP bridge）、`gui/src/views/chat/chat_impl/runtime.rs`（process_stream_events）、`src/cli/chat.rs`（classify_token）、`acp/impl/request/dispatch.rs`。已发生两处漂移缺陷（GUI 漏 status/phase、bridge 丢 done.response）。
- **落地**：新增 `src/acp/stream/consumer.rs`：
  - `pub fn classify_stream_event(event: &str) -> StreamEventKind`（chunk/done/result/status/phase/tool_approval/sub_agent/command/telemetry/error）
  - `pub fn extract_chunk_fields(payload) -> (token, reasoning)`（合并 GUI `extract_chunk_text` 与 bridge 的 reasoning/token 分支）
  - `pub fn extract_result_fields(payload) -> (response, thinking, agent, model)`（合并 `extract_result_meta`）
  - 四个消费方改为调用同一实现；GUI `_ =>` 分支对 phase/status 显式处理（上轮已做，本轮并入统一 consumer）。
- **验收**：`grep` 确认四处不再各自定义 token/reasoning 提取；现有 protocol_parity 集成测试（含上轮新增 2 个）继续全绿。

**M0.2 供应商声明式 Profile**（收益：37 家去重，维护面大减）
- **现状**：`src/agents/*.rs` 每家一个文件，重复 normalize/thinking/streaming 样板，仅 6 家原生 function call。
- **落地**：新增 `src/agents/profile.rs`：
  - `pub struct ProviderProfile { id, url_template, api_format, auth, native_function_call, streaming_mode, ... }`
  - 内置表：37 家 → 37 个 Profile 条目（OpenAI 兼容的 31 家共享一个 `OpenAiCompatAgent` 实现，Profile 只声明差异）；
  - 保留 `agents/*.rs` 中 6 家原生实现，其余收敛为 `OpenAiCompatAgent + Profile`；
  - 弱适配且无真实配置的供应商：从"代码内建"降级为"配置可注册"（`agents.<name>.type="openai_compat"` + profile 名），删除独占代码路径。
- **验收**：`src/agents/` 文件数明显下降；`cargo test` 全绿；`available_models` 输出不变（对外契约稳定）。

**M0.3 治理/韧性边缘清零**
- 对 `F-GAP-49` 系列 `#[allow(dead_code)]` 逐项裁决：**接线（给真实调用点）或删除**，禁止长期挂 allow；
- code_repo_analyzer 死错误变体、`ResilienceLevel::Enhanced` 死枚举变体：评估收紧为 crate-private 或删除；
- 混沌测试 14 种注入：保留调度器接入的，清除未接入点。
- **验收**：`grep -r "allow(dead_code)" src/` 数量降至个位数（仅 i18n 启动等合法处）。

**M0.4 大文件拆分**
- `src/acp/impl/chat_phases.rs`（2354 行）→ `src/acp/impl/phases/{mod,observe,think,act,reflect,helpers}.rs`；
- 检查 `src/acp/impl/chat.rs`、`src/cli/chat.rs`、`src/agents/agent.rs` 是否超 2000 行，超出则拆；
- **规则**：单一职责文件 ≤ 1500 行（对照 codex 1.2 万行与 hermes 3 万行 god file 的反面教训）。
- **验收**：`find src -name "*.rs" -exec wc -l {} +` 无 >2000 行文件（或明确记录豁免）。

**M0.5 thinking 标记双轨合一**
- GUI `THINKING_MARKER` + `split_thinking_from_content` 与后端 `TOKEN_THINKING_PREFIX` 二选一：**以 SSE `reasoning` 字段为唯一通道**，删除 GUI 的 marker 拆分（保留后端 prefix 仅作 CLI/兼容通道）。
- **验收**：GUI 不再 import THINKING_MARKER；CLI 与 GUI 对同一响应的 thinking 渲染一致。

**M0.6 文档统计 CI 化**
- `scripts/` 新增 `stats.sh`（生成测试数/供应商数/工具数/模块数），CI 或 pre-commit 回写 README 统计表；`README.zh-CN.md` 的 1555/1646 等数字改为占位符。
- **验收**：README 统计与实际 `cargo test --lib` 一致。

### M1 — 能力缝架构（学 dsh 的形态，用 Rust 的方式）

**M1.1 能力缝三件套**（最大单点收益，同时根治 R45 沙箱三份）
- **现状**：shell 执行（`orchestration/tool/exec_common.rs` + `extended/shell.rs`）、文件读写（`extended/filesystem.rs`）、沙箱规则（三份）各自为政。
- **落地**：新增 `src/orchestration/seam/`：
  - `fs/mod.rs`：`pub trait FsService { read, write, stat, list, search }` + Provider（`LocalFs` / `SandboxedFs`）+ Consumer（`read_file`/`write_file`/`search_files` 工具改为调用 seam）；
  - `subprocess/mod.rs`：`pub trait SubprocessService { spawn, exec }` + Provider（`LocalSubprocess` / `RemoteSubprocess` / `SandboxedSubprocess`）；
  - `sandbox/mod.rs`：`pub trait SandboxProvider { confine(argv) -> SandboxedArgv }` + Provider（`Bwrap` / `None`）+ 策略（网络/写入）；
  - `terminal/mod.rs`（可选）：持久终端 seam，Provider：`LocalPty` / `Remote`；
  - 目标：**换一个 provider 全产品跟随**（如沙箱从 bwrap 换远端，Bash/PTY/文件同步一起换）。
- **验收**：`read_file`/`write_file`/`shell_exec` 全部经由 seam；新增单元测试：`LocalFs` 与 `SandboxedFs` 对同一工具实现输出一致（除沙箱差异）；clippy 零警告。

**M1.2 配置补丁层**
- **现状**：`src/core/config` + 热重载 + schema 版本；无"分层合并 + 来源追踪"。
- **落地**：配置加载器支持 `内置 → 项目(.go-on/config.toml) → 用户(~/.config/go-on) → CLI --patch` 逐层合并，每个值记录来源（`ConfigSource { file, section, key }`）；`go-on config dump --sources` 输出每项来源（对齐 dsh `--dump-config`）；热重载保留。
- **验收**：`config dump --sources` 可打印每项来源；补丁层可覆盖任意标量/表项，无需改代码。

**M1.3 文件写操作收口 + diff 事件**
- **现状**：write_file / apply_patch / edit_file 三入口，沙箱各管各（R45 F8 补过 edit_file 漏洞）。
- **落地**：新增 `src/orchestration/write.rs`：
  - `pub struct WriteOp { path, content, mode }`（统一中间表示）；
  - 所有写工具 → `WriteOp` → 单一沙箱校验（`enforce_write_sandbox` 收敛到此）→ 执行 → **记录 `FileChangeEvent { path, old_hash, new_hash, op }`**（对齐 codex `TurnDiffEvent`）；
  - `FileChangeEvent` 进审计链 + GUI diff 展示 + `done` 事件携带。
- **验收**：三入口沙箱行为一致（新增对照测试）；审计链可回放"每次修改前后 hash"。

**M1.4 会话日志即事实源**
- **现状**：go-on 有 `conversation checkpoint/distillation`、audit 链，但模型上下文不从日志派生。
- **落地**：声明并实现不变式 **"模型可见 ⇒ 日志可重建"**：
  - `src/acp/session_log.rs`：append-only `SessionEvent`（user_message/assistant_message/tool_call/tool_result/thought_chunk）；
  - `derive_messages()` 从日志投影模型历史（对齐 dsh `deriveMessages`）；
  - fork/resume/重放/审计/UI 全部改为从日志派生（先做 fork/resume，UI 后置）；
  - 运行时 debug 断言：模型请求输入必须能从日志重建。
- **验收**：`session/fork`、`session/resume` 基于日志投影的测试全绿；审计与模型历史同源。

**M1.5 工具可见性由注册决定**
- **现状**：`orchestration/tool/mod.rs` ToolRegistry 已有注册，但 schema 源分散（R45 F4 修过描述与实现不符）。
- **落地**：注册点成为**唯一 schema 源**：`ToolSpec { name, schema(json_schema), visibility: ModelVisible|ServerOnly, mode_scope }`；prompt 组装从注册表取 schema（删除 `shared/tool_descriptors.rs` 的手写字符串，改为注册表生成）；`mode.rs` 的 allowed_tools 校验基于注册表 visibility。
- **验收**：`tool_descriptors.rs` 删除；模型可见工具集与 GUI/CLI 展示的工具集同源。

**M1.6 注册 RAII guard（卸载即回滚）**
- 工具/技能/事件监听注册返回 `RegistrationGuard`（drop 时注销，对齐 `SpawnGuard` 先例）；为 M4 插件化打基础。
- **验收**：`unregister` 测试：guard drop 后工具消失、事件不再触发。

### M2 — 执行器接口（学 codex 的确定性）

**M2.1 可编程执行器 `go-on exec --json`**
- **落地**：`src/cli/exec.rs` 新增子命令：
  - `go-on exec --json "prompt"`：单轮或有限轮执行，**stdout 只允许 JSONL**（事件契约：`thread.started / turn.started / item.* / turn.completed`），stderr 走日志；
  - headless 默认 `AskForApproval::Never`（可配置 `--approval-mode`）；
  - 复用 M0.1 统一事件契约序列化（对齐 codex `exec/src/exec_events.rs` + `#![deny(clippy::print_stdout)]` 式约束）；
  - 非交互：`--input-stdin` 读 JSON 输入（含 session_id 支持 resume）。
- **验收**：`go-on exec --json "echo test" | jq -c .` 输出结构化事件流；hermes/codex 风格的外部程序可无头调用 go-on。

**M2.2 审批链路分层（hook → 自动审核 → 用户）**
- **现状**：SafeGuard 模式 + `ensure_tool_permission` / `request_client_permission`，缺 hook 预决策与独立 reviewer 自动审核。
- **落地**：`src/governance/approval_chain.rs`：
  - ① `permission_hooks`（配置外部命令/脚本，返回 allow/deny/override）——在 HarnessBus 策略评估后、模型前；
  - ② `AutoReviewer`（可选，strict 模式）：独立 reviewer 会话（复用 `multi_model_voter` 的并发调用底座）自动审批低风险工具调用；
  - ③ 用户弹窗（现有）。
  - 审批决策全部进审计链（hook 返回、reviewer 判定、用户决定）。
- **验收**：三层的优先级链测试（hook deny 短路、reviewer 放行不弹窗、默认弹窗）；SafeGuard 交互打断频率下降（低风险自动放行）。

**M2.3 SDK 事件类型从 Rust 生成**
- **落地**：对流式事件/工具 schema 引入类型生成（`serde` + 手写生成器或引入 `ts-rs` 类 crate）；`sdk/typescript/` 直接 import 生成类型；工具 JSON Schema 由 M1.5 注册表导出。
- **验收**：TS SDK 无手写事件类型；`cargo build` 时校验生成文件无 diff（CI 门）。

### M3 — 编排智能（学 hermes 的成长性）

**M3.1 技能从经验自动创建闭环**（最大护城河差距）
- **现状**：`orchestration/skill/`（34 预置 + 导入 + 发现），技能是静态资产。
- **落地**：
  - `skill/auto_extract.rs`：会话结束后（reflect 旁路，fire-and-forget）后台提炼"本任务可复用方法"→ 生成 SKILL.md 草稿（agentskills.io 格式，go-on 已兼容），经 `SkillImportStore` 校验后入本地库（默认关闭，配置 `skill.auto_extract=true` 启用，避免噪音）；
  - `skill/usage.rs`：`skill_execute` 计分（次数/视图/成功率）→ 低频归档、高频置顶（对齐 hermes `skill_usage.py` + `curator.py`）；
  - 命名统一：删除 analyze-text←classify-text 类合并展示名，或明确别名表（`skill list` 输出一致）；
  - agent 可直接 `skill_create/update/delete`（受 RBAC + SafeGuard 门控，对齐 hermes `skill_manager_tool.py`）。
- **验收**：连续 N 次同类任务后，`skill list` 出现自动生成的草稿技能；低频技能自动归档测试通过。

**M3.2 跨会话记忆全文检索（FTS5 + CJK）**
- **现状**：`src/memory/`（warm.db SQLite + embedding + 语义缓存），无跨会话全文检索。
- **落地**：`memory/search.rs`：在 warm.db 消息表建 **FTS5 外部内容表 + CJK bigram 分词**（`tokenize='cjk_unicode61'`，解决中文 2 字符查询，对齐 hermes `hermes_state_search.py`）+ BM25 + LIKE 降级；新增 `memory.search` 工具（跨会话检索 + LLM 摘要，结果纳入上下文预算门控）。
- **验收**：中文关键词（2 字符）检索命中；`memory.search` 工具经 RBAC 门控；检索结果不超上下文预算。

**M3.3 用户级 cron + durable delegation**
- **现状**：background tasks（内部维护）存在，无用户级定时任务。
- **落地**：
  - `orchestration/schedule/cron.rs`：croniter 解析 + 文件锁 tick（对齐 hermes `cron/scheduler.py`），job 防重叠，usage 审计（token/费用），复用 `workflow.execute` 契约；
  - `orchestration/schedule/durable.rs`：`spawn_agent` 增加 durable 模式（任务落盘 SQLite + 崩溃恢复 + 结果 claim 交付，对齐 hermes `async_delegation.py`）；
  - 结果投递：先接 GUI 通知 + `--notify` 回调脚本，平台投递见 M3.4。
- **验收**：`cron add "*/5 * * * *" workflow.execute ...` 定时触发；kill -9 后 `recover` 恢复未完成任务。

**M3.4 多平台网关（架构模式验证）**
- **落地**：新增 `src/gateway/`（Rust，不学 hermes 的 3 万行 god file，只学模式）：`platform_registry + adapter trait + 会话哈希(platform+chat_id) + turn 租约锁 + 送达账本`；先支持 **1–2 个平台**（Telegram / 企业微信 webhook）验证模式。
- **验收**：单平台端到端（消息→agent→回复投递）集成测试；第二个平台只改 adapter。

### M4 — 生态自进化（学 dsh 的插件形态 + 神级愿景）

**M4.1 agent 生命周期事件域（瀑布事件）**
- **现状**：事件在传输层（StreamFrame），无 agent 生命周期扩展点。
- **落地**：`src/orchestration/events/` 新增 `agent/pre-step`、`agent/request`、`tools/pre-execute`、`tools/post-execute`、`agent/turn-stopping`（瀑布语义：监听者 next() 委派，对齐 dsh）；事件注册走 M1.6 guard；第三方包无需改循环即可观察/拦截/注入。
- **验收**：插件化监听器可重写 `tools/pre-execute` 拦截工具调用（审计记录拦截结果）。

**M4.2 技能即插件（可注册能力包）**
- **落地**：技能升级为"能力包"：`SkillBundle { SKILL.md + 配置段 + 关联工具白名单 + 上下文片段 + 事件监听 }`，运行时注册/卸载（trait object registry + M1.6 guard）；`skill_market.rs` 支持 bundle 打包导入。
- **验收**：安装技能包 = 注册其工具/上下文/事件，卸载 = 全部展开。

**M4.3 安全自进化（self-modification 的治理版）**
- **现状**：`orchestration/self_evolution/` 是后台 agent 改源码重编译。
- **落地**：双轨：① 运行时轨道（技能/配置/工作流的自进化——走 M4.2 能力包，不重编译）；② 源码轨道（保留，但全部修改经 `apply_patch` 收口（M1.3）+ 沙箱验证 + 审计回滚点 + RBAC 审批）。对齐 dsh self-modification 的"agent 挂载插件"，但**治理不绕过**。
- **验收**：自进化产生的每个改动有审计回滚点；高风险改动需审批。

## 6. 风险、取舍与明确不做

| 取舍 | 理由 |
|---|---|
| **不做**"一切是插件"（dsh 式运行时补丁任意改） | 安全面；Rust 用配置分层 + trait + 特性门控达到可组合 |
| **不做**运行时动态代码加载 | 失去编译期保证与审计可追溯性；Rust 生态代价高 |
| **不做**50 个 workspace 包 | 维护面爆炸；go-on 模块 + 3 crates 足够 |
| **不做**TS 式 invariant.rs 运行时断言文化 | 编译期类型 + 1646 测试已覆盖 |
| **不做**hermes 式进程内线程子代理 | GIL 无隔离；go-on 用 spawn + RAII 预算（已有 SpawnGuard） |
| **不做**codex 式平台绑定（重 OpenAI） | go-on 相对优势就是多供应商/多协议中立 |
| **风险**：M0.1 统一契约波及 GUI/CLI/ACP 三端 | 缓解：先加统一 consumer 层、逐端切换、每端独立测试 |
| **风险**：M3.1 自动技能产生噪音 | 缓解：默认关闭 + 草稿态（需人工/低风险确认才转正）+ 计分淘汰 |
| **风险**：M3.2 FTS5 CJK 在 Rust 侧实现成本 | 缓解：SQLite FTS5 内置 + cjk_unicode61 分词器（hermes 已验证可行）；先用 LIKE 降级保底 |

## 8. 终局画像（"神级 AGI"的验收形态）

完成 M0–M4 后，go-on 应当同时具备：

1. **可信**：每步工具/审批/自进化都有审计回滚点；沙箱 + patch 收口让"改了什么"永远可查；
2. **自主**：任务进来 → 技能库自动匹配/沉淀 → 记忆跨会话召回 → cron 无人值守 → 失败自动恢复；
3. **能干**：`go-on exec --json` 可被 hermes/codex/CI 无头调用；能力缝让执行环境（本地/沙箱/远端）一键切换；
4. **成长**：技能从经验自动创建并自我改进；跨会话记忆越用越懂你；安全自进化持续重构自身；
5. **互联**：ACP/MCP/SSE/OpenAI 兼容 + 多平台网关 + SDK 类型零漂移——任何入口进得来、任何平台出得去。

**这不是加功能，而是把 go-on 从"编排运行时"进化为"可信自治的 AGI 运行时"**：治理是它的免疫力，编排智能是它的自主力，执行器接口是它的行动力，插件生态是它的生长力，协议面是它的社交力。
