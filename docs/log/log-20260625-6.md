## 发现的问题与修复

### 🔴 变更1: `fault_tolerance/mod.rs` — 异步上下文中的阻塞 SQLite 操作 (HIGH)

**文件**: `src/fault_tolerance/mod.rs:228-378`

**问题**: `try_persist_state()` 在 `async fn` 中直接使用 `rusqlite::Connection::open()` 和所有 `conn.execute*()` 同步 SQLite 操作，**没有使用 `spawn_blocking`**。这直接违反了 Tokio 异步最佳实践，会阻塞整个运行时线程。

**同时**: 所有易错操作使用 `let _ =` 静默丢弃错误（共13处），状态持久化失败时无任何告警。

**修复**:
1. 新增 `FaultToleranceSnapshot` 结构体，在异步锁下克隆数据后立即释放锁
2. 将 SQLite 写入移到独立的同步函数 `persist_sqlite()`，通过 `spawn_blocking` 执行
3. 将 JSON 写入移到独立的同步函数 `persist_json()`，通过 `spawn_blocking` 执行
4. 所有 SQL/文件操作现在都有 `tracing::warn!`/`tracing::error!` 错误日志
5. 创建父目录失败时记录 warn 而非静默忽略

**效果**: 异步运行时不再被 SQLite 阻塞，持久化错误可观测可追踪。

### 🔴 变更2: CI发布流程 `release-full.yml` — 不存在的Feature名 (HIGH)

**文件**: `.github/workflows/release-full.yml:28,34,40`

**问题**: 使用 `profile-local`、`profile-multi-users-server`、`profile-simple-server` 等feature名，但Cargo.toml中对应名称为 `local`、`multi-users-server`、`simple-server`（无 `profile-` 前缀）。整个发布流程将因"none of the selected packages contains these features"而失败。

**修复**: 将 `profile-local` → `local`，`profile-multi-users-server` → `multi-users-server`，`profile-simple-server` → `simple-server`。

### 🔴 变更3: Dockerfiles 中 `COPY languages/` 路径错误 (HIGH)

**文件**: `deploy/simple-server/Dockerfile:18`, `deploy/multi-users-server/Dockerfile:18`

**问题**: `COPY languages/ languages/` — 但 `languages/` 实际在 `config/languages/`。Docker build 时该路径不存在，复制操作将静默失败（或无文件被复制），导致运行时语言文件缺失。

**修复**: 改为 `COPY config/languages/ languages/`。

### 🟡 变更6: `server.rs` `begin_shutdown()` 锁中毒恢复两次失败 (MEDIUM)

**文件**: `src/acp/server.rs:678-688`

**问题**: 首次尝试使用 `if let Ok(mut guard)`，失败后第二次尝试 `.write().unwrap_or_else(|p| p.into_inner())`。但首次失败后锁已中毒，第二次 `.write()` 也会失败——但第二次的 `unwrap_or_else` 会恢复。更严重的是：第一次的 `if let Ok` 意味着中毒时什么也不做。

**修复**: 简化为直接使用 `write().unwrap_or_else(|poisoned| { ...; poisoned.into_inner() }).begin_shutdown()`，用一次操作完成毒恢复+关停。

### 🟡 变更7: `runtime.rs` `artifact_ledger()` 毒恢复创建空ledger (MEDIUM)

**文件**: `src/acp/impl/runtime.rs:237-248`

**问题**: 锁中毒时使用 `unwrap_or_else(|_| ArtifactLedger::new(...))` 创建全新的空 ledger，丢失所有制品数据。

**修复**: 改为 `poisoned.into_inner().clone()` 恢复中毒时的内部状态。

### 🟡 变更8: `zh-TW.json` i18n 键拼写错误 (MEDIUM)

**文件**: `config/languages/zh-TW.json:396`

**问题**: 键名 `info.auth_session_rsssevoked` 拼写错误，应为 `info.auth_session_revoked`。会导致 i18n 查找失败。

**修复**: 更正为 `info.auth_session_revoked`。

### 🟢 变更9: `fault_tolerance/mod.rs` 新增 snapshot 结构体和持久化辅助函数

**文件**: `src/fault_tolerance/mod.rs`

**说明**: 新增 `FaultToleranceSnapshot` 结构体（在异步锁下克隆数据）、`persist_sqlite()` 函数（`#[cfg(feature = "backend-sqlite")]` 下编译）和 `persist_json()` 函数（非SQLite模式下编译）。所有持久化操作在 `spawn_blocking` 中执行并记录错误。
