## 2. 修复项详情

### P0-1: `agent_thread.rs` 测试代码编译错误

**文件**: `src/agents/communication/agent_thread.rs:497-499`

**问题**: `EchoAgent` 测试实现中 `available_models()` 返回 `Vec<String>`，但 
`Agent` trait 要求返回 `Vec<ModelInfo>`。此问题会导致编译失败。

**修复**: 将返回类型改为 `Vec<ModelInfo>`，正确填充结构体字段。

```rust
// Before
fn available_models(&self) -> Vec<String> {
    vec!["echo".to_string()]
}

// After
fn available_models(&self) -> Vec<ModelInfo> {
    vec![ModelInfo {
        id: "echo".to_string(),
        name: "Echo Agent".to_string(),
        description: "Test echo agent".to_string(),
        is_default: true,
        capabilities: vec!["chat".to_string()],
        context_window: None,
    }]
}
```

**验证**: 类型签名与 `Agent` trait 一致。

### P0-2: `agent_main_loop` 流式响应收集缺失

**文件**: `src/agents/communication/agent_thread.rs:338-347`

**问题**: `agent_main_loop` 创建了 `(token_tx, _token_rx)` 但丢弃了接收端，
导致 `chat()` 发送的所有流式 token 被丢弃。且 `Completed.result` 设为了
`content`（输入内容）而非 agent 的实际响应。

**修复**: 
1. 将 `_token_rx` 改为 `mut token_rx` 
2. `chat()` 返回 `Ok(())` 后收集所有流式 token
3. 将 agent 的实际响应作为 `Completed.result` 和 `reply_to` 发送

```rust
// Before
let (token_tx, _token_rx) = mpsc::unbounded_channel();
let sender = StreamingSender::new(token_tx);
let result = agent.chat(messages, None, None, sender).await;
match result {
    Ok(()) => {
        let result_msg = content.clone();
        status_tx.send_replace(AgentStatus::Completed { result: content });
        let _ = reply_to.send(result_msg);
    }
    // ...

// After
let (token_tx, mut token_rx) = mpsc::unbounded_channel::<String>();
let sender = StreamingSender::new(token_tx);
let result = agent.chat(messages, None, None, sender).await;
match result {
    Ok(()) => {
        let mut response = String::new();
        while let Some(token) = token_rx.recv().await {
            response.push_str(&token);
        }
        let response_for_status = response.clone();
        status_tx.send_replace(AgentStatus::Completed { result: response });
        let _ = reply_to.send(response_for_status);
    }
    // ...
```

**验证**: AgentThread 现可正确收集 agent 响应。
之前 `chat()` 的流式输出完全丢失。

### P0-3: `SpawnAgentTool::run()` block_on 消除

**文件**: `src/orchestration/tool/extended/spawn_agent.rs:100-157`

**问题**: `SpawnAgentTool::run()` 使用 `handle.block_on(execute_spawn(...))`。
虽然使用了 `Handle::try_current()`（符合原则 #24），但在异步运行时线程上
调用 `block_on` 仍违反原则 #23（禁止 production 热路径上的 `block_on`）。

**修复**: 改为使用专用阻塞运行时（`Runtime::new()`），完全避免在异步运行时
线程上执行 `block_on`。

```rust
// Before
match tokio::runtime::Handle::try_current() {
    Ok(handle) => handle.block_on(execute_spawn(/* ... */)),
    Err(_) => {
        let rt = tokio::runtime::Runtime::new()?;
        rt.block_on(execute_spawn(/* ... */))
    }
}

// After
let rt = tokio::runtime::Runtime::new()?;
rt.block_on(execute_spawn(/* ... */))
```

**验证**: 彻底消除异步运行时线程上的 `block_on`。同步调用者通过专用运行时
执行，异步调用者应使用 `run_async`。

### P0-4: 删除无意义 `#[expect(dead_code)]`

**文件**: `src/orchestration/tool/extended/spawn_agent.rs:651`

**问题**: EchoAgent 在测试模块中被标记为 `#[expect(dead_code)]`，但该类型
在测试中实际被使用（`impl Agent for EchoAgent`），属于误标记。

**修复**: 删除该属性。

**验证**: EchoAgent 是测试模块中的类型，被 impl 块和测试函数使用，非 dead code。

## 6. 本轮新增修复项详情

### P1-5: SpawnGuard 集成到 SpawnAgentTool（BLUE71 §5）

**文件**: `src/orchestration/tool/extended/spawn_agent.rs`

**问题**: SpawnAgentTool 使用独立的 `SPAWN_SEMAPHORE: Semaphore` 进行并发控制，
与 `agent_thread.rs` 中的 `SpawnGuard` RAII 模式不一致。缺少 `current_usage()` 
追踪能力。

**修复**:
1. 将 `SPAWN_SEMAPHORE` 替换为 `SPAWN_BUDGET: OnceLock<Arc<AtomicU64>>`
2. 新增 `init_spawn_agent_budget()` 函数，在 server 启动时初始化
3. `execute_spawn()` 中使用 `SpawnGuard::try_reserve` 替代 `Semaphore::acquire`
4. 更新测试：`spawn_agent_concurrency_permit_acquires_and_releases` →
   `spawn_agent_guard_reserves_and_releases`

```rust
// Before
let _permit = SPAWN_SEMAPHORE.acquire().await
    .map_err(|_| anyhow!("..."))?;

// After
let budget_arc = spawn_budget()?.clone();
let _guard = SpawnGuard::try_reserve(budget_arc, DEFAULT_MAX_CONCURRENCY)
    .map_err(|e| anyhow!("..."))?;
```

**接线链路**: `server_builder.rs:new_acp_server()` → `init_spawn_agent_budget()` →
`execute_spawn()` → `SpawnGuard::try_reserve()` → 自动 Drop 释放

### P2-1: GuardianReviewer 独立模型审查（BLUE71 §11）

**文件**: `src/governance/guardian.rs`（新建）

**实现**:
- `GuardianReviewer` — 使用独立模型审查工具操作安全性
- `GuardianCircuitBreaker` — 熔断器（连续3次拒绝 → 自动上报）

| circuit_breaker_reset | 单元 | 手动重置 |
| parse_decision_allow | 单元 | 解析ALLOW |
| parse_decision_deny | 单元 | 解析DENY |
| parse_decision_invalid_fails_closed | 单元 | 无效→拒绝 |
| guardian_review_allow | 集成 | 端到端允许 |
| guardian_review_deny | 集成 | 端到端拒绝 |
