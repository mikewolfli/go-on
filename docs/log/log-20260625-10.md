## 具体发现与变更

### 🔴 变更1: 修复server.rs panic!()

**文件**: `src/main/server.rs:251`

**问题**: `NegProtocolMode::from_str(dispatch_mode)` 失败时 `panic!()` — 进程直接崩溃。

**修复**: 改用 `tracing::error!` + `std::process::exit(1)`。

### 🔴 变更2: 修复8处锁中毒expect

**文件**:
- `src/resilience/hyper_resilience.rs` — 4处 expect (lock_mutex, read_lock, health_check_handle, consensus)
- `src/protocol/websocket.rs` — 4处 expect (rate_limit, last_heartbeat ×2, start_heartbeat)

**修复**: 全部改为 `unwrap_or_else(|poisoned| { tracing::warn!(...); poisoned.into_inner() })`，与 chaos.rs 中已有的正确处理模式一致。

### 🔴 变更3: 修复CI发布流程

**文件**: `.github/workflows/release-full.yml:122`

**问题**: `cp -r languages "$PKG/backend/"` — `languages/` 目录在项目根目录不存在（实际在 `config/languages/`），发布包会缺少语言文件。

**修复**: 改为 `cp -r config/languages "$PKG/backend/languages"`。

### 🟡 变更4: 修复CLI输出 22处 eprintln→println

**文件**: `src/main/cli.rs:241-338`

**问题**: `SkillCommand::List/Import/ListImported/Info/Refresh/Remove` 全部使用 `eprintln!` 输出用户可见信息（技能列表、成功消息等）。违反了 Unix stdout/stderr 分离惯例。

**修复**: 全部改为 `println!`。

### 🟡 变更5: 修复cli.rs expect

**文件**: `src/main/cli.rs:231`

**问题**: `SkillMarketRegistry::new()` 失败时 `.expect()` panic。

**修复**: 改为 `?` 传播错误。
