## 3. 本轮发现的问题

### 3.1 授权链双发（P0）

**路径追踪（真实代码，非推测）：**

1. `autonomy_loop.rs:457-469` — `emit_tool_approval_event()` 通过 `config.progress_tx` 发出 `tool_approval` 帧
2. `session.rs:264-366`（`session_prompt_payload` bridge）— 收到 `tool_approval` 帧后：
   - **发送** `session/update::PermissionRequest` 通知（L322-366）
   - **注册** `PendingPermissionRequest`（L313-320）
3. `autonomy_loop.rs:471-489` — `ensure_tool_permission()` 调用 `request_client_permission()`
4. `server.rs:1664` — `request_client_permission()` **再次发送** `session/request_permission` JSON-RPC request

**结果**：ACP 客户端收到两次审批请求 —— 一次是 `session/update` 通知，一次是 `session/request_permission` JSON-RPC request。

### 3.2 拒绝/超时无标准 ToolCallUpdate（P0）

当 `ensure_tool_permission()` 返回 `Ok(false)` 或 `Err(...)` 时，autonomy loop 只在文本响应中插入 `[Tool '...' denied by user approval gate.]` 提示，没有发出标准 ACP `ToolCallUpdate` 事件。Zed 无法在 UI 上正确显示工具调用被拒绝的状态。

## 4. 本轮修复内容

### 4.1 消除双发：统一授权入口到 `request_client_permission`

**修改文件**：
- `src/acp/server.rs`
- `src/acp/impl/request/protocol_pack/session.rs`

**修复内容**：

1. **`request_client_permission` 新增前置通知**（`src/acp/server.rs:1766-1813`）：
   - 在发出 `session/request_permission` JSON-RPC request 之前，先发出 `session/update::PermissionRequest` 通知
   - 这样 `session/prompt` 桥接不再需要发此通知

2. **`session_prompt_payload` bridge 移除重复通知**（`src/acp/impl/request/protocol_pack/session.rs:266-371`）：
   - 保留 `PendingPermissionRequest` 注册（供 `session_request_permission_payload` inbound handler 回接治理层）
   - **移除** `SessionUpdate::PermissionRequest` 通知的发送
   - 添加详细注释说明统一入口的设计

**效果**：
- 同一个工具审批请求，客户端只收到一次完整的 `session/request_permission` JSON-RPC request
- 先发 `session/update::PermissionRequest` 通知（UI 提示），再发 JSON-RPC request（权威审批流）
- 治理层回接路径不受影响（`session_request_permission_payload` 仍能通过 `PendingPermissionRequest` 消费审批决定）

### 4.2 拒绝/超时输出标准 ToolCallUpdate

**修改文件**：
- `src/acp/server.rs`

**修复内容**：

1. **新增 `emit_permission_request_notification`**（`src/acp/server.rs:1766-1813`）：
   - 集中发出 `session/update::PermissionRequest` 通知
   - 含标准 `PermissionOption`（approve/deny, AllowOnce/RejectOnce）

2. **新增 `emit_tool_call_update_rejected`**（`src/acp/server.rs:1815-1854`）：
   - 在权限被拒绝/通道关闭/超时时发出标准 `ToolCallUpdate`
   - 状态设为 `Cancelled`
   - 携带 `raw_input`（工具参数）和 `title`（描述原因）

3. **`request_client_permission` 错误/超时路径增加 ToolCallUpdate**：
   - `Err(err)` — `emit_tool_call_update_rejected` + 返回错误
   - `Err(_recv_closed)` — `emit_tool_call_update_rejected` + 返回错误
   - `Err(_timeout)` — 清理 pending + `emit_tool_call_update_rejected` + 返回错误

**效果**：
- Zed 客户端在工具被拒绝或超时时，能收到标准 ACP `ToolCallUpdate` 事件
- 状态为 `Cancelled`，包含工具名和原因
- 保持与 Zed 原生权限 UI 的协议兼容
