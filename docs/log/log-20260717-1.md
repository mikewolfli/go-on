# Log 2026-07-17-1: 工具扩展 — P0/P1/P2/P3 全链路实施

## 一、实现策略决策

### 决策框架

| 方式 | 适用场景 | 优点 | 缺点 |
|------|---------|------|------|
| **代码集成 (Tool trait)** | 需外部进程、高性能确定性操作 | 零依赖、精确控制 | 需编码 |
| **SKILL (SKILL.md)** | LLM驱动、需语义理解 | 零代码、灵活 | LLM调用延迟 |
| **Crates.io 依赖** | 已有成熟库 | 快速实现 | 编译时间↑、版本冲突 |

### 冗余检查

| 新工具 | 可能冲突的现有工具 | 关系 |
|--------|-------------------|------|
| run_build | cargo_check, cargo_test | 互补 — cargo tool是Rust专用，run_build是通用(npm/python/make) |
| json_query | jsonl_read/jsonl_write, grep | 互补 — json_query用jq语法查询，不重复 |
| hash_file | compress/decompress | 不同功能 — hash是完整性校验，不是压缩 |
| add_dependency | shell_exec | 替代 — add_dependency更安全(有参数校验)，shell_exec可做同样事但危险 |
| format_code | shell_exec | 替代 — format_code封装了formatter调用 |
| search_packages | web_search | 互补 — search_packages是结构化包搜索，web_search是通用网页搜索 |
| review_pr | git tool | 互补 — git tool操作git，review_pr获取PR diff并分析 |

**结论：无功能冗余，所有新工具与现有工具互补。**

### 2.2 实现细节

#### P0 — 核心代码智能
| 工具 | 实现方案 | 关键依赖 |
|------|---------|---------|
| **go_to_definition** | 正则匹配 `fn xxx`/`struct Xxx`/`impl Xxx` 等模式。支持Rust/Python/TS/Go/Java语言检测 | regex（已有） |
| **find_references** | 正则搜索所有文件中的符号引用，自动排除定义行 | regex（已有） |
| **apply_code_action** | 插入use/import语句、添加 #[allow(...)] 属性、或运行 cargo clippy --fix | 纯文件操作 |
| **format_code** | 自动检测 `.rs→rustfmt` / `.js→prettier` / `.py→black` / `.go→gofmt` | 子进程CLI |
| **search_packages** | 搜索 crates.io (api.crates.io) / npm (api.npmjs.org) / PyPI (pypi.org) | reqwest |
| **uuid_gen** | 生成 UUID v4 | uuid（已有） |
| **random_token** | hex/base64/alphanumeric 随机令牌 | rand（已有） |
| **encode_decode** | Base64/Hex/URL 编码解码 | base64（已有） |
| **hash_file** | SHA-256/SHA-512 文件哈希 | sha2（已有） |

#### P1 — 构建与工具链
| 工具 | 实现方案 | 关键依赖 |
|------|---------|---------|
| **run_build** | 自动检测 Cargo.toml→cargo build / package.json→npm run build / Makefile→make | 子进程CLI |
| **lint_code** | 自动检测 Cargo.toml→cargo clippy / package.json→npx eslint / .py→ruff | 子进程CLI |
| **add_dependency** | 自动检测 Cargo.toml→cargo add / package.json→npm install / requirements.txt→pip | 子进程CLI |
| **json_query** | 类jq路径语法读取JSON文件: `obj.key[0].nested` | serde_json（已有） |
| **yaml_query** | 同上支持YAML（feature-gated: data-export） | serde_yaml（可选） |
| **template_render** | {{变量}}替换 + {{#each}}循环 + {{#if}}条件，纯字符串实现 | 无 |

#### P2 — 深度分析
| 工具 | 实现方案 | 关键依赖 |
|------|---------|---------|
| **code_metrics** | 统计代码行数/圈复杂度/函数数/最大函数大小 | 纯解析 |

## 四、实现策略总结

| 维度 | 决策 | 依据 |
|------|------|------|
| **代码工具 vs SKILL** | 20代码 + 7SKILL | 确定性操作用代码，LLM驱动用SKILL |
| **Crates依赖** | 0新增 | 全部复用已有依赖（reqwest, sha2, uuid, base64, rand, regex） |
| **Feature gate** | yaml_query= data-export | 保持编译速度，不引入无条件新依赖 |
| **功能冗余** | 0冗余 | 全部新工具与现有工具互补 |
| **测试覆盖** | 78新测试 | 每个新工具至少2-3个单元测试 |

## 五、后续建议

1. **LSP协议深度集成**: 当前go_to_definition/find_references使用正则，可增加可选的LSP TCP模式（需要配置LSP服务器地址）
2. **模板引擎升级**: 当前template_render为纯字符串实现，如需jinja2全功能可考虑 minijinja crate
3. **OSV缓存**: security_scan每次查询OSV API，可增加本地缓存减少重复查询
4. **docker工具扩展**: 可增加 docker_build, docker_push, docker_compose_* 等
