## Round 2 — CLI Chat Optimization

### 3. 🔴 CRITICAL: Zombie agent tasks on Ctrl+C
- **File**: `src/cli/chat.rs:656-661,714-720`
- **Problem**: Ctrl+C broke the streaming loop but the spawned agent task continued running to completion in background, accumulating zombie tasks over multiple interruptions.
- **Fix**: Replaced with `JoinHandle::abort()` pattern — Ctrl+C now calls `chat_task.abort()` which cancels the spawned future immediately, dropping the `StreamingSender` and preventing resource leaks.
- **Impact**: Zero zombie tasks on Ctrl+C ✅

### 4. 🟡 MEDIUM: Blocking `std::process::Command` on async executor
- **File**: `src/cli/chat.rs:374,413,436,456,512,524` (6 locations)
- **Problem**: All git commands (`diff`, `status`, `add`, `commit`) used `std::process::Command` which blocks the async executor thread.
- **Fix**: Replaced all 6 with `tokio::process::Command` + `.output().await`
- **Impact**: Git commands no longer block concurrent async tasks ✅

### 5. 🟡 MEDIUM: Session auto-save cloned all messages + blocking I/O
- **File**: `src/cli/chat.rs:598-607`
- **Problem**: Every turn triggered a full `Vec<Message>` deep clone followed by `std::fs::write` on the executor thread.
- **Fix**: Added `SAVE_IN_FLIGHT: AtomicBool` debounce flag + `tokio::spawn` with `tokio::fs::write`. Serializes `&messages` directly (no intermediate `ChatSession` allocation).
- **Impact**: Save is now non-blocking and debounced ✅

### 6. 🟢 LOW: `terminal_width()` spawned subprocess on every call
- **File**: `src/cli/markdown_renderer.rs:427-443`
- **Problem**: Each code block and horizontal rule triggered a `stty` subprocess.
- **Fix**: Cached result with `OnceLock<usize>` — one-time initialization.
- **Impact**: Zero subprocess spawns after first call ✅

### 7. 🟢 LOW: Empty assistant message duplication
- **File**: `src/cli/chat.rs:855-866`
- **Note**: Identified as potential issue — the response duplication path is mitigated by the follow-up path check. Left as identified for future review.
