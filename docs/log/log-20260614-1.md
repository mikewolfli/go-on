# Performance Fix Log — 2026-06-14

## Issue: HTTP 端口监听延迟（180s+ 初始化瓶颈）

**问题**: `new_acp_server()` 在启动时创建了 3 个独立的 `MemoryPersistence` 实例，每个实例都会：
- 执行 `fs::create_dir_all()` 创建冷存储目录
- 打开 SQLite WAL 数据库连接
- 执行 `CREATE TABLE IF NOT EXISTS` 和 `CREATE INDEX IF NOT EXISTS` DDL

所有这些同步 I/O 操作在 tokio 工作线程上顺序执行，阻塞了 `run_acp_http_server()` 的端口绑定。

## 根因分析

### 冗余的 MemoryPersistence 创建（3→1）

| # | 创建位置 | 用途 | 实例 |
|---|---|---|---|
| 1 | `server_builder.rs:270` | 主服务器 governance_deps.memory_persistence | SQLite warm.db |
| 2 | `server_builder.rs:273` | retrieval engine (wire_memory_retrieval) | SQLite warm.db（第二次） |
| 3 | `server_builder.rs:467` | `init_memory_persistence_with_auto_migrate(None)` | SQLite warm.db（第三次） |

第 3 个实例完全冗余——它与前两个使用相同的 `warm.db`，仅在代码中启动了一个独立的 auto-migrate 后台任务。

### 累积同步阻塞

`new_acp_server()` 虽然是 `async`，但几乎所有工作都是同步执行的：
1. 3× `MemoryPersistence::new()` — 共 3× SQLite 连接 + 文件系统操作
2. `HashChainAuditor::new()` — 打开审计链文件
3. `PolicyReloader` — 加载 `.goon/policies/*.toml`
4. `builder.build()` — 创建 SkillRegistry，从磁盘加载技能
5. `wire_server()` — 创建持久化调度器 SQLite 数据库

这些同步 I/O 操作在 tokio 运行时线程上累积，导致端口绑定前需要数分钟。

## 修复方案

### 改动 1：移除冗余的第三个 MemoryPersistence 实例

**文件**: `src/acp/impl/runtime/server_builder.rs`

删除了 `new_acp_server()` 中的 `init_memory_persistence_with_auto_migrate(None)` 调用。该调用创建了第三个独立的 `MemoryPersistence` 实例（第三个 SQLite 连接 + 文件系统操作），在关键启动路径上同步执行。

### 改动 2：将 auto-migrate 任务移至 start_background_tasks()

**文件**: `src/acp/background.rs`

在 `start_background_tasks()` 中新增了两个功能：
1. **Auto-migrate 后台任务**: 使用 server 已有的 `MemoryPersistence`（通过 `governance_deps.memory_persistence`），每 5 分钟运行一次 `auto_migrate()`
2. **Initial bridge_promote**: 启动时执行一次内存桥初始提升。此前仅在 `run_acp_server()`（stdio 模式）中调用，现在对所有协议模式（HTTP、WebSocket 等）生效

### 改动 3：清理死代码

**文件**: `src/memory/memory_bridge.rs`

- 删除了 `init_memory_persistence_with_auto_migrate()` 函数（死代码，且代表我们修复的反模式）
- 删除了 `start_auto_migrate_task()` 函数（死代码，测试已内联）
- 更新了测试 `test_background_task_cancellation`：内联创建后台任务，使用 `tokio::select!` + `cancelled()` 实现可取消的定时器模式

## 性能改善预估

- 启动路径上减少 ~33% 的 SQLite 初始化开销（3→1 个 `MemoryPersistence` 实例）
- 消除同步 `fs::create_dir_all` + `execute_batch` 在关键路径上的重复执行
- 端口绑定不再需要等待第三个 SQLite 连接创建完成
- HTTP 服务器应在数秒内完成端口绑定（此前 ~180s+）

## 影响范围

- 所有 4 种协议模式（acp_stdio、acp_http、mcp_stdio、mcp_http）均受益
- 不影响 governance.status、health 端点、main 链路指标
- 不影响 compile-time 零警告要求
