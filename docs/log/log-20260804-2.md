### 2. chat 热路径双查双写(核实确认,记录不改)

## 四、chat 热路径 token cache 双查双写(残留 #1,最难项)

**根因确认**(逐调用链验证):
1. `act_phase` 先行 canonical `token_cache.lookup`(chat_phases.rs);
2. miss 后 fallback 执行 `resolved.agents`(来自 `flow.resolve` → `registry.get()` → **CachedAgentWrapper**)→ wrapper 内**第二次 lookup**;
3. wrapper 命中 store + fallback `store_async` → **同键双写**(L1 put + L2 embedding + L3 persist 各两遍);
4. **duplicate-user 检测漏洞**:act_phase 直查命中时返回旧答案,wrapper 的 `is_duplicate_user` 分支永远不执行(GUI 重复提问命中旧答案的 bug 源头)。

**实施**(三个动作合治):

| # | 改动 | 位置 |
|---|------|------|
| 1 | 提取共享 `last_user_message_is_duplicate()`(wrapper 原逻辑逐字迁移),`CachedAgentWrapper::chat` 改用之 | `token_cache/mod.rs` |
| 2 | `AgentRegistry` 新增 `get_unwrapped`/`all_unwrapped`(raw 取 agent,不带 wrapper);`get`/`all` 重构为取 raw 后包装 | `agents/agent.rs` |
| 3 | `flow.resolve` 改用 `get_unwrapped`/`all_unwrapped` → chat phases 全链路(fallback + autonomy)执行 raw agent | `orchestration/flow.rs` |
| 4 | `act_phase` 在 canonical lookup **之前**做 duplicate-user 检测,命中则同时绕过 token 与 semantic 缓存(agent_entry 标记 `duplicate_user: true`) | `chat_phases.rs` |
| 5 | store 单点化:phases 路径唯一 store = fallback `store_async`(wrapper store 不再出现在该路径) | 隐含于 2-3 |

**架构结果**:缓存门控归位两处——ACP chat phases 由 `act_phase` 单门控,其余 `registry.get()` 消费者(CLI 直调、review、summarizer、Guardian)仍由 `CachedAgentWrapper` 门控,互不重叠。
