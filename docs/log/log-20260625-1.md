These are **deliberate performance optimizations**, not oversight. Each `std::sync::Mutex` is confined to synchronous critical sections that never cross `.await` boundaries, making `tokio::sync::Mutex` strictly worse (higher overhead, no benefit).

| Location | Why `std::sync::Mutex` is correct |

| `circuit_breaker.rs` — breaker state (`failure_count`, `stage`) | Sync-only methods (`record_success`, `record_failure`, `is_open`, `snapshot`). Lock-unlock within one function call, no `.await`. |
| `inflight.rs` — global + per-phase counters | Sync-only methods (`try_enter`, `leave`, `snapshot`). Pure counter ops, no `.await`. |
| `task.rs` (adaptive_selector, failure_prevention) | Every `std::sync::Mutex::lock()` is followed by `drop()` before any `.await` — the lock is never held across an async boundary. |
| `server_builder.rs` | Startup-time only — not in any hot path. Converting would add zero value. |
