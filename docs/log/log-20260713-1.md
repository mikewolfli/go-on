# 日志：全链路审查与优化 - 2026-07-13

## 总览

本轮全链路审查覆盖 3 大核心改进：
1. **`/rpc` 管道机制消除** — 用 `tokio::task_local!` per-request 缓冲区替代全局管道切换 + 串行锁
2. **Handler 纯函数化** — ~85 个 handler 改为返回 `Result<Value>`，由中央 `respond()` 统一发送
3. **GUI Chat 渲染优化** — 消息改为 Zed 样式（content 在上、thinking 在下，自动换行，无截断）

## 1. `/rpc` 管道机制消除

### 问题
`/rpc` 端点使用管道机制：将 `server.output` 从 stdout 临时切换为管道写端，处理函数写入管道，主线程读取管道后写入 HTTP socket。需要 `rpc_serial` 串行锁防止竞态，导致所有 RPC 调用串行执行，健康检查超时后被 GUI 误判为断线。

### 方案
使用 `tokio::task_local!` 存储 per-request 输出缓冲区，替代全局 `server.output` 管道切换。

### 修改文件

| 文件 | 修改内容 |
|---|---|
| `src/acp/impl/io.rs` | 新增 `RPC_BUFFER` 任务本地静态变量；`write_json_line` 优先写入任务本地缓冲区，回退到 `server.output` |
| `src/acp/impl/runtime/http.rs` | `/rpc` 处理器移除 `rpc_serial.lock()`、管道创建/切换/读取；改为 `RPC_BUFFER.scope()` |
| `src/acp/impl/runtime/tls.rs` | `route_rpc_over_tls` 同样移除 `rpc_serial.lock()`，改用 `RPC_BUFFER.scope()` |
| `src/acp/server.rs` | 移除 `rpc_serial` 字段 |

### 效果
- ✅ 消除串行锁，多个 `/rpc` 请求可并发处理
- ✅ 消除管道机制，无内存管道创建/切换/读取开销
- ✅ 零 handler 签名变更
- ✅ stdio 模式向后兼容

## 2. Handler 纯函数化

### 问题
所有 handler 通过 `send_result`/`send_error` 直接写入输出通道，耦合了处理逻辑和传输逻辑。

### 方案
创建中央 `respond()` 函数，handler 改为返回 `Result<Value>` 的纯函数。

```
改造前：handler → send_result → write_response → write_json_line → 缓冲区
改造后：handler → Result<Value> → respond() → send_result/send_error → 缓冲区
```
