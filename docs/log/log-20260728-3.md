## 1. 死代码分析结果

### 1.1 🔴 `src/agents/session.rs` (~740行) — **已删除**

**分析**:
- 该文件在 `agents/mod.rs` 中**从未声明**为模块（无 `pub mod session`），因此整个文件压根不被编译
- `spawn_session`、`SessionHandle`、`SessionState` 全部仅在本文件内部和测试中使用
- `#[allow(dead_code)]` 注解本身是误导性的——模块本身都不参与编译

**接线评估**: 此模块是 BLUE71 设计的备选会话架构（SessionActor），但当前生产代码已通过 `acp/impl/session.rs` + `acp/impl/chat/session.rs` 处理会话。该备选架构从未接入，且已有功能的替代实现。

**决定**: ❌ 不接线。**已删除**。

### 1.2 🔴 `acp/prelude/circuit_breaker.rs` — **已简化**

**分析**:
- `CircuitBreakerStage::Open` / `HalfOpen` 变体从未被构造
- `transition_to()` 方法从未被调用
- 注释说"保留给 HyperResilienceEngine 同步"，但 HRE 从未调用此方法
- 但 `reset()`、`open_count()`、`snapshots()`、`is_healthy()` 确实被生产代码使用（`health_pack.rs`、`governance_handlers/actions.rs` 等）

**接线评估**: HyperResilienceEngine 有自己的内部断路器状态机，但它从未向 ACP 的 `CircuitBreakerRegistry` 同步状态。所有条目永远停留在 Closed 状态。完整的接线需要修改 HyperResilienceEngine 的状态机来发布事件到 ACP 注册表，这是一个较大的架构变更。

**决定**: ❌ 暂不接线。**已简化**：
- 移除 `Open` / `HalfOpen` 变体
- 移除 `transition_to()` 方法
- 移除 `CircuitBreakerStage` 枚举（不再需要）
- 保持 `reset()`、`open_count()`、`snapshots()`、`is_healthy()`（被生产代码使用）
- 更新测试以验证新的简化 API

### 1.3 🟡 `governance/guardian.rs::GuardianCircuitBreaker::reset()` — **已删除**

**分析**:
- `reset()` 方法仅在一个测试中被调用（`test_circuit_breaker_reset`）
- 无生产代码调用它
- 功能与 `record_decision(false)` 相同（后者也会重置连续拒绝计数）

**接线评估**: 不必要——自愈行为通过 `record_decision(false)` 已经实现。保留一个仅测试使用的复位入口没有意义。

**决定**: ❌ 不接线。**已删除**。同时删除对应的测试。

### 1.4 🟡 `multimodal/excel_writer.rs::FeatureDisabled` 变体 — **已修复**

**分析**:
- 当 `document-excel-write` 功能启用时，`FeatureDisabled` 变体被编译但从不构造，导致 full profile 编译警告

**决定**: ✅ 添加 `#[cfg(not(feature = "document-excel-write"))]` 条件编译，使该变体仅在功能未启用时编译。

### 1.5 🟢 空 `.goon` 目录 — **已删除**

`go-on/.goon` 和 `go-on/config/.goon` 均为空目录，已删除。
