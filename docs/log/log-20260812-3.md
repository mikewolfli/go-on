### 第 1 轮（5 域并行扫描，R27–R29 修复）

#### R27 — 协议/传输链路（A 域）

1. **P1 `CURRENT_TRANSPORT` 进程级全局 → task-local 重构**：并发 HTTP 连接互相覆盖全局传输（A 的 session/update、审批写入 B 的 buffer/响应串台；`clear` 会清掉并发请求的传输）。重构为 `tokio::task_local!` + `with_transport` 作用域（stdio 整个循环 / /rpc 请求 / /chat/stream 流 / OpenAI SSE 与 Responses API 流），任务派生继承。测试（dispatch/auto_mode 6 处）同步改造。TLS 臂保持文档化的无带外传输行为。
2. **P1 HTTP 审批回环断裂**：`resolve_pending_client_response` 仅 stdio 循环调用；HTTP 下客户端回传 response 形状（id+result 无 method）被当请求解析失败（400），pending oneshot 必超时（15s）→ `ensure_tool_permission` 超时后 fail-open 放行。修复：`/rpc` 入口先识别 JSON-RPC response 形状并 resolve（与 stdio `is_jsonrpc_response` 同判据），补 ack 响应。
3. **P2 `mcp.client.connect` SSRF/任意程序拉起**：base_url 无校验（内网/元数据探测）+ stdio program 任意可执行文件。修复：http 走 `validate_url_async`（同 http_request 策略）；stdio 强制绝对路径 + 拒绝路径穿越/Shell 元字符 + args 数量/长度上限。
4. **P2 ACP session/terminal 状态无容量上限**：`session/set_mode`、`resume`、`new` 对任意 id `or_default()` 建条目；`terminal/create` 持子进程句柄无上限。新增 `MAX_ACP_SESSIONS=4096` / `MAX_ACP_TERMINALS=256` + 超限驱逐，4 个插入点接线。
5. **P2 terminal 输出缓冲无限增长 + O(n²)**：`drain` 永不清空、每次 `terminal/output` 全量序列化。改为增量读取（`read_offset` 只返回新字节）+ `MAX_TERMINAL_OUTPUT_BYTES=4MiB` 硬上限（超限丢最旧并置 truncated）。
6. **P2 `mcp.completion.complete` 桥臂直接拒绝**（原生臂完整实现）：桥臂移植原生逻辑（ref/prompt 的 agent://、template:// 补全 + ref/resource）对齐能力。
