## 五、遗留问题(记录不实施 / 推荐后续)

1. **三重断路器体系**(`failure_prevention` / `hyper_resilience` / `guardian`)——`HyperResilienceEngine` 已被 `metrics_exporter` 指定为权威,建议后续将 `failure_prevention` 的并行状态机与 `UnifiedCircuitBreaker` 垫片退役。*风险较高,单轮不宜,记录。*
2. **Copilot OAuth 设备码流程三份拷贝**(GUI `providers/render.rs` + `setup.rs` + 后端 RPC 已存在)——建议 GUI 改调 `provider.copilot_device_code(_poll)` RPC 并删除两份 GitHub 直连实现(~300 行)。*GUI 重构,记录。*
3. **审计管道多源**(`governance/audit.rs` 规范 sink + `security/audit_integrity.rs` 哈希链 + 4 种 AuditEntry)——建议哈希链作为同一 sink 的完整性层。*跨模块重构,记录。*
4. **SSE 解析三端差异**(vscode `parseSseChunk` 按 `\n\n` 切分+丢弃 `[DONE]`,GUI 回退 `\n`+包装)——建议按 `contracts/sse-protocol.md` 对齐并加对等测试。*记录。*
5. **`tests/e2e/` 名不副实**(不启动子系统,为结构型测试)——建议更名 `tests/structural/`。*记录。*
6. **GUI 侧重复**(chat body 构造×2、SSE 事件解释×2、HTTP 客户端×3、退避算法×5、模型名列表 vs 后端权威)——建议后续按后端 RPC 收敛。*记录。*
7. **`nodejs chatStream` 非真流式**(缓冲整体后单次 yield)——建议重构为逐 chunk yield。*记录。*
8. `sdk/typescript/dist/` 已重建;`sdk/nodejs` 无 node_modules 未跑 tsc(改动与 typescript 镜像,已由 README 同步佐证)。*环境限制,记录。*
9. **链路重复:三重 `cancel_subtree` 委托**(`CommunicationBus::cancel_subtree`→`AgentMessenger::cancel_subtree`,旁路其持有的 `ExecutionGovernor::cancel_subtree`)——建议收敛为 单链路 bus→governor→messenger。*涉及 agent 通信内部,单轮不宜,记录。*
10. **流式载荷构建器重复**(`chat/streaming.rs` SSE chunk/done 载荷 vs `helpers/metrics.rs` stream_chunk/done_notification,存在显式漂移风险 NOTE)——建议共享同一 builder。*记录。*
