## 一、四项定论的复核结论(附证据)

### 1. 断路器:确认不可合并(数据模型本质不同)
- `hyper_resilience::HyperResilienceEngine` 全部公开 API 核对(`register_circuit_breaker`/`record_failure[_with_mode]`/`record_success`/`is_available`/`probe`/`system_health`/`profile`/`health_check_cycle`/`trigger_failover`/`execute_healing`):**无**每服务健康监控(成功率/错误率/延迟)、**无**降级策略/`should_degrade`、**无** `recover` 恢复操作、**无** `(name,state,failure,total,success)` 快照。
- `failure_prevention` 消费者实测:`health_pack.rs`(`get_health_report`/`get_circuit_state`/`get_degradation_strategy`/`recover`)、`acp/prelude/circuit_breaker.rs`(`breaker_snapshots` 经 `attach_source`)、`optimization_bus.rs`(`record_outcome`/`is_circuit_broken`/`circuit_breaker_trips`)、`exec_pack/task.rs`(`should_degrade`/`record_outcome`)——全部依赖其健康监控数据模型。
- **结论**:全量合并=重写 5 个消费点 + 改变线上故障语义(阈值/半开/恢复超时 vs 连续失败计数),且无端到端韧性测试覆盖(原则 §14 无法闭环验证)。维持第26轮定论:两引擎职责不同,死代码垫片已清。

### 2. 审计类型:确认低收益(字段域不同)
- 4 类型逐字段对比:`AuditLogEntry`(通用决策:task/phase/agent/tool/inputs/outputs)、`harness_bus::AuditEntry`(策略评估:dispatch/execution/governance_policy+violations)、`security_governor::AuditEntry`(安全策略:policy_id/resource/actor+`PolicyVerdict` 枚举)、`audit_integrity::AuditEntry`(哈希链格式:prev_hash/payload_hash——**格式即完整性机制**,不可统一)。
- 规范 sink 已统一(`hardening.rs` 文档:旧第二写入器已移除),哈希链位置已统一至 `~/.goon/`。
- **结论**:类型合并=纯改名无行为收益,维持定论。
