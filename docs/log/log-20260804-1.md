## 一、工具层重复实现合并（3 处）

### 1. STL 读取双实现合并 → 单一原生解析

**问题**：`stl.rs`（cad-stl 原生解析，支持 ASCII+binary、bounding box、volume、unique vertices）与 `stl_tool.rs`（model-3d 的 stl crate 版，仅 binary，功能更弱）实现同一 `stl_read` 能力。

**连带发现 feature 组合缺口（编译级 bug）**：
- `extended/mod.rs` 中 `#[cfg(all(feature = "model-3d", not(feature = "cad-stl")))] pub use stl_tool::StlReadTool;` —— 但 `stl_tool.rs` 只定义 `StlCrateReadTool`，该组合下**编译失败**（实测 `model-3d` 单独启用 7 个编译错误）。
- `tool/mod.rs` 注册条件 `all(cad-stl, not(model-3d))` 与 `all(model-3d, not(cad-stl))` 互斥 —— **full profile（cad-stl+model-3d 同时启用）下 `stl_read` 工具完全不注册**（实测静态分析确认）。

**实施**：
| # | 改动 | 位置 |
|---|------|------|
| 1 | `stl.rs` 全部 20 处 `cfg(feature = "cad-stl")` → `cfg(any(feature = "cad-stl", feature = "model-3d"))` | `extended/stl.rs` |
| 2 | 删除 `stl_tool.rs`（114 行）；`extended/mod.rs` 三分支 STL 导出合并为 `#[cfg(any(cad-stl, model-3d))]` 单分支 | `extended/mod.rs` |
| 3 | `tool/mod.rs` STL 注册条件改为 `#[cfg(any(cad-stl, model-3d))]`，删除 `StlCrateReadTool` 注册块 | `tool/mod.rs` |
| 4 | `Cargo.toml`：`model-3d = ["dep:stl"]` → `model-3d = []`，删除 `stl` crate 依赖 | `Cargo.toml` |

**效果**：full profile 下 `stl_read` 恢复注册（此前缺失）；`model-3d` 单独启用不再编译失败；消除重复 STL 解析实现。

## 一、ResponseCache 接入 token_cache 作为 L3 持久化层（用户选 A，最优接入）

**设计**：`TokenMultiLevelCache` 增加可选持久化后端（L3 层）：
- 新 trait `PersistentCacheBackend`（`get_cached`/`put_cached`），`ResponseCache`（SQLite + PG 双后端）实现该 trait —— 统一抽象，token_cache 不感知具体后端。
- `CacheLevel` 增加 `L3` 变体；`TokenCacheStats` 增加 `l3_hits` 并在 `hit_rate`/`to_json` 报告。
- `lookup`：L1 → L2 未命中后，若配置了持久后端，按精确 key（`hash_input`）查 L3；命中则**提升回 L1/L2**（后续请求走内存），并计入 L3 命中统计。
- `store`：写 L1/L2 后，**异步 `tokio::spawn` 写 L3**（不阻塞请求热路径）。

**开关（`persist_enabled`，默认 true）**：
- `CacheConfig` 新增 `persist_enabled: bool`，`#[serde(default = "default_cache_persist_enabled")]` 返回 **true**。理由：默认配置 `[cache] enabled = true` 已打开 SQLite，接入零额外启动成本；开启后跨重启/跨实例命中省 LLM 调用（秒级），远大于每 miss 一次 SQLite 查询（ms 级）。
- 关闭场景：low-memory / 性能敏感部署可显式 `persist_enabled = false`（SQLite 仍作 healthcheck）。
- 三端同步：`config/config.toml` 显式 `persist_enabled = true`（含注释）；vscode `configManager.ts` 的 `CacheConfig` 接口 + 默认值同步。

**接线链路**：`main/server.rs`（从 `adjusted_cache_cfg` 读 `persist_enabled`）→ `dispatch_server` → `new_acp_server`（新增 `persist_cache` 参数）→ `ServerBuilder.with_persist_cache` → `build()` 中若 `persist_cache && response_cache.is_some()` 则 upcast 为 `Arc<dyn PersistentCacheBackend>` 并 attach。

**新增 3 个行为测试**（`token_cache/mod.rs`）：`store_writes_through_to_persistent_backend`（写穿透）、`lookup_falls_through_to_persistent_backend_on_l1_l2_miss`（L3 命中 + 提升 L1）、`without_backend_lookup_returns_none`（无后端无 L3）。

## 二、HTTP accept 循环合并（残留项收口）

**设计**：新建 `shared/tcp_accept_loop.rs`，抽取两个服务器逐字重复的 accept 骨架：
- `shutdown_signal()`：SIGINT/SIGTERM 信号等待（原两处独立实现，逐字重复）
- `run_http_accept_loop(listener, shutdown_notify, max_connections, should_stop, on_connection)`：accept + select 分发 + 并发信号量（Semaphore）+ per-connection `tokio::spawn`
- `bind_tcp_listener()`：SO_REUSEADDR 绑定（原 ACP 内联实现）

**协议特定部分保留在闭包内**（`on_connection: Arc<F>`）：
