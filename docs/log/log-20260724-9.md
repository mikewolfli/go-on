## 🔴 发现 & 修复

### 1. 虚假 `#[allow(dead_code)]` 标记清理（3个文件）

#### `optimization/compaction.rs`
- `ConversationTurn` 结构体和 `impl` 块标记为 `#[allow(dead_code)]`
- 但实际上被 `agents/session.rs` 导入并使用（`ConversationTurn::new("user", &content)`）
- 移除 3 个虚假 `#[allow(dead_code)]` 标记

#### `agents/communication/agent_thread.rs`
- 15 个 `#[allow(dead_code)]` 标记在 `pub` 可见性的类型上（`AgentStatus`、`AgentInput`、`SpawnConfig`、`AgentThread`、`SpawnGuard` 等）
- 这些类型均被 `agents/session.rs` 导入并使用，`pub` 可见性不可能触发 `dead_code` 警告
- 移除所有 15 个虚假标记

#### `agents/communication/lifecycle.rs`
- `AgentLifecycleBuilder::idle()` 标记为 `#[allow(dead_code)]`
- 实际上被 `agents/session.rs` 调用（`AgentLifecycleBuilder::idle()`）
- 移除该标记

### 2. 死枚举变体删除

**`agent_thread.rs` - `SpawnError` 枚举**：
- `AgentNotFound(String)` 和 `Other(String)` 两个变体从未被构造使用
- 根据原则 #9 "不允许占位、空函数、逻辑错误"，直接删除

**`agent_thread.rs` - `SpawnGuard` 结构体**：
- `max: u64` 字段在构造后从未被读取
- 删除该字段

### 3. 内联锁模式统一（`reinforcement/mod.rs`）

**`FederatedRLAdapter`** 的 3 个方法使用内联的 `lock().unwrap_or_else(|e| { ... e.into_inner() })`：
- `profile()` — 改为 `crate::lock_or_recover!`
- `register_client()` — 改为 `crate::lock_or_recover!`
- `submit_and_aggregate()` — 改为 `crate::lock_or_recover!`

### 4. 预存在测试失败修复

**`agent_thread::tests::test_chat_request_variant`** — 测试一直因超时而失败（预存问题）：

**根因**：`agent_main_loop` 是持久循环（persistent loop），处理完 `ChatRequest` 后继续等待下一个输入，不会自动终止。但测试的 EchoAgent 的 `chat()` 方法返回 `Ok(())` 但既不发送任何 token 到流中（导致 `while let Some(token) = token_rx.recv().await` 永远挂起），也不发送 Cancel 来终止循环。

**修复**：
1. EchoAgent 的 `chat()` 现在发送 "echo" token 到 `StreamingSender`，确保 token 收集循环能正确终止
2. 测试顺序改为：先等 reply → 发送 Cancel → 再等完成状态
